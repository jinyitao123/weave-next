# 能力服务 Loom 运行时接入

日期：2026-09-13

## 已接通的路径

经过认证的 HTTP 请求保存草稿、发布固定修订、创建 invocation；服务启动时启动持久 worker。worker 领取任务后读取修订并校验摘要，使用现有 Loom compiler、ToolLoop、运行租约和终态记录执行步骤。每个模型步骤的 Loom run ID 在推理前绑定到 invocation，完成结果可以通过查询接口读取。

支持本机 Loom、显式模型、多角色 worker、串行依赖、并行分支和全成功汇合。transform 和 deliver 步骤只做输入绑定投影，不解释指令。空绑定接收原始运行输入；指定绑定只读取运行输入或祖先步骤输出。输入、单步输出和最终按步骤 ID 汇总的对象执行 JSON Schema 校验。

当前拒绝条件、循环、人工等待、工具/数据/密钥资源声明、运行时池和额外 runtime requirements。此前仅把图按顺序排列并丢弃关系的行为已修正，不能把未执行的配置当作支持。Codex、Claude、OpenCode 仍使用已有平台执行路径，但尚未接入本能力服务。

## 运行约束

- 每个能力最多 32 步，每个 Loom 步骤输出上限 4096 tokens。
- 一次能力执行最多 120 秒；数据库领取期限为 150 秒。
- 执行器每 100 毫秒观察取消和领取有效性。
- 排队取消立即完成；运行中取消先记录 cancel_requested，执行返回后确认 cancelled 并丢弃输出。重复取消幂等。
- 领取令牌和事务状态检查拒绝错误 owner、迟到和重复完成。
- worker 中断后，过期任务标记失败；不自动重放有可能已经执行的步骤。
- 发布修订由数据库 trigger 禁止更新或删除，发布函数深复制草稿。
- API key 使用 capabilities:manage、capabilities:invoke、capabilities:read、capabilities:cancel 显式范围；空范围无授权。人员入口支持 admin、owner、developer。
- application_id 仍绑定现有 API key ID 或人员 ID。独立应用身份、凭据轮换后保持同一应用和版本 grant 尚未接入，不能宣称完整开发者权限模型完成。

## 验证证据

TestCapabilityHTTPToLoomRuntimeRealPG 经过真实认证中间件、HTTP handler、PostgreSQL、生产 worker 循环、Loom compiler/ToolLoop 和终态存储。两个模型步骤并行执行，再由 transform 汇合；测试检查结果、重放不增加模型调用、两个 Loom run 绑定和两个 Loom attempt lease。

模型端为受控的 OpenAI-compatible HTTP 测试服务，因此该测试证明运行时接通，不证明真实模型的业务输出正确。

PostgreSQL 故障验证覆盖八个并发领取者只产生一个领取、取消后的迟到完成、过期任务不重试且拒绝旧完成、nil 错误结果持久化、伪造领取令牌、独立连接重放、跨应用读取拒绝及数据库修订不可修改。测试启用 TEST_DATABASE_URL 并运行 -race。

make test、make depguard、make productguard 和 make workbench-check 均通过。额外运行的 verify-client-ui-i18n 被原有 AgentExecutionPanel.tsx 中 Claude CLI、Codex CLI、OpenCode 三个硬编码选项阻断；本次新增组件使用中英文词典。

当前终端没有模型提供商密钥，项目 .env 仅有平台账号及 Workbench 配置，127.0.0.1:11434 未提供 Ollama 服务。本轮未执行真实模型验收，也没有发布或部署。

## 尚待完成

Workbench 的能力创建沿用团队组建方式：主对话先列出已有能力，没有合适项时由 AI 生成并保存可审查草稿，用户确认后再发布不可变修订。Workbench 不提供手工 JSON 编辑器。MCP 契约测试验证列表结果隐藏内部定义、生成只保存草稿、发布需要独立调用，以及重复请求使用稳定幂等键。

真实浏览器验收只覆盖独立的“应用接入”管理：页面创建应用、授权既有发布版本、轮换并撤销密钥，随后读取同一调用结果。证据保存在[浏览器证据目录](2026-09-13-能力服务Workbench/evidence.json)；脚本为 scripts/capability-browser-acceptance.mjs。它不构成对话式能力生成的真实模型验收。

底层仍保留隔离调试运行能力。调试使用 run_kind=debug，数据库内部 revision=0，公开查询省略发布版本；快照、invocation 和任务在同一事务创建，既不保存草稿，也不创建发布记录。当前产品入口不直接暴露这套底层调试接口。

真实模型对话验收、CLI 引擎接入、工具资源授权、条件/循环/人工等待语义、步骤 checkpoint 的自动恢复尚未完成。它们保留在整体目标内，不能由本次受控运行时测试替代。
