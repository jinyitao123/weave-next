## 用户动作与事实负责方

| 用户动作 | 当前入口及已有字段 | 事实负责方与消费方 | 接入要求 / G 用例 |
|---|---|---|---|
| 选择服务器 | 目前 Host 由 `WEAVE_API_URL` 和 `WEAVE_API_KEY` 配置；[Go 配置校验](../../../internal/app/weaveclient/config.go)接受 `wv_sk_` key | 现有配置属于 Host；新增 ConnectionProfile 只属于桌面偏好 | 描述和设备认证适配器待接入；不能把 Host key 当个人登录。G01/G02/G15/G16 |
| 账号登录/续期 | [auth.go](../../../internal/app/api/auth.go) `LoginRequest` 为 `username/password/tenant`；成功返回 `token/user`，refresh 返回 `token` | Weave 用户与认证入口；现有 [BrowserAuth](../../../workbench/packages/client/connection/src/browser-auth.ts)是 Host 的浏览器 cookie | 来源 AuthSession、跨 RPC/MCP 传递、撤权政策属于后续增量；不声称现有登录响应带设备会话。G03/G04 |
| 输入一条监督消息 | [SessionPromptRequest/Value](../../../workbench/packages/api/session-controller/src/types.ts) 含 `requestId/sessionId/mode/content/clientTimeZone?`，返回 `{accepted:true}` | Session/监督 Agent；[commands.ts](../../../workbench/packages/api/session-controller/src/commands.ts)把消息交给 `steer/followup` | 基线只证明进入 inbox；不能当成持久落盘或业务接受回执。G05/G06 |
| 派发团队工作 | MCP `team_dispatch` → [weaveclient](../../../internal/app/weaveclient/client.go) → `POST /v1/teams/:id/dispatch`；[基线请求](../../../internal/app/api/team_dispatch.go)含 task、mode、workflow_id/version、client_request_id、project_id、conversation_id | Weave 派发入口负责接受；Workbench 展示关联 | 工作流路径的稳定 ID 与指纹按代码处理；可信输入修订及材料引用以修复后的实际请求为准。G05/G07/G09/G10 |
| 读取派发结果 | [workflowManualRunResponse](../../../internal/app/api/workflow_manual_run.go)含 run_id、task_id、workflow_id/version、可选 project_id/conversation_id | Weave 回执；MCP 归一化后供监督工具和 WorkTask 使用 | 各模式须分别核对；`dispatch_status` 当前访问 `/v1/chat-requests/:id`，不能假设它能对账所有工作流派发。G07/G12 |
| 查看执行状态 | [server.go](../../../internal/app/api/server.go)注册 `/v1/runs/:id` 与 `/activity`；[WorkTask](../../../workbench/packages/bundle/workbench-app/src/index.ts)保留 runId、attempts、status 等 | Weave 运行事实；Workbench Session 存本地关联与投影 | 执行终态与交付核验分开；状态枚举消费修复版本，不提前复制一套新 enum。G12/G13/G19 |
| 停止前台讨论 | Session `cancel` 返回 `{accepted:true}`，针对当前 Agent turn | 监督 Session；不拥有团队 run 的终态 | 与业务停止分开显示。G19 |
| 停止指定业务 run | `POST /v1/runs/:id/stop`；[runs.go](../../../internal/app/api/runs.go)请求含 reason、grace_seconds、idempotency_key；202 返回 run_id/status/idempotency_key | Weave CancelRequest 与运行记录 | 202 是请求已接受；继续观察最终状态与副作用，不把关窗或本地 abort 当作停止成功。G05/G12/G19 |
| 上传材料 | [attachments.go](../../../internal/app/api/attachments.go)接收 multipart 文件，计算 digest，保存 workspace 归属；`POST /v1/attachments` | 附件存储与后续任务授权；Host 路径不是 Runtime 可读事实 | 个人/共享策略、派发材料集合与快照绑定待接入；不将 created_by 等同权限政策。G08/G09/G10 |
| 下载成果 | `GET /v1/deliverables?run_id=...` 与 `/:id/content`；[final_deliverables.go](../../../internal/app/api/final_deliverables.go)按存储内容返回下载 | Weave 成果记录；桌面下载路径由用户选择 | 实际打开并核对材料与 run 归属；存在成果条目不证明专业要求满足。G09/G12/G17 |
| 判断交付要求是否满足 | 基线 WorkTask 有执行状态与 deliverables；当前修复正在补交付判定 | 目标负责方为 Weave 的交付核验；客户端消费结论与证据 | 需求核验的字段与接口仍待修复提交，不能把 completed、总结或模型 PASS 替代核验。G12/G19 |
| 记录用户是否采用成果 | 基线 `weave-assess` 只在完成且有 final/summary 成果时，向 Session 写 outcome `adopted/needs-revision` 与 outcomeNote 并 flush | 当前事实在 WorkTask 的 Session；不是已存在的独立服务端接受 API | 保留既有事实，后续统一接受记录必须明确迁移；不与交付核验混为一项。G12/G19 |

## 五种事实不得互相替代

| 事实 | 基线可证明内容 | 仍待提供的保证 |
|---|---|---|
| 监督输入接收 | Agent inbox 接收回执 | 与落盘的准确顺序、可查询的持久输入接收 |
| Weave 业务接受 | 派发入口返回 run/task 等关联；幂等按具体模式处理 | 修复后的可信原输入、材料与授权绑定；丢响应后准确对账 |
| 执行结果 | 服务端运行状态和已观察运行事实 | CLI/Loom 的停止原因、预算/接续映射以修复证据为准 |
| 交付核验 | 现有成果记录可读取 | 对全部必需条件给出可核查结论；当前不冻结响应字段 |
| 用户接受 | 当前 Session 的 outcome 与备注 | 跨设备或服务端统一的接受事实若进入范围，须另外实现 |

最小字段样例见 [字段样例](字段样例.json)，其中 `existing_at_baseline` 表示源码已有字段，`proposed_consumer_requirement` 表示消费要求。样例身份全部是虚构值，不是实测响应，不应提交给任何业务服务。

## 请求上下文与接入时的核对项

当前 [RPC Host](../../../workbench/packages/client/connection/src/rpc-host.ts)以 endpoint、payload、signal 调用 handler；[MCP bridge](../../../workbench/packages/mcp/mcp-client/src/tools.ts)提交 name、arguments。这里不能推断来源设备会话已经受信传递。AuthSession 及 trusted OperationContext 属于后续应用边界接线，模型参数不能为其提供身份保证。

接入时先记录修复 SHA、实际 request/response/事件样例和反例测试，再补以下差异：输入修订如何由 Host 选定；各派发模式如何查询响应未知的原操作；执行/交付/接受分别在哪个对象保存；stop 回执如何关联最终停止；材料如何进入同一派发指纹。当前分支不为这些差异创造兼容枚举或模拟成功路径。

[连接选择源码](../../../workbench/apps/desktop/src/connection-selection.ts)中的 ServiceIdentity、ConnectionProfile、ConnectionScope 是客户端本地类型。`expectedInstanceId` 需要生产入口在业务处理前实际校验；本地代数只判断旧响应是否可以更新页面，不能作为服务端幂等键、授权票据或业务版本。
