# 分层迁移产品发现记录

日期：2026-09-14

本文记录迁移和真人式验收准备中观察到的产品问题。它区分“已经修复并完成工程验证”和“仍需在最终产品环境确认”，不以接口可用、运行阶段完成或模型自述代替业务验收。

## 已观察并已修复

### 建队试运行曾经像另一套产品

普通团队任务与建队试运行原先各自排队、取消和恢复。同一个用户动作因此可能出现两种等待方式、两种失败解释和两套恢复规则。现在两者共用平台执行管理；建队仍保留自己的业务进度，但不再拥有第二套物理队列。

工程验证已经覆盖重复提交、取消等待停止、执行者失联、恢复、迟到结果和延后继续。页面中的真实体验留到最终部署后确认。

### 指定工具曾可能再次交给模型选择

用户已经指定工具时，旧路径仍可能让模型决定是否调用。这会让一个确定动作变成概率行为。现在能力发布时冻结具体工具、参数规则、服务版本和权限，执行时直接进入受控工具入口。真实工具服务验证中只发生一次工具调用，没有模型代调用。

### 成果写着“通过”曾可能被系统相信

复核曾偏向检查成果是否存在以及文字是否完整，金额或集合错误可能逃过。现在发布的业务规则会实际比较金额、字段、数量、集合和重复项。成果即使自称通过，实际数值错误仍判失败；修正后可重新核验，历史失败继续保留。

### 修订任务曾丢失原始依据

用户要求修改上一版时，旧链路可能只传递本轮修改要求，团队看不到原始材料和上一版成果。现在服务端固定保留原任务、原材料、上一版最终成果、本轮修改要求和沿用的交付要求，并校验它们属于同一用户和任务链。

### “浏览器已经登录”并不等于“平台知道是谁”

Workbench 原有浏览器凭证只证明这台浏览器可以访问本机 Host，不能证明平台用户身份。用 Cookie 摘要代替用户，会让权限、历史和额度缺少真实归属。现在执行主体由平台账号或受验证的用户委托产生，并写入任务、快照和恢复事实；任务正文和任意身份字符串不能改写它。

### 共享 Host 存在三条不明显的身份旁路

只给普通网页请求加用户身份仍不够。检查中另外发现：后台轮询可能继续用 Host 身份；共享 MCP 进程可能用固定 Host 密钥建队或调用能力；会话事件和控制流可能通过长连接绕开普通请求检查。

当前改造覆盖普通请求、后台工作、逐次 MCP 调用和长连接会话。每次动作都绑定当前登录用户；缺少用户委托时明确要求登录，不再退回 Host 账号。双用户页面和长连接验证尚在进行。

### 模型缓存也会形成跨用户泄漏

即使数据库按用户保存密钥，如果模型客户端仍按工作区缓存，两个用户可能复用同一会话或旧密钥。现在个人模型路由按可信用户分区；共享服务每次重新检查授权且不长期缓存。凭据撤销后，已经取得的旧路由对象也会拒绝继续调用。

### 取消不能等同于工作已经停止

远程工作可能在断连后继续运行。旧做法若立刻显示已取消，会掩盖仍在发生的调用和费用。现在取消请求、执行停止确认和外部影响分开保存；没有停止回执的运行进入核对，确认后才恢复或结算。旧执行世代的迟到结果不能覆盖新执行。

### 运行环境曾经知道太多平台内部细节

远程 Host 原先直接理解平台队列、存储类型和内部失败入口。这会让 Loom、Codex 或其他运行环境各自形成一套恢复与终态规则，也让平台升级容易迫使所有 Host 同步修改。

现在 Host 只接收版本明确的执行请求，并返回用量、工具、产物和停止结果。平台统一决定派发、重试、期限、额度和最终状态。未知协议版本会明确拒绝，旧失败入口和模糊终态已经移除。Loom 保留通过 Codex 等提供方获得推理的能力，但不再重复控制平台执行。

### 个人任务目录曾可能被后台能力绕开

多人共用一台 Host 时，仅隔离页面列表仍不够。后台轮询、会话恢复、工具调用和工作目录如果继续共用默认身份，用户可能看到正确的任务列表，却仍在共享位置执行或读取材料。

现在个人任务从登录、会话、后台派发到工作目录使用同一可信身份；普通用户只进入自己的任务空间。管理员明确创建的共享项目保留为协作资源，不能由普通个人任务自动升级为共享。

## 仍需最终产品验收确认

- 登录、退出、刷新和账号失效时，页面是否始终给出自然的下一步，且不会短暂显示他人的任务。
- 两名用户共用同一 Host 时，会话、任务、材料、模型凭据、工具授权、目录、产物和历史是否都不可交叉访问。
- AI 建队能否从真实任务稳定生成完整、可计算的业务核验规则。
- 简单机械任务是否保持直接执行，不被强制增加方法研究、建队或多层复核。
- Loom 经 Codex 提供推理时，暂停、恢复、用量、取消和工具权限是否按平台规则呈现。
- 远程断连、Host 进程中断和恢复后，已确认工作是否保留，未知副作用是否不会被重复执行。
- 版本不匹配、旧 Host 或缺少停止回执时，页面是否给出可理解且可继续处理的状态。

以上项目只在迁移、分仓和新环境部署完成后，通过 Workbench 正常页面、真实模型、实际成果及独立复核关闭。
