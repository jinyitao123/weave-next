## 已接通的行为

调用应用拥有稳定的 app_ 标识。应用可同时持有多个 wv_cap_ 访问密钥，每个密钥只包含 invoke、read、cancel 中的选定范围。轮换时创建新密钥、替换调用方配置、再撤销旧密钥；新密钥仍能读取和重放旧密钥创建的调用，request_id 的工作空间和应用归属保持不变。

应用只能调用明确授权的 capability_id 和发布修订。应用密钥不能保存草稿、调试、发布、管理应用或访问其他平台接口。读取和取消只允许访问本应用的调用。开发者与管理员继续使用人员身份或已有 Host 管理凭据，管理操作同时校验数据库中人员的当前工作空间、角色和停用状态。

能力草稿、发布版本、应用、凭据、授权和调用都以 workspace_id 作为数据库归属边界，跨工作空间读取、管理和执行默认拒绝。同一工作空间内，能力是受权限控制的组织资产，并非每位开发者的私人副本；应用调用则继续按稳定应用身份隔离。当前桌面 Workbench Host 使用一个开发者凭据，因此只支持一个人员身份。多人共享 Host 前必须增加逐用户委托身份，否则不能宣称具备个人级审计归属。

## 持久事实与撤销

0141 迁移增加应用、凭据、版本 grant 和操作审计四张表。密钥为 32 字节随机值，数据库只保存 SHA-256 摘要；只有创建响应返回原密钥，快照不返回原文或哈希。

应用调用在写入 invocation 和任务的同一事务中重新检查应用、凭据、操作范围和版本 grant，认证后的撤销仍能阻止受理。领取任务、每个 Loom 步骤登记、运行期间的检查及结果回写继续检查应用和版本授权。撤销授权或停用应用会阻止后续执行与可用结果；撤销旧密钥本身不取消此前已合法受理的任务，以支持轮换。

调用记录保存首次受理凭据 ID 供审计，但所有者使用应用 ID。旧凭据仅标记撤销，不删除既有调用归属。正式应用调用与开发者调试使用不同的 caller_kind，应用凭据不能创建 debug 运行。

## Workbench

“调用应用”设置页提供创建与停用应用、授权和撤销版本、选择密钥操作范围、创建新密钥和撤销旧密钥。新密钥一次性显示，手动隐藏或切换应用后不再显示；宿主自身的 Weave 凭据不进入页面。

浏览器验收经过真实 Workbench Host、认证中间件、PostgreSQL 和现有 Loom runner：页面创建应用、授权已发布版本、创建首个密钥；应用发出调用后，页面创建替换密钥并撤销旧密钥；新密钥重放得到同一个 invocation_id，读取原结果，旧密钥得到 HTTP 401。模型端仍为受控 HTTP 测试服务。证据见[结果 JSON](https://github.com/jinyitao123/weave-next/blob/d9d7f797d059b43ffc71c990cd089f0956f5accc/docs/%E9%AA%8C%E6%94%B6/2026-09-13-%E8%83%BD%E5%8A%9B%E6%9C%8D%E5%8A%A1Workbench/evidence.json)和[应用页面截图](https://github.com/jinyitao123/weave-next/blob/d9d7f797d059b43ffc71c990cd089f0956f5accc/docs/%E9%AA%8C%E6%94%B6/2026-09-13-%E8%83%BD%E5%8A%9B%E6%9C%8D%E5%8A%A1Workbench/applications.png)。

## 验证

- PostgreSQL 测试验证密钥轮换、授权撤销对 queued/running 的作用、迟到输出丢弃、认证后撤销、跨工作空间管理拒绝及敏感字段不进入快照。
- HTTP 测试验证应用凭据的版本授权、读取归属、各操作范围、旧密钥失效，以及普通平台路由拒绝该类凭据。
- 前端生产构建、404 项 Workbench 相关测试及实际浏览器操作通过。
- make test、make depguard、make productguard 通过。应用与 HTTP 相关测试显式设置 TEST_DATABASE_URL 并启用 -race。
