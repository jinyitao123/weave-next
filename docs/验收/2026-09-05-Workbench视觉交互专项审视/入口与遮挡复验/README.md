# 任务卡遮挡与顶部入口复验

2026-09-06，针对停止卡片展开回执后占据输入区上方、顶部团队状态重复以及会话记录下载按钮的反馈进行修正。

## 实现

任务卡原本与输入框共用固定在底部的容器，展开回执会扩大覆盖消息的区域。Workbench 现在将输入上方的任务区放回正常文档流，随消息滚动；输入框单独保持固定。其他构建配置保留原有布局。

停止卡片收成一行，保留状态与现场入口。操作历史移至工作现场的进展页，不再在输入旁展开。记录仍保留；“请求已接收”表示系统接受了操作请求，具体运行结果由当前状态呈现。“你的答复”改为“此前提交的回答”，明确这是历史人审提交内容。

顶部改为单排标题与“工作现场 · 当前状态 ›”。标题保持可读，长团队名留在悬停提示中，进入箭头和按钮边界提示可点击查看更深入的进展、成果及操作记录。Workbench 移除会话记录下载按钮，保留既有日志服务与命令反馈。

## 检查

- `make workbench-install workbench-check` 通过，聚焦 264 项通过。
- GUI 回归 301 个文件通过，4004 项通过、1 项跳过。

- 任务组件回归检查顶部入口可打开现场、长团队名不占标题行、历史回执仍在现场保留且默认收起。

- 浏览器取消全流程与 fixture inventory 共两项通过，包含草稿排队、删除、取消、停止后恢复及记录展开。四份 Workbench 专用黄金记录本次已批准的呈现变化，保留原通用黄金和会话样本。

真实页面的长对话滚动、窄窗口、现场入口与回执检查见[浏览器复验](浏览器复验.md)与[测量记录](real-session-results.json)。两种宽度下停止卡片均为 60px 高，滚动时离开视口，输入区位置变化不足 1px；对话区没有回执折叠块，现场回执可展开。全量文档检查的[迁移基线问题与本次增量](doc-sync-baseline.md)分开记录，不计作通过。后续的[现场排版复验](../现场排版复验/README.md)记录内容宽度、成员行及长文排版的最终检查。
