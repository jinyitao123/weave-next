# 精修样板 · 会话卡、成员阅读与成果预览

本轮只交方案。后续先完整精修这一条路径，再推广其他页面。样板覆盖同一主对话的任务卡，以及工作现场的两种内容状态，保留 Weave 的简洁、克制和以文字为主的风格。

## 想让用户感受到的变化

打开现场马上知道谁在做什么，正文就在眼前。图标安静、清楚，不会在鼠标移上去时变成另一种东西。展开后清楚内容从哪里开始、在哪里结束；切换或收起再回来，可以接着读。技术信息需要时找得到，默认不占据阅读区。

主对话的运行、等待和结束卡片属于第一轮范围，详见[运行与结束卡片方案](运行与结束卡片方案.md)及[卡片视觉细则](卡片视觉细则.md)。不能只精修现场后就认定整体通过。

## 图标与展开收起的可见规则

| 对象 | 样板规则 | 实际效果怎么判断 |
|---|---|---|
| 内容图标 | 文档、表格、图片使用同一家族；固定在文件名前，悬停不改变类别 | 扫一眼知道是什么文件，文字不移动 |
| 展开箭头 | 固定右侧，收起向右、展开向下；整行可操作 | 任意折叠行的开合都可预测 |
| 返回／进入详情 | 与就地展开的图形区分，仍使用同样的线条重量 | 不会以为“进入成员”只是展开一段内容 |
| 关闭／更多 | 使用常规清晰的线条造型；不加无意义的卡片背景 | 和正文、文件图标处于同一视觉体系 |
| 点击区域 | 图标可小，操作区需从容；默认预留位置 | 无需瞄准小三角，不改变标题截断 |
| 选中与焦点 | 选中表示正在看的内容，焦点表示下一次按键的对象 | 两种状态可同时看懂 |

起始参数建议为行内图标16像素、较主要工具图标18像素，线条视觉重量约1.5像素；操作区至少28×28像素，主要按钮高度32—36像素。它们是打样起点，需在真实屏幕上检查光学对齐，不能仅按外框数学居中判定好看。保留已有品牌色，不统一改成系统蓝。

短信息展开采用同一缩进和12—16像素的内容间距，一条轻分隔足以表达归属；不再给每层都包边框卡片。多个文件需要分组，单个阶段文件直接露出。长文进入一个稳定阅读区，标题及收起入口在阅读时仍易找到；不要在长文底部堆一排重复控制。

## 产物预览的目标效果

文档的标题与正文层级清楚，默认宽度舒适；全幅增加可用空间，但正文不无限拉长。建议正文宽度上限约720—800像素、正文15像素、行高1.65—1.75。表格和大图可超出文章的文字宽度，用明确的横向阅读区域承载，避免整页横向漂移。

文件标题、状态、收起、下载和全幅入口组成稳定工具栏。短结果直接显示，长结果滚动阅读。当前终审批注能明确显示“已通过”和评语，原始数据另行展开；其他未知结构不自动改写。

预览体验必须区分以下四种状态，文案只谈用户此刻能做什么。

| 状态 | 页面应呈现 | 后续动作 |
|---|---|---|
| 正在加载 | 文件名保持可见，正文区域给轻量加载反馈 | 可返回、可切文件，不整页闪空 |
| 已载入 | 默认看清主体内容 | 阅读、全幅、下载 |
| 暂时无法显示 | 简短说明没有成功载入 | 重试与下载；故障细节按需查看 |
| 该格式尚不支持 | 清楚写“暂不支持在线预览” | 下载文件，不给一个空白容器 |

格式能力以[支持矩阵](技术附录.md)为当前边界。第一轮先把已有格式的阅读效果和失败兜底做完整。PNG/JPEG、PDF、Office 等新增预览能力需要另定范围，不能在迁移中顺手扩展。HTML 静态预览应提示其为预览，不能让用户误认为其中所有按钮都能执行原页面操作。

## 操作状态的连续性

| 操作 | 预期反馈 | 必须保留 |
|---|---|---|
| 悬停折叠行 | 轻背景，固定箭头 | 标题位置、内容图标 |
| 按下 | 轻微明暗变化，松开后恢复 | 不拉伸整行、不造成周边位移 |
| 展开短说明 | 标题下方出现内容 | 被点标题仍在视线内，焦点在原控制 |
| 展开文件 | 出现可阅读内容，归属明确 | 当前任务与文件身份 |
| 收起文件再打开 | 回到之前阅读状态 | 段落、表格横向位置、图片缩放 |
| 进展与成果往返 | 同位置切内容 | 页签焦点、成员、分组开合、阅读位置 |
| 全幅与返回 | 空间变化关系清楚 | 草稿、展开状态、同一段落 |
| 关闭现场再打开 | 回到上次上下文 | 当前任务内的成员、内容与位置 |
| 新公开记录到达 | 在读旧内容时显示轻提示 | 不强迫滚到底部 |

动效仅作为关系提示。短开合可从约120—160毫秒试起，避免给整段长文做夸张高度动画；减少动态效果开启时取消位移和缩放过渡。上述动效尚未实现和验收。

## 小窗口规则

1440宽时保留会话与现场并排，比例可调；1024宽用现有真实布局复验两侧阅读，不为了坚持并排而把主要内容挤成细条。768宽进入单现场时，返回对话入口清楚，返回后草稿可继续输入。390宽作为探索样本检查主控制可用和表格兜底，不自动扩大为手机端产品承诺。

成员摘要、运行信息不能随着变窄越堆越高。必要辅助信息合入“详细信息”；主控制换行有固定顺序，不把文字标签缩成难懂的符号。

## 样板复验顺序

1. 补充真实运行到成功、执行失败、等待及停止的会话卡连续观察，核对状态、主动作、卡片高度和输入区稳定。用已有真实中断任务，进入成员，展开长记录并读到中段。
2. 切成果，打开阶段文档，收起、再打开；回成员继续读。
3. 在成果里全幅、调整窗口、返回，核对同一段落和草稿。
4. 用已完成任务，从会话直接打开最终成果，检查内容、文件身份与返回。
5. 用真实表格、SVG和静态HTML分别验证预览；没有样本的格式明确保持待验。
6. 用纯键盘重复路径，补测加载失败、减少动态效果和深色模式。
7. 同一组截图对比普通、悬停、按下、展开、收起和窄窗口。再录完整流程，确认截图之外没有跳动。

**视觉验收单独签署。** 图标、开合边界、正文宽度、首屏层级、技术细节收纳和不同尺寸一致性全部满足后通过。

**交互验收单独签署。** 焦点、阅读锚点、分组状态、预览缩放与位置、返回和错误反馈全部满足后通过。只要仍需反复寻找原段落或文件，就继续修样板。
