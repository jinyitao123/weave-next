# Weave Workbench 视觉与交互专项审视

2026-09-05 · 当前本地页面独立走查 · 方案交付，未修改产品代码

目前能走通会话、工作现场、成员详情和成果查看，完成任务的成果入口也能直接打开对应文件。但细腻程度仍未达到本次要求。最先需要修复的是切换后的焦点与阅读连续性；视觉精修应优先统一展开收起、图标和产物阅读界面，再压缩重复说明。

**视觉验收：不通过本次精修质量目标。交互验收：不通过，存在已复现的焦点与阅读位置问题。** 这两个结论分别针对呈现品质和操作连续性，不等同于所有功能不可用。本次未发现有充分证据支持的 P0。

用户追加的重点已纳入排序：图标美观度、产物预览的支持与实际效果、展开收起体验；产品面向用户的页面减少技术细节。后续以[会话卡、成员阅读与成果查看样板方案](精修样板方案.md)为第一轮范围，完成并实际复验后再推广。

## 整体设计原则

1. **阅读内容优先。** 进入成员后先看到他在做什么、已有结论和公开记录；进入成果后先看到文件和内容。运行位置、编号和工具详情进入一个次级信息入口。
2. **位置形成记忆。** 进展、成果、返回、全幅等入口保持稳定。用户切回来，应接着刚才的段落读。
3. **展开只有一套规则。** 内容图标说明对象，箭头说明开合；两者各自占位。轻量补充就地展开，长文进入阅读区，避免大段正文套在多层折叠中。
4. **图标是一套产品语言。** 保留 Weave 的黑白主体、低饱和状态色和清晰文字；统一线条、尺寸、光学居中和交互区域，不照搬系统装饰。
5. **状态只说本层需要的信息。** 会话列表用短状态，现场说明原因和下一步。不能只为少字而隐藏真实失败，也不能让重复长句挤掉任务名称。
6. **有反馈，但不搬动内容。** 悬停不挤压文字，按下可感知，选中与键盘焦点各自清楚。动效帮助理解对象的出现和收回，不能打断阅读。

质量参照采用 Apple 对[滚动视图](https://developer.apple.com/design/human-interface-guidelines/scroll-views)中上下文保持、对[布局](https://developer.apple.com/design/human-interface-guidelines/layout)中适应变化且保持熟悉关系的原则。下文的尺寸、误差和时长均为本项目拟定的样板目标，不是 Apple 强制数值。

### Q01 · 切换后失去键盘焦点

位置是成员详情顶部的“进展／成果”。[真实截图 A10](证据/A10-keyboard-tab-loss.jpg)，[键盘记录](证据/keyboard-tab-focus.json)。进入成员详情，在“进展”上按右方向键，成果已选中，但焦点落到页面根部；下一次 Tab 到了上方“查看任务要求”，没有从选中的成果页签继续。

用户影响是键盘路径中断，视觉上的选中状态也不能告诉用户下一次按键会作用于哪里。建议让页签在切换中保持同一位置与身份，焦点留在新选中页签；随后的 Tab 进入该页内容。不要用自动滚到页面顶端来掩盖焦点丢失。

复验需覆盖方向键、Home、End、鼠标切换及成员／总览两种入口。选中页签始终有正确焦点，下一次 Tab 按页面顺序前进，不跳到前面的任务说明；连续往返十次不失焦。

### Q02 · 返回后的阅读位置不稳定

位置是成员公开记录的长文区域。[离开前 A07](证据/A07-reading-middle.jpg)、[回来后 A09](证据/A09-reading-return.jpg)、[测量记录](证据/tab-reading-return.json)。展开长记录并向下阅读，切到成果再回来。记录的展开状态与内层滚动位置确实保留；但外层位置从 254.5 回到 0，阅读区顶部由 237.23 移到 491.73，视线需要向下重新找段落。

用户影响是来回核对成员产出时反复定位。建议长文使用一个主要纵向阅读区，切换按成员与内容分别保留阅读锚点；窗口变化时优先保住正在看的段落。实时更新也不得把正在读旧记录的人带回底部。

复验使用同一长文，记住屏幕上的一段话，切成果、切成员、全幅返回后仍能继续读。同尺寸下段落位置偏差目标不超过 4 像素；改窗口尺寸时允许重排，但该段保持可见。本轮只确认了切成果返回的缺陷，其他路径列为修复后的必测项。

### Q03 · 展开收起缺少统一的体验

位置横跨公开记录、阶段产物组、具体文件和补充说明。[成员 A05](证据/A05-member-desktop.jpg)、[成果未展开 A08](证据/A08-member-to-outputs.jpg)、[文件展开 A11](证据/A11-stage-document.jpg)、[最终成果 A18](证据/A18-final-deliverable.jpg)。目前既有文字“收起本条记录”，也有左侧实心小三角，以及文件行右侧箭头；阶段成果默认先开分组，再开文件。长记录之下又能展开同一阶段文档，形成重复正文和多层高度变化。另已实际复现：阶段分组和文件均展开时，只切到进展再回成果，外层分组自动收起，正文重新被藏住。见[切换前 A21](证据/A21-stage-group-open.jpg)和[返回后 A22](证据/A22-stage-group-return.jpg)。这部分是行为缺陷，不只是外观偏好。

用户影响是每个位置都要重新判断“点哪一块、会打开多少、在哪里收回”。分组折叠本身有用，问题在于不同对象的开合规则和内容尺度没有一致性。

建议统一为三种清楚的动作。短补充信息就地展开；成果分组仅控制文件列表；具体文件打开固定阅读区。只有一个文件时直接露出文件行，保留“阶段产物”归属即可。长文展开后，收起入口留在该块标题位置且可找回，不在原文之下再展开一份相同内容。整行可点，箭头固定在右侧；右指表示收起，下指表示展开，悬停不替换内容图标。

复验标准是用户在任意折叠行都能用同一种方式开合；点击图标、标题与空白区域结果一致；键盘 Enter／Space 可操作；打开后边界清楚，关闭后焦点回到该标题且不跳到无关内容。单个阶段文件从成果页一次操作进入正文，不用先猜隐藏在哪一层。大量文件仍可分组，避免全部摊开。

### Q04 · 图标缺少一致的美观度

位置包括侧栏工具、成员返回、说明展开、成果文件和关闭按钮。[团队 A06](证据/A06-team-overview.jpg)、[成果 A11](证据/A11-stage-document.jpg)、[窄窗口 A15](证据/A15-member-narrow-stable.jpg)。当前同一现场混用实心三角、文字式 ‹／› 和线条图标，外观重量与对齐基准不一致；成果文件的辨识点也弱于大段文字。

这是视觉判断，不能把“采用不同圆角或多个图标尺寸”本身判为功能故障。它之所以优先，是因为这些符号贯穿用户最在意的展开收起和查看产物过程。

建议选定一套简洁的线条图标，统一常用返回、开合、关闭、更多和文件类型的轮廓。内容图标稳定表示文档、表格、图片；状态和开合不借用内容图标。优先修光学对齐与线条重量，少用背景方块装饰每一个小图标。具体样板规则见[精修样板](精修样板方案.md)。

复验在真实页面的普通、悬停、选中、按下和深浅背景中逐一比较；相邻图标视觉重量接近，没有文字箭头替代件，文件种类可辨，点击区域不挤压标题。不能只交一张图标库截图作为通过证据。

### Q05 · 产物预览需要成为可用的阅读界面

位置是成果页文件展开区。[阶段文档 A11](证据/A11-stage-document.jpg)、[全幅 A13](证据/A13-output-fullwidth.jpg)、[最终结论 A18](证据/A18-final-deliverable.jpg)。Markdown 文档能实际阅读，最终成果入口也能直接定位并展开正确文件，这是已确认的优点。但阶段文档正文约从屏幕 y=630 才开始；全幅时正文横向铺开，长行和宽表格不便扫读。最终审阅结论以 JSON 原文呈现，用户需要自己读字段才能获得业务结论。

建议给预览稳定的文件标题栏和阅读区域，默认展示可读内容，将下载与原文保留为次要操作。正文用舒适的最大阅读宽度，表格允许独立横向查看。对当前明确的终审结果，用“已通过”和审批意见呈现，原始数据置于“查看原文”；普通未知结构的数据仍保持真实原文，不自动编造解释。预览失败或不支持时明确说明，并保留下载入口。

复验应分别拿长 Markdown、宽表格、图片、长 JSON 和不支持格式检查。当前已实操通过的只有 Markdown 与 JSON；表格、SVG 的能力有代码依据但缺真实文件验证，不能算预览效果已通过。HTML 有静态预览代码，但本轮未拿真实产物确认效果；PNG/JPEG、PDF、Office 等在当前成果阅读器中没有专用渲染分支，也不能凭“有下载链接”算已支持预览。完整支持矩阵见[技术附录](技术附录.md)。增加新的格式能力不在这次审视中自动实施，后续应单独确定范围。

### Q06 · 首屏让说明先于工作内容

位置是成员详情头部及团队／成果头部。[成员 A05](证据/A05-member-desktop.jpg)、[总览 A06](证据/A06-team-overview.jpg)、[成果 A08](证据/A08-member-to-outputs.jpg)。1440×900 下，从现场内容顶端到公开记录区域约占可用高度的 52%；期间依次出现返回、页签、成员名、角色、运行信息、阶段状态、记录能力说明、关注和调整、执行记录标题等。切成果时页签还从约 y=116 移到 y=350，成员上下文换成团队长说明。

用户影响是第一眼知道很多背景，却迟迟看不到工作本身。已完成成员仍展示“执行中接收成员的公开记录”，也容易让人把能力说明误读成当前状态；本轮不据此认定后台运行状态错误。

建议固定页签层级和位置，成员摘要压到“姓名、正在做什么／已完成什么、一个主要操作”。运行技术信息统一放进次级详情。公开记录说明按当前是否仍有更新显示。团队和成员之间用明确返回关系，成果始终标明其属于当前任务。

复验在 1440×900 下未主动展开辅助信息时，首屏应能读到至少一段有效记录；阅读区起点目标不晚于 y=280。同尺寸进展／成果切换时页签位置不变，辅助信息展开后不会掩盖返回入口。1024 并排及768单面板均再验。

### Q07 · 失败卡片重复任务介绍，稀释下一步

位置是创建失败会话卡和工作现场。[会话 A19](证据/A19-creation-failure.jpg)、[现场 A20](证据/A20-creation-failure-scene.jpg)。两处都重述一大段验收目标，再提示回到主对话。会话卡已经位于主对话中，“请回到主对话”的表述增加了一次理解绕路。

建议会话卡集中说“团队未创建成功，任务未派发”和下一步，任务要求按需展开。现场保留“回到对话继续处理”；会话中的动作直接聚焦输入区或打开相关处理上下文。技术原因按需查看，不能以隐藏技术细节为由把错误原因全部抹掉。

复验两个入口中的文字符合所在位置，用户能一眼找到继续处理入口；回到对话后焦点应落在明确的可操作位置。原确认要求保留但不整段重复。无需重新执行真实失败任务来验证版式，先用现有失败记录复验。

### Q09 · 终态卡片缺少统一的细致层级与容器规则

位置是主对话底部的任务结果卡。[成功 A18](证据/A18-final-deliverable.jpg)、[创建失败 A19](证据/A19-creation-failure.jpg)、[已停止 A23](证据/A23-stopped-conversation.jpg)。不同状态的第一眼内容顺序不同，卡片、输入区、按钮的留白和外轮廓尚未形成一套明确规则。用户提供的[浮层参考图](参考/R02-浮层与分组.png)展示了更从容的分组、清楚的对齐和柔和边界。这项是视觉判断，不把不同内容自然形成的高度差当成故障。

建议统一结果卡的“状态结论、结果或影响、主动作、次级详情”顺序，明确任务卡、输入卡和浮层三种容器各自的圆角、边界与阴影层次。技术说明按需查看，主卡保留用户能理解的原因。详见[卡片视觉细则](卡片视觉细则.md)。

复验把成功、创建失败、执行失败、停止、等待、运行中卡片在100%正常显示下比较，检查长中文换行、内边距、图标与按钮基线。视觉通过之外，还需连续观察状态变化时的高度、焦点和输入区稳定性。当前动态与执行失败样本尚未实测，不给通过。

### Q08 · 悬停让会话标题缩短

位置是左侧会话行。[悬停 A04](证据/A04-sidebar-hover.jpg)、[尺寸记录](证据/sidebar-hover-metrics.json)。更多按钮出现时，标题和副标题可用宽度从216变为196像素，截断位置随指针变化。

建议给行尾操作预留固定空间，仅改变显隐和反馈；同一行的文字布局保持稳定。16像素按钮元素边界是本轮测量结果，并不能单凭它判断实际可点击范围。

复验长短标题、多种状态、侧栏伸缩与键盘聚焦。悬停前后文字区域位置和宽度不变，更多操作有清晰反馈且不遮住标题。建议约28像素的行尾交互区，最终以实际鼠标操作效果确认。
