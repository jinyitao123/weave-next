# 运行时动效与结束后的对话卡片

这部分是核心审视范围。它与成员、成果样板共用同一条任务路径，但必须从主对话单独验收。工作现场精修通过，并不能替代会话页面通过。

现有可见会话样本以历史终态和中断为主。本轮未为取得动效而新建或派发任务。后续样板复验要使用真实进行中的任务，或者隔离的审视样本并明确注明来源；模拟演示只能验呈现，不能证明真实后端过渡正确。

## 卡片应回答的三个问题

当前发生了什么；已有的东西在哪里；用户下一步可以做什么。状态、正文和动作按这个顺序组织。任务名称保留，但长要求、运行编号和执行明细默认不重复铺开。旧聊天消息作为历史保留，不悄悄重写；当前卡片应让人明确分辨旧消息与最新状态。

| 生命周期 | 卡片主要内容 | 主动作与补充动作 |
|---|---|---|
| 排队／准备 | 已收到任务、正在准备；真实有排队信息时才显示 | 查看进展；可用时提供取消 |
| 正在执行 | 当前阶段或正在处理的事项，轻量动态提示 | 查看进展；调整、停止按重要性分层 |
| 等待用户 | 具体等用户决定什么 | 完成该决定；展开必要背景 |
| 连接中断／状态未确认 | 目前无法确认什么、哪些工作已保留 | 可用的恢复路径；不假装已停止或可重跑 |
| 执行成功且有成果 | 一句结果摘要，清楚的文件入口 | 查看成果；其他操作收进次级入口 |
| 执行完成但交付未确认 | 明确区分执行已结束与成果状态 | 查看当前记录；不展示虚假的成功交付 |
| 执行失败 | 哪里没有完成、已有产物和下一步 | 能重试时才提供重试；否则说明处理路径 |
| 已停止 | 停止已确认及已有工作保留情况 | 查看已有工作；回执按需展开 |

这些是显示规则方案，不是声称当前所有状态都已具备相应动作。动作是否可用必须服从真实运行事实。

## 运行时动效怎么审

- 是否只有少量必要区域在动。状态点可轻呼吸，新记录可短暂提示；不能让标题、按钮和整张卡同时闪动。
- “正在工作”和“正在等待”是否不同。持续动效只能表明活动状态，不能伪造进度百分比或私人思考。
- 长时间没有新输出时，是否仍能理解状态。不能靠一直转圈代替可用的情况说明。
- 新记录到达时是否打断旧记录阅读。只在用户选择跟随时自动跟随，其他情况给轻提示。
- 成功、失败、停止或等待后，执行动效是否及时停下。结束时用稳定结论替换活动提示，避免还在运行的错觉。
- 卡片高度变化是否挤动输入框、遮住用户正在看的消息，按钮变化时是否丢焦点。
- 窗口隐藏后回来、网络暂时断开、减少动态效果开启时，反馈是否仍可理解。

当前源码具有运行状态点呼吸与新公开记录到达效果；它们是待验入口，不能据此判断节奏自然、终态停止及时或多处动画不过量。

## 和第一轮样板一起复验

从主对话打开运行中的现场，阅读成员记录，回主对话等待该次执行结束，直接查看成果，再返回继续讨论。分别覆盖成功、执行失败、用户等待、已停止及状态未确认，录制连续过程。

视觉验收看卡片层级、信息密度、图标与动效节奏是否统一；交互验收看状态与按钮是否准确切换、焦点和草稿是否保留、成果是否直达、失败是否可继续处理。当前动态部分仍为待验，不能在最终验收中省略。
