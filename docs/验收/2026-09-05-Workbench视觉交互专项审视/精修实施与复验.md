# 第一轮精修实施与复验

实施时间为 2026-09-05 至 2026-09-06。范围是主对话任务卡、成员阅读、成果预览及其共用操作；保留原有任务模型与格式能力。原始[精修样板方案](精修样板方案.md)描述目标，本页记录实际实现与证据边界。

## 已实现的变化

| 部位 | 本轮结果 |
|---|---|
| 主对话任务卡 | 收紧重复任务介绍，统一圆角、边框、阴影与操作间距；创建失败提示符合当前所在的对话位置；修正等待状态引用不存在的主题变量，恢复可见警示圆点 |
| 页签和成员头部 | 进展与成果保持同一行；成员头部缩短，运行编号等识别信息收进详细信息 |
| 图标与折叠行 | 返回、进入、下载和缩放使用细线图形；展开箭头固定右侧，收起向右、展开向下；单个阶段文件不再套第二层分组 |
| 成员记录 | 与现场共用主滚动区；摘要使用原文首段并按 Markdown 呈现；展开后的完整原文保留 |
| 成果阅读 | 文档限制行宽，下载前置；已打开的文件在收起、切换页签后保持挂载，表格横向位置和 SVG 缩放保留 |
| 人审批注 | 仅识别已知的双字段终审格式，显示决定与评语；原始 JSON 可展开，其他结构完整按原文呈现 |

没有新增格式支持。CSV、TSV、SVG、Markdown、静态 HTML 和普通文本沿用已有能力。表格仍最多显示 200 行、40 列并给出截断提示。HTML 仍在限制脚本与外部资源的隔离预览中打开。

## 真实页面复验

本组使用本地 Weave Workbench 中已有的真实会话，只操作阅读、页签和显示偏好，没有将隔离数据写入用户会话。

| 场景 | 证据 | 结果 |
|---|---|---|
| 从最终成果进入，往返页签 | [最终审阅与键盘焦点](精修证据/P01-final-review.jpg) | 已知人审批注可读；再次进入成果时焦点留在页签，不重放首次深链焦点操作 |
| 成员头部与记录摘要 | [成员头部](精修证据/P02-member-header.jpg)、[最终摘要](精修证据/P07-final-member-excerpt.jpg) | 辅助信息收起，摘要不再直接露出 Markdown 标记或裁切半行 |
| 成员长文中段往返 | [页面截图](精修证据/P08-final-reading-roundtrip.jpg)、[测量记录](精修证据/reading-roundtrip-final.json) | 主滚动位置 1034 → 1034；同一可见章节纵坐标 260.125 → 260.125 |
| 独立浏览器页签往返与刷新 | [最终测量记录](精修证据/reading-independent-final.json)、[刷新后截图](精修证据/P16-independent-final-reload.jpg) | 固定 1440 × 900 视口，前后均为 829；同章节纵坐标均为 464.890625，展开状态保留，无页面错误 |
| 390 宽的成员阅读 | [窄窗口](精修证据/P09-narrow-reading.jpg) | 单现场可读，无页面横向溢出；这是窄尺寸探索样本 |

刷新偏移已修复。独立浏览器初次复验发现 829 → 312；[调用栈与布局测量](精修证据/reading-scroll-source-trace.json)证实，面板从很窄展开时，浏览器自动滚动锚定改变了已恢复的位置，没有第二次 JavaScript 滚动写入。修正在承载任务现场的正文滚动区关闭自动锚定，由现场统一恢复位置。最终测量使用正式构建，没有注入样式；同一浏览器再检查 390 × 844，页面宽与滚动宽均为 390，现场宽与滚动宽均为 333。初次失败记录保留用于解释根因，不计入通过项。

## 隔离预览复验

[隔离预览说明](精修证据/F-preview-isolated-note.md)和[测量结果](精修证据/F-preview-isolated-results.json)使用生产组件、CSS 和主题，页面明确标注测试数据。CSV、TSV、SVG 分别覆盖 1440 与 390 宽，共六组通过。

表格和放大图纸使用原生横向滚轮与键盘移动。SVG 在 200% 下收起再展开保持缩放和横向位置，适应宽度回到 100%，切换文件重置为 100%。[390 宽图纸截图](精修证据/F-svg-390-zoom200-right.png)保留实际焦点和横向阅读状态。下载入口已检查可见，但这组验证没有经过真实鉴权下载链路，也没有复刻 Workbench 外层布局。

## 自动化检查

主对话卡片另有[隔离状态验收](精修证据/G-card-isolated-note.md)与[测量结果](精修证据/G-card-isolated-results.json)，直接加载生产组件和主题。准备、执行、等待、失败、完成且有成果、完成但成果待核实、已停止七种状态，分别检查 1440 与 390 宽，共 14 组无横向溢出。[窄窗口状态截图](精修证据/G-card-states-390.png)记录了状态层级和成果入口。

同一个挂载卡片从执行切至等待、完成后，活动标记与脉冲停止。减少动态效果下，执行状态点保持可见，卡片子树动画为零。检查中发现的等待圆点透明问题已修复，并在两种宽度重新测得实际警示色。这些结果证明前端接收给定状态后的呈现，不证明后端连续运行正确。

| 检查 | 结果 |
|---|---|
| `make workbench-install workbench-check` | 依赖安装通过；`make workbench-check` 退出码 0，25 个文件、263 项聚焦检查通过；随后仅修正警示色变量，最终 Workbench 专用构建再次通过 |
| GUI 回归 | 301 个文件通过，4000 项通过、1 项跳过；后续细调另跑受影响的聚焦回归 |
| `make depguard productguard` | 通过，无新增分层违规或独立业务入口 |
| 样式与本地化 | 滚动条样式约束通过；本地化所有权检查通过 |
| 文档 | 3 组中英文档配对一致；653 份 Agent Note 格式检查通过 |
| 通用浏览器 replay | 未通过，不能计作端到端绿灯 |

通用浏览器单场景独立复跑在选择工作区前失败。测试辅助函数仍寻找 `Choose workspace`，Workbench 已使用 `Choose project`，等待 30 秒后超时，未进入本次任务阅读路径；该次退出码为 1。更早的组合运行出现多个超时并被中止，不能把所有失败都归因于同一个原因。这里保留明确缺口，不用组件通过数代替浏览器端到端结果。

## 尚未签署的范围

视觉方面，本轮已检查的成员阅读、成果预览和任务卡片可作为后续精修对照；交互方面，已复现的页签失焦、返回与刷新阅读漂移、文件开合后状态丢失均有修正和对应复验。该结论限于本页列明的路径与样本。

整套 Workbench 的视觉与交互不能据此宣布全部完成。侧栏所有悬停和菜单、完整深色模式、真实连续执行到各类终态、真实鉴权下载、真实表格和图纸运行样本仍需后续验收。真实连续状态与后端恢复不由静态历史页面或隔离组件证明。

本轮没有新增后端业务功能，也没有提交、推送或部署远端服务。当前本地运行使用 Workbench 专用构建，原始审视证据继续保留作为整改前对照。
