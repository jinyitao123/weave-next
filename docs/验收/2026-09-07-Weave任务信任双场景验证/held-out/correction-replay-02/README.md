# 成员级增量纠偏保留样本

本样本验证已完成并行分支上的成员级纠偏是否只重算目标成员和真实下游，同时绑定并保留兄弟成员的逻辑结果与文件产物。它是恢复机制样本，不用于证明广泛业务泛化。

执行协议如下。

1. 派发前冻结 `team-template.yaml`、`task.txt` 和本文件，并记录摘要。
2. 通过当前 Workbench 以团队展示名只派发一次，不补充团队 UUID。
3. 父运行进入并行等待后，只对“数据计算员”提交一次纠偏，要求基于已有 `calculation.md` 增补公式说明并更新版本标记。
4. 系统到达安全点后，先记录其影响计划。只有计划把重启点收窄到数据计算员、把独立复核员列为保留成员时，才确认应用。
5. 不重新派发，不修改团队、任务、合同、生产代码或运行配置，不手工复制旧产物。

通过条件如下。

- 同一 TeamRun 完成纠偏与最终交付，纠偏状态为 `applied`。
- 重启点为数据计算员；受影响范围只含数据计算员、`join`、最终整理员和 `deliver`。
- 独立复核员没有第二次执行，其分支结果、物理来源和 `review.md` 摘要保持不变。
- 数据计算员产生新的物理来源；新 `calculation.md` 含 `formula: refunds / orders` 和 `source-version: corrected`。
- 最终报告通过冻结交付合同，Workbench 分开展示执行、交付核验和用户评价。

任一条件无法证明或发生整组重跑时，本样本即按真实结果失败并停手。
