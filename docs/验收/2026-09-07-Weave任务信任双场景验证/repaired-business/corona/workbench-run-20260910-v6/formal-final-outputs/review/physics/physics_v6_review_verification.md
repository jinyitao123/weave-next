## 3. 数量级与物理解读（复核结论）

| 项 | 结论 |
|---|---|
| **尘埃威胁** | 1 mg 尘埃 0.01c→**1.07 kg**、0.05c→**26.85 kg** TNT 当量。量级真实、物理必要（Whipple 盾 / 规避 / 尘监测），但**通量/密度为 unknown**（U3），不能据此定防护设计 |
| **动能 ≠ 推进预算** | `E=½mv²` 仅为动能下限；真实束功率/能量 = 动能 ÷(束传递效率 × 帆反射/耦合效率)，效率 `unknown`（U1、U2） |
| **P3 束功率 16–400×** | 固定 m、L 时 `P∝v²`：0.01c→400×、0.03c→44.4×、0.05c→16× 降幅。**量级成立**；不含效率修正，且 m、L 因速档而异（U2） |
| **可达域** | S-0.01c 数月到 ~1.6 yr 抵日球层/透镜/1000 AU；S-0.03c 3.5 月到透镜、6.3 月到 1000 AU；S-0.05c 2.1 月到透镜、3.8 月到 1000 AU |
| **星际抵达** | 比邻星 4.25 ly：85/141.7/425 yr，远超单次任务尺度 → 属多代/档案/信标型目标（P2 成立） |
| **相对论** | 修正 0.0075/0.0676/0.1879%（均 <0.2%）；时间膨胀 7.8/23.3/38.8 天（单程）——不影响轨迹数量级，但多代/档案任务的时钟对齐值得登记 |

## 4. 发现的可复现缺陷（只此 1 项）

### 4.1 缺陷描述
v4 冻结 `physics_recompute.py`（[C] 块，第 167–178 行）：
- `e1 = ke_joules(1.0e9, beta)` —— 参数是 **1e9 kg（百万吨级 / 1mt）**；
- 却打印为 `log(f"  E_SAIL_1G    = {e1:.6e} J ...")` —— 标签写作 **`E_SAIL_1G`（1 克帆）**。

1e9 kg 与 1e-3 kg 相差**正好 10¹² 倍**。证据：v4 `physics_recompute_evidence.txt` 第 34 行 `E_SAIL_1G = 4.493776e+21 J`（实为 1e9 kg 的 1mt 值），而同一包内 CSV 列 `E_sail_1g_J=4.493776e+09 J`（真正的 1 克帆）与分析文档 P4「单帆动能 4.5 GJ」均指 **1 克**。

### 4.2 为何判为缺陷（非口径差异）
这是**包内自相矛盾**，不是两个口径并列：
- 分析文档 §0 明确警告：「两张表差约 **10¹² 倍，严禁混用**；引用动能必须带质量基准」；
- v4 的 [B] 产量检查块标签为 `E_SAIL_1G(1mt)`（带了 "(1mt)" 限定），但 [C] 块打印时**丢失该限定**，直接把 1e9-kg 数值标成 「1G」；
- 结果：读 `physics_recompute_evidence.txt` 的人会把 1mt 的 4.49e21 J 当成 1 克帆的动能，与 CSV 的 4.49e9 J 冲突 —— 正是文档亲令禁止的混用错误重复出现。属跨工件一致性（G10）隐患。

### 4.3 处置
- **修**（仅该 1 处标签 + 补 1 行）：新脚本 `physics_recompute_v6_fixed.py` 把 [C] 块该行标签改为 **`E_SAIL_1MT(1e9kg)`**（与其实际计算质量一致），并**新增** `E_SAIL_1G(1g) = … GJ [P4 单帆动能]` 一行；
- 其余**全部复用**：所有公式、常量、锚点、数量级、未知项均未改动；
- **数值零改动**：已用脚本逐字段比对，v4 证据中所有打印数值与 v6 完全一致（唯标签变、新增 1 行）。

> 该修正涉及一次**逻辑结果**而非逻辑错误——是标签错挂导致的量级误导。修正不改变任何物理量真值，只消除一处“把 1e9kg 说成 1g”的可复现误导。
