# Loom 产品边界决策

2026-09-10，v0.5。当前证据下的产品决策已经确定：共用信任机制进入主线，Loom 只保留在已发布的标准串行成员中，继续冻结扩大采用范围。缺少对齐试验时，结论就是不扩大，不根据不完整数据猜测收益。阶段二依原方案停止规则收口，不再用不可比的日冕整组复跑补造收益数字。

电商新隔离样本经过修订运行后已由外部 verifier 复核为 7/7，且用户在 Workbench 中选择采用；这证明受控工作流在该样本上的业务闭环，不证明所有电商任务都可信。日冕 v3 暴露了绿色执行、截断交付、候选应用崩溃和验收角色冒用。v4 的内容硬门槛和真实浏览器复核通过，但没有形成可信的平台交付与用户采用。修复后的 v6 先在一个运行中真实验证持久 fanout 检查点、同一运行身份、精确 stage retry 和新的领取代次；该运行没有形成最终可采用成果。后续第 5 次完整团队修订保存 75 件成果，平台外独立复核通过 G1–G11、真实浏览器三档切换、JSON 导出、本地链接与敏感信息扫描，并在 Workbench 对精确交付版本记录“可以采用”。平台自身仍把 16 项登记检查判为通过，并把“旧成果尚非 Weave 原生跨运行产物绑定”保留为 1 项 unknown。

这组证据证明当前受控边界内能形成可采用的日冕候选，也证明检查点与精确阶段重试机制可审计。它没有证明一次运行从中断自动恢复到采用，没有证明带副作用恢复不会重复，也没有提供对齐 A/B/C 的收益数据。依据见[电商运行证据](repaired-business/invoice/weave-run-evidence.json)、[电商外部复核](repaired-business/invoice/final-verification.json)、[日冕 v6 记录](repaired-business/corona/workbench-run-20260910-v6/README.md)、[日冕最终独立复核](repaired-business/corona/workbench-run-20260910-v6/r5-independent-verification/summary.json)和[日冕精确版本采用](repaired-business/corona/workbench-run-20260910-v6/r5-workbench-assessment.json)。

## 当前采用范围

| 能力 | 当前决定 | 依据与限制 |
|---|---|---|
| 现有 CLI/Runtime 执行路径 A | 保留在已说明限制的受控任务中 | 电商闭环证明一个固定工作流可用；保留不等于已证明所有业务可信 |
| 共用契约、输入、回执与交付核验 B | 纳入产品主线 | 输入原文由 Host 冻结并绑定派发身份；发布工具合同、任务领取权和最终参数由服务端校验；文件、外部对象与业务条件继续由独立核验判断 |
| Loom 成员工具循环和已确认操作恢复 C | 仅允许已发布的标准串行成员使用 | PostgreSQL 复核证明累计预算、预算暂停、授权续跑和已确认操作不重复；自动续跑只以新文件导出等结构化进展为依据 |
| 让 Loom 决定业务成果是否可接受 | 不纳入 Loom 职责 | 引擎报告执行和恢复事实；业务条件、专业质量与用户采用属于 Weave 的任务契约和业务主体 |
| 并行图、交互权限、更多运行时和跨主机恢复 | 冻结 | 当前证据不足以说明这些扩张会降低用户返工或保持副作用边界 |

共用信任机制的收益不得计入 Loom 独有收益。受管工具参数校验和 CLI 发布绑定同样服务于普通 CLI/Runtime 路径。

## A/B/C 对照结论

当前没有满足原方案对齐条件的 A/B/C 对照组。CLI 样本与 Loom 路径的模型、工具约束、输入、交付条件和故障点未完全一致；历史恢复样本也没有足够的实际成本与人工时间记录。不得给候选排序，不得从不可比运行计算采用收益。

| 原方案判据 | 当前证据 | 结论 |
|---|---|---|
| A 是否已满足用户信任条件 | 电商一个新隔离样本闭环；日冕最终修订形成独立内容通过和精确版本采用，但平台仍保留一项跨运行绑定 unknown | 两个冻结样本内满足，不能泛化 |
| B 是否获得至少 80% 的 C 恢复收益，且成本更低 | 缺对齐后的 B/C 中断样本与实际成本记录 | 未证明 |
| C 恢复中位时间比 B 至少快 30% | 缺可比较的恢复时点与足够样本 | 未证明 |
| C 正常任务耗时与 token 增长分别不超过 15% | 输入、模型和任务量尚未对齐 | 未证明 |
| 无新增正确性、重复副作用或误报交付缺陷 | PostgreSQL 中确认操作恢复与未知副作用停机检查通过；日冕最终候选的内容和用户采用闭环，但中断运行没有走到最终采用，且当前合同没有外部副作用 | 不满足扩大采用条件 |

原始 benchmark 分数继续单独保存。新增参数校验、写入核对或交付验证后，应登记新的实验条件，不能覆盖先前失败，也不能把共用保护的收益归给 Loom。

## 已确定的准入线

Loom 路径只有同时满足以下条件才可进入普通任务：成员来自已发布工作流；拓扑是标准串行叶子；工具来自冻结的受管 MCP 清单；每次调用先通过冻结参数合同和当前任务领取权；预算上限随发布物固定；暂停、授权和累计用量持久化；交付仍经过 Weave 独立核验和用户采用。任一条件不满足，回到普通 CLI/Runtime 路径或停止任务，不临时放宽。

目前不准入并行 Loom 成员、交互权限、跨主机恢复、任意网络或文件系统隔离声明，以及让 Loom 判定业务成果合格。将来只有同一输入、模型、工具、交付门和故障点下完成 A/B/C 对照，并达到既定 80%、30% 和 15% 阈值，才重新审议扩大范围。

## 后续主线

输入绑定、工具合同、CLI 发布绑定、任务领取权、结构化停止和连续预算均已实现并完成 PostgreSQL 复核；对应记录见[工具合同复核](tool-contracts/mechanism-verification.json)和[成员预算复核](member-budget/mechanism-verification.json)。日冕 v6 又证明了持久检查点、精确阶段重试和完整可采用候选，也暴露出已完成运行不能成员级纠偏、跨运行产物仍靠只读路径和哈希清单、普通故障不能自动恢复到最终采用，以及平台 unknown 仍需人工外部核验等边界。

下一条产品主线是 Weave 原生跨运行产物绑定和完成后成员级纠偏，使冻结产物与精确变更范围成为正式运行输入，只重跑真实受影响成员。该主线开始前，不继续用全量重建反复跑同一日冕样本，也不为 Loom 扩张补做不可比试验。机制回归只证明对应机制，不能替代完整业务交付。

最终出口和保留缺口以 [completion-audit.json](completion-audit.json) 为准。本决策将阶段二按停止规则关闭，没有把缺少对齐数据的能力改判为通过；以后只有新增证据满足明确触发条件时才重开扩大范围的讨论。
