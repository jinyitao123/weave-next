# Loom 产品边界决策

2026-09-09，v0.4。当前证据下的产品决策已经确定：共用信任机制进入主线，Loom 只保留在已发布的标准串行成员中，继续冻结扩大采用范围。缺少对齐试验时，结论就是不扩大，不根据不完整数据猜测收益。

电商新隔离样本经过修订运行后已由外部 verifier 复核为 7/7，且用户在 Workbench 中选择采用；这证明受控工作流在该样本上的业务闭环，不证明所有电商任务都可信。日冕 v3 暴露了绿色执行、截断交付、候选应用崩溃和验收角色冒用。随后派发的 v4 由两个运行环境真实协作，独立总装和外部复跑均支持内容硬门槛 11/11，真实浏览器能够切换三个速度并导出有效 JSON；但平台交付核验仍为 unknown，旧产物没有作为正式输入绑定，数字成果被完整重建，成员级纠偏会扩大成整组重跑，最终报告还扩大了未实际发生的恢复事实，用户也尚未采用。因此 v4 证明“完整重建可以形成可用候选结果”，没有证明可信的增量恢复、平台交付闭环或泛化能力。依据见[电商运行证据](repaired-business/invoice/weave-run-evidence.json)、[电商外部复核](repaired-business/invoice/final-verification.json)、[日冕 v3 运行证据](repaired-business/corona/workbench-run-20260909/run-evidence.json)、[日冕 v3 外部复核](repaired-business/corona/workbench-run-20260909/external-verification.json)、[日冕 v4 运行证据](repaired-business/corona/workbench-run-20260909/v4-run-evidence.json)、[日冕 v4 外部复核](repaired-business/corona/workbench-run-20260909/v4-external-verification.json)和[深度审视记录](repaired-business/corona/workbench-run-20260909/deep-review-20260909.md)。

## 当前采用范围

| 能力 | 当前决定 | 依据与限制 |
|---|---|---|
| 现有 CLI/Runtime 执行路径 A | 保留在已说明限制的受控任务中 | 电商闭环证明一个固定工作流可用；保留不等于已证明所有业务可信 |
| 共用契约、输入、回执与交付核验 B | 纳入产品主线 | 输入原文由 Host 冻结并绑定派发身份；发布工具合同、任务领取权和最终参数由服务端校验；文件、外部对象与业务条件继续由独立核验判断 |
| Loom 成员工具循环和已确认操作恢复 C | 仅允许已发布的标准串行成员使用 | PostgreSQL 复核证明累计预算、预算暂停、授权续跑和已确认操作不重复；自动续跑只以新文件导出等结构化进展为依据 |
| 让 Loom 决定业务成果是否可接受 | 不纳入 Loom 职责 | 引擎报告执行和恢复事实；业务条件、专业质量与用户采用属于 Weave 的任务契约和业务主体 |
| 并行图、交互权限、更多运行时和跨主机恢复 | 冻结 | 当前证据不足以说明这些扩张会降低用户返工或保持副作用边界 |

共用信任机制的收益不得计入 Loom 独有收益。受管工具参数校验和 CLI 发布绑定同样服务于普通 CLI/Runtime 路径。

## A/B/C 对照结论

当前没有满足原方案对齐条件的 A/B/C 对照组。CLI 样本与 Loom 路径的模型、工具约束、输入、交付条件和故障点未完全一致；历史恢复样本也没有足够的实际成本与人工时间记录。不得给候选排序，不得从不可比运行计算采用收益。

| 原方案判据 | 当前证据 | 结论 |
|---|---|---|
| A 是否已满足用户信任条件 | 电商一个新隔离样本闭环；日冕 v4 内容门槛通过，但平台交付、增量恢复和用户采用未闭环 | 仅局部证明 |
| B 是否获得至少 80% 的 C 恢复收益，且成本更低 | 缺对齐后的 B/C 中断样本与实际成本记录 | 未证明 |
| C 恢复中位时间比 B 至少快 30% | 缺可比较的恢复时点与足够样本 | 未证明 |
| C 正常任务耗时与 token 增长分别不超过 15% | 输入、模型和任务量尚未对齐 | 未证明 |
| 无新增正确性、重复副作用或误报交付缺陷 | PostgreSQL 中确认操作恢复与未知副作用停机检查通过；日冕 v3 出现绿色执行和错误交付，v4 仍有 unknown 交付、全量重建和未实证恢复被写成通过 | 不满足扩大采用条件 |

原始 benchmark 分数继续单独保存。新增参数校验、写入核对或交付验证后，应登记新的实验条件，不能覆盖先前失败，也不能把共用保护的收益归给 Loom。

## 已确定的准入线

Loom 路径只有同时满足以下条件才可进入普通任务：成员来自已发布工作流；拓扑是标准串行叶子；工具来自冻结的受管 MCP 清单；每次调用先通过冻结参数合同和当前任务领取权；预算上限随发布物固定；暂停、授权和累计用量持久化；交付仍经过 Weave 独立核验和用户采用。任一条件不满足，回到普通 CLI/Runtime 路径或停止任务，不临时放宽。

目前不准入并行 Loom 成员、交互权限、跨主机恢复、任意网络或文件系统隔离声明，以及让 Loom 判定业务成果合格。将来只有同一输入、模型、工具、交付门和故障点下完成 A/B/C 对照，并达到既定 80%、30% 和 15% 阈值，才重新审议扩大范围。

## 后续主线

输入绑定、工具合同、CLI 发布绑定、任务领取权、结构化停止和连续预算均已实现并完成 PostgreSQL 复核；对应记录见[工具合同复核](tool-contracts/mechanism-verification.json)和[成员预算复核](member-budget/mechanism-verification.json)。日冕 v4 已完成双运行环境执行、独立总装和外部内容复核，也暴露出恢复任务路由错误、旧产物未绑定、成员纠偏范围过大、Workbench 决定回执不可靠、交付合同缺失和最终报告扩大过程结论等问题。下一条产品主线是让恢复任务携带冻结产物和变更范围，按真实依赖只重跑受影响成员，并把用户确认范围固化为逐条可核验的交付合同；在这条主线完成前，不继续用全量重建反复跑同一日冕样本。机制回归只证明对应机制，不能替代完整业务交付。

当前待完成项以 [completion-audit.json](completion-audit.json) 为准。本决策不将未完成的日冕阶段改为通过，也不取消真实 Workbench 样本、中断接续和用户证据的要求。
