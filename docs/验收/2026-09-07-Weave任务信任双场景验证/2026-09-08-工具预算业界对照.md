# 工具预算的价值与业界对照

核验日期：2026-09-08。以下区分官方接口设计、本项目实测和建议；没有据此修改运行代码。

工具轮数上限适合限制异常循环，并给调度器一个可以收回控制权的边界。它不能精确表示成本、实际副作用次数或业务进展。一轮可能包含多个工具调用，不同工具的时间与输出量也不同。判断任务完成仍需独立的交付契约。

## 官方设计

| 实现 | 限制方式 | 耗尽处理 |
|---|---|---|
| Claude Agent SDK | max_turns 与 max_budget_usd，文档默认均不设上限 | 区分 error_max_turns、error_max_budget_usd 与 success，并保留 session_id 供接续 |
| LangGraph | recursion_limit 限制图的 super-steps；不能直接当作工具次数 | 超限抛 GraphRecursionError；可用 RemainingSteps 提前转入保存状态、返回部分结果的分支 |
| Vercel AI SDK | ToolLoopAgent 文档默认 stepCountIs(20)，支持组合和自定义 stopWhen | 命中条件结束循环；应用仍须决定结果是否满足业务验收 |
| Claude Managed Agents | 可配置会话费用上限 | 到限后暂停并记录 budget_reached；在模型请求之间检查，最后一次请求可能使费用略超阈值 |

## 对 Weave 的建议

保留可配置的保护上限，但不以固定 20 轮作为长任务的整体交付期限。把局部调度轮次和全任务费用、时长、重试额度分开。任务仍在取得可验证进展、全局预算仍有余量时，可以由调度器保存状态后继续；无进展或反复失败时提前停下诊断。不能通过不断重启局部循环清零全局预算。

达到保护上限时必须记录明确的停止原因、已确认效果、剩余工作和接续身份。可以生成供用户查看的总结，但缺少交付时不能仅凭总结调用成功就把业务标记为通过。只改 20 为 200 会移动停止点，不能解决这些语义问题。

阈值应按任务族的成功样本、耗尽比例、停滞行为、总成本和用户返工选取。当前两个场景的样本不足，不指定具有统计含义的“最佳轮数”。下一步验证应包含复杂任务持续推进、重复失败能停止、耗尽后可接续，以及未完成不会误报业务通过。
