## 每项实际运行记录

每完成一项，把下列记录复制到本文末尾。若题目不适用，可以用同等真实工作替换并写明原因，不能用造出的材料凑数。

| 记录项 | 待填写内容 |
|---|---|
| 任务编号、日期、用户 | 真实提出任务的人与本次工作目的 |
| 输入与团队 | 材料位置、所选团队、是否选对及原因 |
| 入口与版本 | Workbench 与 Weave 的实际版本 |
| 任务身份与成果 | 同一任务的运行标识、最终成果位置；不记录凭据 |
| 时间与用量 | 发起时间、首次有效产出耗时、总耗时、可取得的模型用量；未知写未知 |
| 人工介入 | 确认或纠偏次数、处理的具体问题 |
| 中断与恢复 | 原因是否看懂、采用的操作、恢复次数、已保存成果是否保留；未遇到写未发生 |
| 最终结果 | 完成、失败或停止，以及能否打开属于本次任务的成果 |
| 用户采用 | 采用、修改后采用或未采用，并记录用户给出的原因 |
| 再次使用 | 用户是否愿意继续，以及是否实际提交下一项工作；两者分别记录 |
| 待修问题 | 问题描述、复现材料、负责人及处理状态 |

## 配套恢复验收

在隔离试点环境另外验证以下情况，记录版本、操作、任务标识与结果。它们不增加真实业务任务数量，未执行的项目保持未勾选。

- [ ] Workbench 首次使用只需选团队、确认任务、查看执行和领取成果。
- [ ] Workbench 主对话发起的任务可持续按同一任务标识查询并领取成果。
- [ ] 任务等待人工输入时，问题清楚；答复后继续同一任务。
- [ ] 一个支持重试的阶段失败后，能说明重做范围，重试后保留不受影响的成果。
- [ ] 不支持重试的失败有明确原因与维护处理指引。
- [ ] 运行机器暂时离线时显示等待或故障，恢复后不重复创建任务。
- [ ] 停止任务时区分停止中与已停止，并可查看已保存的工作。
- [ ] 关闭页面再打开、重启 Workbench 后，任务身份与已保存成果不丢失。
- [ ] 最终成果不可读或不属于本次任务时，不把它当作成功交付。

## 一轮结束后如何判断

完成 20 项记录后汇总成果采用情况、首次有效产出耗时、恢复成败和再次使用情况。恢复成功率只统计实际遇到且支持恢复的情况，同时单列不能恢复的原因；没有数据不写成零故障。

下一轮先处理反复导致成果无用、任务无法继续或用户不愿再用的问题。公开发布仍按设计伙伴发布基线另行验收，不能仅凭完成 20 次运行认定已经可用。
