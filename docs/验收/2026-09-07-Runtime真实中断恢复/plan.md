# 真实 Runtime 中断恢复验收登记

2026-09-07。三个真实模型运行前登记。目标是确定现有成员执行链路在哪种故障下丢失有效工作，以及是否需要最小补丁；不进行 A/B/C 性能排名。

## 任务与输入

复跑历史 `digital-engineering-builder` 的完整成员工作：统一模型、至少三张 SVG、OpenSCAD 概念模型、可交互并导出 JSON 的离线应用、机器验证清单。保留该历史节点实际批准的单一 `0.03c`、baseline `1.0.0`，不冒充整个日冕团队的最终验收。

原成员提示词和四份上游文本从历史执行载荷提取，上游 SHA-256 逐项一致。四份原始参考文件从目前保留的源文件冻结，不能证明与历史运行时逐字一致；三轮均用本次相同快照。原绝对路径改为 `inputs/reference/`，上游通知由当前 Executor 生成。原始文本、改写文本、差异说明和哈希见 inputs/manifest.json。

不提供旧模型实现、预写修复工具或标准答案补丁。模型使用当前 Claude CLI 的原生文件和命令工具，系统身份沿用原成员。新增统一机器清单契约仅规定交付结构，所有运行使用相同内容。

## 执行链路和边界

驱动器直接调用当前 `runtimes.Executor.ExecRemote`，使用冻结成员记录、稳定 logical invocation、schema-v2 task identity 和上游完成回执。HTTP 服务使用当前 `api.NewServer` 的真实 Runtime 注册、领取、续租、完成、事件接口；执行端启动当前 `weave runtime` 二进制及真实 Claude CLI。PostgreSQL、工作目录、Runtime token 全部隔离。

本轮入口是成员级验收驱动器，代替整队工作流入口；没有验证 Workbench 自助恢复或整队调度。服务保留成员任务的 60 秒租约、30 秒过期巡检、Runtime 20 秒续租/30 秒心跳、完成 spool、公有事件和原 Executor 接回语义。未启用业务工作流自动调度器，驱动器只调度本次冻结成员。此边界必须出现在结论中。

上游回执和父运行由试验初始化导入，明确为夹具，不算本轮模型执行。每轮独立 snapshot、invocation、工作目录；重启同一轮保留原身份与全部目录。禁止删除 A 的已有状态。候选 B/C 尚不存在。

## 三组运行与故障位置

固定顺序为 N 正常、C 协调进程中断、M 成员进程中断；先验证 N 能交付，避免重复消耗在不可用输入上。这是定性故障验收，不作随机性能对照。

共同里程碑：观察到原生 Bash 工具执行模型测试（命令包含 unittest/pytest 或明确的模型测试入口）并返回成功，且 outputs/model 至少已有两份非空源码文件、模型/图纸/应用全量交付尚未结束。保存关联 tool call/result 和全目录文件哈希。若无法可靠识别里程碑，记未注入，不强行用秒数代替；登记新的触发条件后另开批次。

- N：记录里程碑，继续到成员终态。
- C：里程碑后 SIGKILL 本轮协调驱动器和 API 服务，Runtime 及其 CLI 保持运行；10 秒后启动新 API 进程和新驱动器，以同一 invocation 接回，不新建尝试。
- M：里程碑后 SIGKILL 本轮 CLI 进程组，Runtime 与 API 保持运行，观察是否保留文件、回传失败、发生自动重派。收到终态后以同一 invocation 再接回一次，验证不会隐式新建工作。需要新尝试时，单独登记显式恢复动作，不能冒充自动续跑。

每轮上限使用现有 45 分钟执行预算；恢复后不延长同一物理 CLI 的原预算。未达注入点的自然失败保留，不能替换成好看的轮次。N 失败时先分清任务质量、环境和基础设施错误，若需改公共输入则所有场景重新登记版本，不隐瞒失败。

## 核验和度量

分别判定引擎退出、文件交付、独立内容验收、恢复行为。引擎 completed 不能自动算交付正确。

交付要求：模型源码和有界测试入口、冻结基线哈希一致、至少三份可解析 SVG 并标明概念级、OpenSCAD 源码及可执行验证或明确 NOT_RUN、无需常驻开发服务的离线应用、真实操作与 JSON 导出、机器清单含完整追溯键。五个参考计算用独立高精度/标准公式复核；模型测试真实运行，图纸解析和应用行为单独检查。不强制新实现沿用旧实现的 38 项测试接口，也不把模型自己声称通过当证据。

故障表记录：进程和进程组、task/invocation 身份、事件序号、故障时已落盘文件哈希、重启后同一文件保留情况、实际新建物理调用数、CLI 会话身份、恢复前后公有工具事件、最终回执、输出文件、停止原因。重复同名工具不直接记作浪费；只把可证明已完成且再次执行的逻辑工作计入返工。最终模型计费回执缺失则标未知，不能用最后一次消息 token 伪装整段费用。

人工计时从本登记起分块记录：公共设施、任务冻结、核验、缺陷修复、等待分别说明；前期探索时间无法精确还原，标未知。无计费价格不算金额，不从三个注入场景推算生产发生率。

## 决策出口

- C 能接回同一任务，说明该故障无需新恢复框架；不把保留的同一 CLI 工作算成 Loom 潜在收益。
- M 正确终止且保留失败产物，只说明失去的是运行中上下文还是文件接续入口，分别记录；不要求不确定副作用盲重放。
- 若现有恢复满足需求则停止；若存在具体缺口，优先复用现有回执与阶段/产物接续，补丁要证明自身减少了哪项重做。
- 只有多个真实任务证明最小补丁需要反复编写复杂恢复机制，才重启 Loom 增量价值试验。

服务与测试数据仅属于本次实验。保留证据后停止自建进程，删除无用临时文件；原业务数据库、服务、文件不受影响。
