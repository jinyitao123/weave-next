# Loom 采用价值验证

2026-09-07，Asia/Shanghai。状态：**正式 batch-02 的 18 轮真实模型对照执行中**。batch-01 因 T2 夹具工具错误停止并作废，原因和修复见 [决策记录](decision-log.md)。

本验证不预设 Loom 胜出。决策问题是：对真实存在的长成员任务，Loom 相比现有执行方式和最小恢复补丁，能否提供足够的增量收益，抵消正常运行开销与工程复杂度。

采用门槛、停止规则和 18/54 轮设计已在运行前写入 [验证计划](../../计划/2026-09-07-Loom采用价值验证计划.md)。本目录记录实际执行，计划没有因观察到的结果而修改。

## 比对任务

### T1：日冕三速度复算

控制样本。读取冻结的 `corona-prephase-a-v1`，按质量 `1e9 kg`、距离 `4.25 ly`、速度 `0.01c / 0.03c / 0.05c` 计算经典动能和匀速巡航时间，再用独立公式验证。输入、工具结果和最终文件都可机器核对。

T1 的作用是检查工具回执、检查点、崩溃位置和数值正确性，不承担业务收益外推。

### T2：数字工程模型修复

主要业务样本，来自 2026-09-06 日冕完整运行中的 `digital-engineering-builder`。原成员任务实际持续 `1549.1 s` 和 `1395.7 s`，分别产生 `76` 和 `73` 次工具请求。原始事件记录包含三个真实问题：

1. Lorentz gamma 测试使用精度不足的硬编码期望值。
2. macOS 没有 GNU `timeout` 命令。
3. 验证命令从错误相对目录再次进入 `outputs/model`。

本轮冻结为一个较小、可重复的真实修复任务：检查原文件、应用三项登记修复、运行完整验收、生成机器清单。减少的是原任务中与恢复价值无关的图纸和应用文件数量，没有加入等待或无意义计算来放大收益。

来源任务为 `task-3b0014b553bdaa5746c6a708d5c75ecd` 与 `task-d83fea8e5aa82eca0097753a0869ae03`；筛选事件见 [T2 来源事件](evidence/t2-source-events.csv)。

### T3：验证集成复核

保留的泛化样本，首批不运行。若 C 达到继续资格，将使用未参与原型调试的 `verification-integrator` 任务，核对一组已有数字工程产物、执行检查并生成验收矩阵。历史任务最长 `965.7 s`、`94` 次工具请求，适合检验通用恢复机制是否真的减少第二个任务的接入成本。

## 三个候选

| 候选 | 本轮实现 |
|---|---|
| A | 同一 Runtime LLM 和工具循环；成员进程崩溃后从冻结输入创建新工作目录并从头运行。保留当前“新成员尝试”的基线语义。 |
| B | 在 A 上加入 JSON 状态、待调用操作身份和工具回执账本；恢复仍使用普通循环，没有图引擎或历史分支。 |
| C | 使用 Loom v0.8.1 的 PostgreSQL 检查点保存同一循环状态；每次推理和每个工具回执后形成 `after_step` 位置。 |

B/C 共用完全相同的工具回执账本。工具效果完成而响应丢失时，它们都以保存的 `operation-NNNN` 查询原回执。该收益属于共同基础；只有 C 相对 B 的差异才归因于 Loom。

三组都使用当前 `runtimellm` 和本机 Claude CLI `2.1.245` 承接一次模型响应。CLI 原生工具调用会被探针取消并判失败；文件、计算、测试和修复工具全部由同一探针实现。

## 场景

| 场景 | 故障位置 |
|---|---|
| S0 | 无故障，测正常开销和正确性。 |
| S1 | 关键工具效果已经提交并写入回执账本，回执尚未并入成员循环时进程退出，退出码 `86`。 |
| S2 | 关键工具回执已经并入候选状态并保存后进程退出，退出码 `86`。 |

T1 的关键工具是 `calculate_scenarios`；T2 是第一次 `apply_repair`。故障由工具事件触发，不按固定秒数触发。恢复一定使用新 PID；A 使用新工作目录，B/C 沿用保存的工作目录和状态。

首批为 `2 tasks × 3 candidates × 3 scenarios = 18` 轮，每格一次。正式运行顺序使用固定随机种子 `20260907` 写入 `evidence/batch-02/order.json`。出现候选失败也保留，不补跑替换；实验设施错误按决策记录单独处理。

## 历史需求审计

数据库按最近 30 天查询，但当前可访问记录只覆盖 2026-09-05 至 2026-09-06。共有 37 个 `engine_exec` 成员任务：34 完成、2 失败、1 取消。20 个审计样本由全部 3 个非完成任务和按时间倒序的 17 个完成任务组成，规则在读取结果前确定。

两次失败均为 `runtime offline: execution lease expired`，持续约 `122.9 s` 与 `125.0 s`。现有日志无法关联它们随后是否重做、重做了什么，返工量记为未知。取消任务持续约 `1540.3 s`，取消原因也不足以归因于恢复缺口。

因此当前只能确认“有真实基础设施中断”和“存在 20 分钟级工具密集成员任务”，还不能从历史数据算出生产返工率或月度节省。故障注入结果用于比较候选机制，不能替代真实故障发生率。

## 当前边界

本轮测量完整候选路径，不冒充对 Loom 库的纯微基准。A 是当前执行语义的受控复现，并非通过 Workbench 发布的完整产品运行；C 也尚未补齐产品工具冻结。若 C 胜出，仍需 T3 和真实产品路径验收。

历史分支、整支团队迁移、跨主机工作目录转移不在首批范围内。首批结束后按预先门槛决定停止、采用 B、继续 C，或判定证据不足。
