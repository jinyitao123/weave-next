# Loom 采用价值验证记录

2026-09-07，Asia/Shanghai。**本轮按对照有效性和正确性门槛停止，结论为证据不足，保留现有路径 A。没有证据支持采用 Loom，也没有证据足以认定 B 已经胜出。**

已实际执行候选探针、真实模型调用、进程退出与恢复、当前 Runtime 恢复测试、独立数值核验和历史任务夹具复核。计划首批 18 轮，batch-02 实际启动 6 轮，其中 5 轮完成、1 轮中断且结果未知、12 轮未启动。**18 轮没有完成；54 轮、T3 和产品接入没有启动。** 前一批 batch-01 因夹具错误作废，全部证据保留。

停止依据为原[验证计划](../../计划/2026-09-07-Loom采用价值验证计划.md)第四、六节的有效性与正确性门槛。不是观察到某一候选更慢就停止，而是续跑前审计发现基线、任务和机制前置验证均不满足原计划。继续增加模型次数无法修复这些问题。

## 候选实现与计划的偏差

| 候选 | 探针实际实现 | 对采用比较的影响 |
|---|---|---|
| A | 自编工具循环；新进程丢弃循环状态，运行器归档工作目录后重新复制初始夹具 | 未走当前 CLI/Runtime 完整执行路径，主动丢弃了真实路径可能利用的结果；不能称为现有产品基线 |
| B | 同一循环，加 JSON 待调用状态和逐工具回执账本 | 未复用现有任务调度/阶段恢复；还不能称为可交付的“最小产品补丁” |
| C | Loom v0.8.1，PostgreSQL 保存相同循环状态，每次推理/工具完成后 `after_step` | 仅证明受控内核路径；没有产品工具冻结、成员身份与 Workbench 恢复验收 |

三组使用同一 `runtimellm` 与本机 Claude CLI `2.1.245` 取得单次模型响应；原生 CLI 工具被禁止，改用探针提供的工具。实际回执报告的模型标识包含 `k3`/`k3[1m]`，见逐次 `inference-*.json`；同名配置不证明提供方底层模型版本严格固定。三组工具条件相同，有利于机制比较，但不能弥补 A 不是原定产品路径的缺口。

B/C 共用回执账本。S1 在**工具效果和账本均已写入、但回执未并入循环**时退出；并未覆盖效果已生效、账本尚未落盘的更早窗口。S2 在工具结果并入候选状态后退出。B 使用文件 rename，没有 fsync；C 使用 PostgreSQL，持久性等级也未完全对齐。两组共用的收益不能归因于 Loom。

原计划要求先执行 B/C 各四类故障窗口、每格三次的无模型测试，**实际未完成此前置矩阵**。双恢复者所有权、旧进程迟到、团队只接收一次、外部工具独立存活及预算恢复没有获得完整证据。

## 当前产品恢复能力的复核

代码检查表明，现有 A 已具备以下能力：Runtime 写入持久化完成回执并重报；重启后回放回执而不重新启动 CLI；调度器按物理调用身份接回；对已可能接收的调用，不因断线直接盲重试。

本次在当前提交 `5cbc3eb35c3f12a1818d4f813c372e17287ed118` 执行了 6 项现有恢复测试，全部通过：

| 测试 | 核验内容 |
|---|---|
| `TestRuntimeRecoveryWaitsForProcessExitBeforeAcknowledgement` | 确认进程退出后才能确认恢复 |
| `TestRuntimeRecoveryLostCompletionResponseDoesNotExecuteAgain` | 完成响应丢失后不重复执行 |
| `TestRestartReplaysDurableResultWithoutExecutingCLI` | 新守护对象回放持久化结果 |
| `TestRuntimePoolDoesNotReplayWorkAfterDisconnectedInvocationRealPG` | 已接收的物理调用断线后不自动重做 |
| `TestSchedulerRestartReattachesCompletedPhysicalInvocationRealPG` | 调度器重建后接回已完成调用 |
| `TestRuntimeRetryRequiresNoPossiblyAdmittedInvocation` | 自动重试的准入条件 |

两项名称带 `RealPG` 的集成测试使用显式 `TEST_DATABASE_URL` 和临时隔离 schema，实际运行而非跳过。其余为受控服务、假引擎或重建对象的测试；不能扩大为所有进程故障或已部署产品都验证通过。见[完整测试输出](evidence/current-runtime-recovery-tests.jsonl)。

代码入口为 `internal/app/daemon/result_spool.go`、`internal/app/daemon/daemon.go`、`internal/kernel/runtimes/exec.go`，对应测试在相邻目录。它们证明“现有路径完全没有恢复”不成立；并未证明工具循环中途进程死亡后的所有进度都能保留。

## 探针正确性审计

新增[回执身份冲突复现](probe/receipt_audit_test.go)，不调用模型。在 B/C 共用工具宿主上各执行两种冲突：同一 `operation-0001` 改工具名，以及改参数。四种情况均错误返回旧的成功回执；测试实际退出码为 1，见[失败输出](evidence/probe-receipt-identity-tests.jsonl)。

这是**B/C 实验公共基础设施缺陷**，不是对 Loom 存储库的失败判定。它证明现有探针尚未通过错误复用回执的安全门槛。顺序编号修复降低了已观察的重启碰撞，但没有取代工具名、规范化参数和任务身份绑定。当前探针源码保持原状便于复现，没有用事后修复覆盖已运行版本。

## 需求、成本和实验纪律

可访问数据库覆盖 2026-09-05 至 09-06，虽查询最近 30 天，并没有完整 30 天观测。37 个成员任务包含 34 完成、2 失败、1 取消。失败均为 Runtime 租约超时，但无法关联随后返工；取消原因也不足以归因于恢复问题。真实返工次数、月节省与生产故障率均未知。

最终历史清单为 17 个最新完成任务加全部 3 个非完成任务。**这项规则是在先读到 20 个完成记录后调整的**，偏离原计划的简单时间倒序取样。原 README 的“读取结果前确定”不成立。该清单可说明存在长任务和基础设施故障，不能当作无偏发生率样本。

其余偏差也纳入[决策记录](decision-log.md)：整批 18 格随机打乱未按任务/场景配对分块；`prebatch-input-manifest.json` 实际生成晚于 batch-02 开始，不能充当事前冻结证明；早期清单含 Python 缓存文件；原报告把 A/T2 的等价性和验证独立性说得过满。原材料保存在 [审计前 README](evidence/README-before-validity-audit.md) 和[审计前探针归档](evidence/probe-before-audit.tar.gz)，不抹去偏差。

batch-02 已记录 29 次完成模型响应、累计输入 token 745647、输出 token 5005。只包括有完成回执的请求，未包含无法识别的未完成请求成本；batch-01 和预检另有消耗，不应冒充全项目总成本。无可核对价格，未计算金额。

## 收口与重新开跑的条件

本轮选择**保留 A，采用证据不足，停止扩跑**。这不等同于判定现有 A 已满足全部恢复需求，也不等同于否定 Loom 技术能力。

新的正式对照必须先满足以下条件，不能接着把本批剩余 12 格跑完后称为原计划完成：

1. A 使用真实 Runtime 路径，保留结果重报、调用接回和已有目录/产物能力；B 是该路径上可说明成本的最小补丁。共同工具若无法对齐，明确停止严格性能比较。
2. 锁定有实际工作量的真实 T2 和独立验收，允许模型自行诊断与生成修复，不由工具提供答案；重建 38 项测试夹具可作为输入候选，仍需先锁定工作范围与代表性。
3. B/C 共用基础绑定完整操作身份，先通过四类故障窗口各三次、并发接管、晚到结果、预算与不确定效果处理，再开展真实模型运行。
4. 运行前写入不可变版本、输入哈希、配对顺序、指标定义和人工成本记录，重新登记批次，不合并本批无效数据计算 80%/30%/15% 门槛。

所有逐次模型回执、工具账本、PID、故障标记、产物和失败留存在本目录。三次相关 Loom run 的 23 条存储记录已[导出](evidence/loom-checkpoint-snapshot.json)，数据库原记录保留。预检目录已压缩归档并逐文件核对 SHA-256，本轮无用临时目录和二进制已清理，见[清理清单](evidence/cleanup-manifest.json)。没有停止或修改其他任务的服务。

最终检查见[验证状态](evidence/final-verification-status.json)。依赖与产品边界检查通过；本次未改产品源码，因此未重复运行全仓库或 Workbench 测试。
