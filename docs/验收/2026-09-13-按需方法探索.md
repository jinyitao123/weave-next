# 按需方法探索验收

日期：2026-09-13。范围：纠正团队与能力创建指导中过度插入方法探索的问题。

## 规则

已知输入、流程、工具和验收口径的任务直接执行。只有具体未知阻止选择可执行路径时，才在该部分安排有证据要求、尝试上限和停止条件的探索。外部接口、权限要求和副作用风险本身不触发探索。输入错误、缺少权限和临时故障分别校验、请求补充权限或有限重试。遵守禁止联网、禁止研究等约束，不改写已发布流程。

选择发生在生成方案时，不增加通用分类模型调用或分类阶段。混合任务允许已知的独立分支直接执行，已验证方法可复用。

通过本机 Workbench 正常页面输入、提交、查看成果，使用真实模型。

## 检查与限制

`make test depguard productguard`、`make workbench-install`、`make workbench-check` 均通过。Workbench 包含构建、1项启动检查和32个测试文件中的407项测试。模型可见规则的现有快照已更新。

本次修改是模型指导，不是运行时强制分类或自动回退机制。结构化团队创建仍为负责人→并行成员→汇总；角色名称和指令不产生顺序依赖、人工暂停或返回循环。实际控制需要受支持的自定义图。自动复核不等于真人审批。

固定金额任务的交付核验页面仍显示“尚无法确认”，本记录仅确认实际正文金额正确及没有额外研究阶段，不代表通用交付核验问题已解决。抖音内容获取、自动回退、多用户隔离及生产环境全量验收不由本次样本证明。
