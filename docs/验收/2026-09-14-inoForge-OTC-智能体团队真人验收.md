# inoForge OTC 智能体团队真人验收

更新于 2026-09-15。

## 验收目的

用户只在 Workbench 中用几句日常语言提出一笔柜机交付需求。Workbench 应自己理解 inoForge 当前能够办理的业务，自己判断是否调用 Weave、是否需要建队、团队需要多少人和怎样分工，并让团队在 inoForge 中完成一笔从接单到收款结项的连续业务。

验收判断业务是否真正完成，不以团队创建成功、运行状态完成、模型声称完成或生成总结文档代替系统中的正式业务结果。

## 测试角色

测试者只扮演一个不熟悉软件和 OTC 模块划分的业务用户。测试者知道客户、产品、合同金额、内部预算和期望交期，不知道系统页面、对象、状态机、团队结构、工具名称和恢复方法。

测试过程中禁止测试者：

- 告诉 Workbench 应该创建多少个智能体或设置哪些岗位。
- 展开 OTC 阶段、单据清单、页面入口、接口或工具。
- 提醒 Workbench 去研究代码、调用某个能力或采用某种运行时。
- 在失败后解释原因、提供重试步骤或替它修复运行。
- 用开发工具、接口或数据库帮助团队完成业务。

Workbench 若提出业务问题，测试者只回答一个普通业务负责人合理知道的事实。Workbench 若询问系统实现、页面或流程，测试者回答“你先看看系统里怎么规定，需要我做业务决定时再问我”。

## 用户起始表达

正式验收时只提供类似下面的含糊表达，不向模型展开流程、对象和接口：

> 我们接了苏州澄岳一套 800 型柔性线控制柜，年底前要交。你帮我找合适的人，把这件事在系统里办完，办完告诉我结果。

只有 Workbench 主动追问时，测试者才逐步补充：合同金额 24.32 万元、内部预算 18 万元、计划周期为 2026-09-10 至 2026-12-31。其他事实由 Workbench 从系统已有规则和资料中查找；确属业务决策且系统中不存在时，再由测试者确认。Workbench 不能自行编造会改变正式业务结果的事实。

## 不预设团队答案

测试者和验收脚本都不提供标准成员数量、岗位名称或工作流。Workbench 需要从任务复杂度、系统现有业务、所需权限和职责制衡中形成自己的团队方案。验收记录原样保存它第一次提出的成员数量、成员职责、选择依据和后续调整，不用预先设计的答案引导它。

评判关注最终业务是否完整、关键结果是否有人独立核对、同一成员是否越权完成互相冲突的职责，以及团队是否存在明显重复或空转。成员多或少本身不直接判错。

## 隐藏验收基线

下面的基线只供验收者在运行结束后核对，不能复制给 Workbench，也不能用于运行中提示它。

同一笔业务应留下可追溯关系：

客户需求 → 报价与合同 → 销售订单 → 项目与计划 → 正式 BOM → 缺料与采购 → 到货检验与入库 → 制造装配 → 发运与签收 → 调试整改与验收 → 开票应收 → 收款核销 → 收入与成本确认 → 项目结项与经营复盘。

允许采购、制造、开票和回款按业务条件并行或穿插，不要求为了展示流程而强制串行。团队需要说明每次并行或跳过的业务依据。

## 测试者如何回应确认

Workbench 主动请求确认时，测试者先判断它是否说明了操作对象、影响和后续结果。以下事项可以由测试者作业务确认：

- 合同金额、交付范围、承诺日期或付款节点缺失或互相冲突。
- 正式 BOM 发布、超预算采购、让步接收、发运、客户验收、开票、收款核销和项目结项需要责任人判断。
- 操作会撤销、作废、红冲、删除或覆盖已经形成的正式结果。

普通资料读取、计算、汇总、草稿准备和可撤销的页面填写如果反复要求确认，记录为产品摩擦，但不替 Workbench提出正确流程。

## 验收证据

1. Workbench 对话中能看到它自主形成的团队方案、必要追问、人工确认、进展和最终结果。
2. 团队成员在 inoForge 正常业务页面办理工作，不用测试脚本或直接改数据冒充用户操作。
3. 每个阶段的正式单据可从上游来源进入，并能找到下一岗位的待办或入口。
4. 金额、数量、库存、状态和来源关系前后一致；异常条件会被系统阻断。
5. 完成后重新启动 inoForge，仍能在页面回读同一笔业务及其结项结果。
6. 独立审核员重新核对页面和单据，能够发现刻意放入的至少一个业务错误。
7. 最终交付包含业务摘要、关键单据、异常与处理、验收依据、收款结算和经营结果。

## 问题记录与停止规则

每个问题记录用户表现、影响、证据、处置状态和恢复条件。出现以下任一情况立即停止：

- inoForge 无法从确定且可恢复的代码与数据库状态启动。
- Weave 团队无法通过受控工具访问 inoForge 的正常业务能力。
- 原始材料、上游单据来源或用户身份在流转中丢失。
- 运行中断后无法判断操作是否已经发生。
- 页面显示与实际业务状态不一致，继续会污染验收结果。
- 关键操作只有模型自述，没有系统结果或独立复核证据。
