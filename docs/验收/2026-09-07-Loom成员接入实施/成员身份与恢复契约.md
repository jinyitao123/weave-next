# 成员身份与恢复契约

2026-09-07。A 验收期间核对的 B/C 实现约束。B/C 定向实现与子进程契约已验证，产品出口 D 尚未完成。保留当前固定串行流程范围；并行成员不因新增入口而自动获得恢复能力。

## 稳定身份

团队运行、工作流快照、节点、节点进入序号、分支身份共同决定一次成员逻辑调用。团队恢复代数和执行租约代数属于执行权，不进入逻辑调用键。明确的新一轮节点进入使用新的序号。当前串行第一版分支身份固定为空；非空分支必须由支持它的入口处理，否则拒绝。

现有 `UsageAccumulator.NextCall` 会推进节点调用序号。团队当前检查点写在该调用分配之前，普通崩溃重入会得到相同序号；但若失败后把已推进的用量状态直接保存，下一次恢复会分配新调用。因此必须显式保存“当前未完成成员调用”，恢复优先接回它，完成接收后才清除此指针。不能直接使用带 `ResumeGeneration` 的现有 invocation ID。

首次进入先保存成员记录，再调用模型或工具。记录固定成员版本、工厂键、冻结包哈希、初始输入哈希和稳定 Loom run ID。重复投递应读取同一记录；同一逻辑键却有不同输入或冻结包时拒绝复用。

## 执行权与保存

复用现有 PostgreSQL Store、运行登记和 attempt 租约。成员的终态归于团队父运行，不能作为另一项团队根终态重复聚合。成员逻辑身份跨进程保留，新进程接管才更换 attempt。

保存检查点、保存回执、确认结果前，在同一事务中验证团队当前执行权和成员 attempt。旧进程迟到不能覆盖新检查点或结果。工具派发前也须验证执行权；数据库租约不具备撤回已发到远端的外部效果的能力。

新检查点协议的 latest、同序号不可变历史和成员进度索引必须一次事务提交。Loom 随后的相同 history 写入只确认同一内容；同序号不同内容是冲突。保存失败阻止图继续。旧 v1 图与发布物保持既有解释方式。

成员完成的结果必须先持久化，团队再幂等接收。若在两者之间崩溃，接回已完成结果即可，不再执行图。取消、业务失败与可恢复中断分别处理。

## 通用工具循环

模型响应、待调用队列、单项工具回执和继续位置分别形成持久化边界。一次模型响应可包含多项调用，第一版按顺序执行；业务代码和调用顺序由模型决定。

在已确认回执之后恢复时，复用原回执；回执与调用身份、工具名称、规范化参数哈希、输入版本绑定。工具效果已发生但回执未知时，需要幂等键或可查询结果；无法核对则停止并显示待核对，不自动重放。

内部边界在同一个有效 attempt 下推进，不把每项工具都伪装成用户暂停或新成员工作。新进程才领取新的 attempt。工具次数、模型用量、循环上限和累计预算随状态保存，恢复不归零。

## 验收反例

| 触发 | 必须观察到的结果 |
|---|---|
| 同一成员入口双进程同时接回 | 只有一个有效执行者，另一个获得具体冲突 |
| 新 attempt 生效后旧进程保存 | 旧写入被拒绝，最新状态保持新所有者的值 |
| 服务退出再启动 | 原成员与检查点可找回，逻辑身份不变 |
| 成员结果保存后、团队接收前退出 | 团队补收原结果，不重新调用工具或模型 |
| 回执保存后、图检查点保存前退出 | 从原回执补齐图状态，不重复产生效果 |
| 工具效果发生后、平台回执前退出 | 能查询则核对，不能查询则待核对 |
| 数据库保存失败 | 不进入下一模型或工具调用 |
| 重复点击继续 | 返回同一次恢复结果或其进行中状态 |
| 旧执行尚未失去执行权 | 不提前显示已暂停或可接管 |

## 实现取舍补充

使用原通用 ToolLoop 的确定性事件回放，在 Weave 适配层持久化模型与工具边界。模型请求保存了当时完整消息，响应保存了待调用队列，工具回执与位置分别绑定到成员、step segment 和序号。恢复回放已确认事件重建循环计数与消息，并恢复原物理用量回执；不会把已确认请求重新发给模型或工具。Loom 图状态保存 mid_step 定位，正常图步骤完成后保存 after_step，内部边界不需要用户 yield。

团队 generation 与 execution lease epoch、resume generation 共同验证当前父执行权，成员表使用父 generation 比较接管先后。这一细化来自实际继续命令测试，不能假定每次继续都推进 execution lease epoch。新 attempt 只在接管同一成员时分配。

## Workbench 继续入口

队列回收带有未完成成员的团队运行时，先保存原成员指针并进入等待，不自动调用模型或工具。只有用户接受一次“继续”，才允许一次新的成员执行入口。继续消息被重复投递，或者接受继续后进程又退出，下一次队列回收仍回到等待；这条命令不构成跨进程永久自动重试授权。

继续按钮同时要求原执行者已经释放或失去租约。已知工具效果但回执未知时，仍显示待核对并拒绝普通继续。API 只投影当前工作区、团队运行、快照和节点对应的成员 ID 与真实检查点时间，不返回模型消息或完整检查点状态。第一阶段只补齐中断后继续，没有新增主动暂停产品入口。

## 实际文件交付

被选中的冻结工具可在成功回执的 JSON 对象中返回 `weave_member_artifacts_v1`，其值为完整文件数组，字段沿用既有 `fileartifact.File`。普通 JSON 或模型最终文字不具有文件交付含义。新导出覆盖之前的完整快照；空数组表示清空，缺少此字段表示维持既有快照。路径、重复文件、单文件与总大小沿用现有交付校验；非法导出停止本次成员执行。

工具回执先持久化，随后把实际文件内容放入成员状态 `__member_artifacts_v1`。若在两者之间退出，恢复从原回执重新提取，不再执行工具。成员终态持久化这份内容；父工作流以 `member:<run_id>` 引用已完成成员，只接受同一工作区、父运行和快照下的完成结果，进入现有阶段与最终交付事务。API 不凭远端路径去读取本机文件，也不把模型声称的路径当作文件存在证据。

## 用量归属

成员终态保存自身物理回执的累计量，团队终态列出成员子项；团队自身量排除已列入子项的成员用量。API 使用根运行的 subtree 合计展示整项工作。完成结果补收与回执回放均不得再计一笔。失去响应的模型请求允许重试，但无法证明的那次用量保留不完整标记，不填写估算值冒充实测。
