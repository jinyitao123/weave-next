# Codex 受限工具配置探针

当前判定：不能以该配置开放“无工具”能力执行。平台 CLI 适配仍是未完成项。

本机 codex-cli 0.144.5 可启动且已登录。协议探针使用独立临时 CODEX_HOME 和拒绝请求的本机 HTTP provider，不调用真实模型，不改动宿主登录或全局配置。探针从 CLI 实际发出的模型请求读取工具清单，而非通过命令行参数推断限制成立。

配置使用 read-only sandbox、never approval，关闭 shell_tool、unified_exec、multi_agent、apps、plugins、computer_use、image_generation、hooks、skill_mcp_dependency_install，并设置 web_search=disabled、tools.view_image=false、project_doc_max_bytes=0。相关术语依据[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)和[官方安全说明](https://learn.chatgpt.com/docs/security)，具体效果以本机探针为准。

实际请求仍带 update_plan、request_user_input、apply_patch、view_image、get_goal、create_goal、update_goal 共 7 个工具。结果保存在[工具清单](2026-09-13-能力服务Workbench/codex-tool-inventory.json)。read-only 并不等于不向模型提供工具，因此本轮没有新增或启用能力服务的 Codex 执行适配器。

另一个已修复的兼容问题是 codex mcp list 的工作目录传递：进程通过 cmd.Dir 选择任务目录，不向 mcp list 传入它不支持的 -C 参数。既有 MCP 禁用测试通过。

可重复探针：设置 WEAVE_CODEX_PROTOCOL_TEST=1，运行 go test ./internal/kernel/engine -run TestCodexRestrictedProfileStillNeedsToolEnforcement -count=1 -v。可选的 WEAVE_CODEX_TOOL_PROBE_EVIDENCE 必须为绝对路径，输出只有 CLI 版本、工具名称和未启用标志。

后续需要可证明的工具执行约束或符合能力授权范围的隔离 Runtime，再接入生产调用。不能靠提示词、只读文件权限或后置输出检查代替工具授权。
