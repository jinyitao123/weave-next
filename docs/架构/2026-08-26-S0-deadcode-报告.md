## 1. 扫描与复核方法

执行了：

```bash
go run golang.org/x/tools/cmd/deadcode@latest ./...
staticcheck -checks=U1000 ./...
go run golang.org/x/tools/cmd/deadcode@latest -test ./internal/... ./cmd/...
```

首条命令得到 157 个函数候选，按路径为 app 25、base 33、build 9、kernel 83、`weave-app/node_modules` 7。staticcheck 得到 60 个声明候选，其中 14 个是 deadcode 未单列的 type/const/var，其余与 deadcode 函数重合。staticcheck 因发现 U1000 返回 1，属于扫描结果，不是验收门失败。

每个候选都按以下项目复核：

1. 用 `rg` 检查 `internal/`、`cmd/` 的生产与测试 Go 引用；另用 `deadcode -test` 复扫测试根。
2. 用固定字符串搜索检查非 Go 文件、字符串注册、反射式方法名和拼接入口。
3. 检查候选所在文件的接口实现关系和构造入口；接口方法不能仅因 deadcode 报告删除。
4. 全量检查 `//go:build`、`//go:embed` 及 `go list` 的 EmbedFiles/TestEmbedFiles。候选文件无构建标签；embed 仅存在于 db migrations、API install assets、web UI dist，均未命中删除对象。

## 2. 三分类统计

以下统计以 deadcode 的 157 个函数候选为主口径：

| 分类 | 数量 | 处置 |
| --- | ---: | --- |
| 确认死码 | 83 | 均位于 kernel；进入 S0-2，按 loomruntime 与其余 kernel 分票删除 |
| 误报 | 10 | 保留；原因逐项列于 §4 |
| 存疑 | 64 | 保留；均在 app/base/build，S0-2 的 kernel 删除范围外，且含导出 ABI、测试工具或尚未装配的产品路径 |
| 合计 | 157 |  |

staticcheck 额外单列的 14 个非函数声明中，kernel 的 4 个 `expectedAttemptLeasePresence*` 声明确认死码，随 loomruntime 票删除；其余 10 个位于 app/build，归入存疑并保留。因此按“声明”联合口径是确认 87、误报 10、存疑 74，共 171 项。

### loomruntime 子图裁决

`NewTerminalReconciler` 在生产和测试均只有定义；其调用的 recovery coordinator/assembler 也没有第二个根。因此 reconciler、coordinator、assembler 主体是可删除的无根连通子图。

不能整体删除相关文件：

- `terminal_lineage_repair.go` 的 `repairTerminalLineageRun` 同时被 `terminal_sink.go` 调用，是正常终态 lineage 修复活路径。
- recovery checkpoint 错误码被 `terminal_marker_store.go` 和 `attempt_lease_store.go` 的活跃校验使用，需保留定义。
- `attempt_lease_store.go` 的 lease CRUD 大部分仍被 admission、heartbeat、normal terminal 路径使用，只删除报告列出的七个函数。
- `normal_terminal_coordinator.go` 的核心事务路径由 terminal sink 调用，只删除一层无调用包装。

## 4. 误报

1. `internal/app/api/upload.go: importPackageError.Error`：`importPackageError` 在上传路径实际构造，`Error` 是 `error` 接口方法；保留。
2. `internal/base/fanout/workflow_seams.go: WorkflowResumeScheduler.ScheduleFromCompletion`：存在 `var _ LateSynthesisScheduler = WorkflowResumeScheduler{}` 的显式接口合同；即使当前没有运行时构造，也不能把接口实现当普通无引用函数删除。
3. `internal/base/testutil/postgres.go: PostgresPool`：被 `teamrun`、`teambuild`、`chatrequest` 测试直接调用；首轮不含测试根的 deadcode 扫描误报，`deadcode -test` 已不再报告。
4. `weave-app/node_modules/flatted/golang/pkg/flatted/flatted.go` 的 `Stringify`、`Parse`、`revive`、`loop`、`ref`、`ToJSON`、`FromJSON`：`./...` 穿入前端依赖内附的 Go 示例，既不属于 Go module 受控源码，也不能修改；整组 7 项为扫描范围误报。
