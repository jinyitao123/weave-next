## 1. 问题陈述（互审校正版）

compiler_v1 candidate 路径消耗真实 LLM 预算但无预算闸：无启动预检、scenario 循环间无检查、judge 无检查、tool_calls 记零。结果语义"先超支、后照常发布"。（legacy 控制器已有三道检查——本设计只针对 compiler 路径，不制造第三套语义。）

互审揭示的两个范围事实：

- **CLI 用量当前不可测**：CLI 节点返回零 usage（标 `usage_complete=false`）、CLI-backed build-agent adapter 返回空 Usage、engine.RunResult 根本无 usage 字段。预算闸只能约束**可测世界**；CLI 计量是 loom/engine 层的独立债务（§6）。
- **"提额恢复"当前不存在**：blocked 无出边、预算仅 planning 可改、receipt 绑预算、RetryOperationStep 不认 budget failure class。恢复协议是本设计的一部分，不是实现细节。

## 2. 分期

**Phase 1（本设计实施范围）**：可测世界的预算闸 + 恢复协议 + 统一原语。
**Phase 2（另立债项，不在本设计）**：CLI/engine 用量收据（engine.RunResult 增 usage、CLI adapter 如实上报）。Phase 1 对 `usage_complete=false` 的处理见 §3.6——不假装闸住了不可测部分。

## 3. Phase 1 设计

### 3.1 统一原语（防第三套语义）

- 单一 gate primitive：`teambuild.EvaluateBudget` 为唯一判定点，legacy/compiler/scenario/judge/planner/publish 共用；
- 判定规则只用 `ExceededDims`（**等号不阻断**——正好用满预算的 passing run 不得被误杀，修正 `Allowed` 的等号语义误用风险）；
- 统一结构化 reason：`budget_exhausted`（沿用 teameval 既有 failure class，不新造 `budget_exceeded`；legacy 的自由文本逐步收敛，恢复逻辑禁止解析字符串）。

### 3.2 闸点

| 闸点 | 位置 | 行为 |
|---|---|---|
| G1 启动预检 | candidate 启动前 | 已用量 ExceededDims → blocked(budget_exhausted)，零 LLM 调用 |
| G2 scenario 间 | 每场景记账后 | 超限 → 停止后续场景，blocked，已跑结果入报告 |
| G3 judge 前 | SemanticJudge 调用前 | 同 G2 |
| G5 publish 终检 | 见 §3.4 终结协议 | — |

### 3.3 G4 tool_calls 如实记账

- 扩展 terminal/checkpoint ABI 携带 tool-call 计数（旧 JSON omitempty 兼容读）；
- 两条硬编码零的 charge 映射改为真实计数；
- **历史零值行不补正**（append-only），报告区分"未知"与真实零。

### 3.4 G5 终结协议（不是"读一下 ledger"）

publish 路径上：`FOR UPDATE` 锁 BuildRun（复用 MarkPublishedTx 既有锁）→ 结清全部 usage source → 同事务读 ledger 判定 → 通过则 publish+passed，拒绝则**显式 `publishing → blocked` 原子转移**（绝不能裸返 error——那会被包装成 retryable infra error 形成重试循环）；passed 之后 `RecordBudgetUsageTx` 拒绝迟到 charge（状态校验）。

### 3.5 预算阻断恢复协议

- `RetryOperationStep` 增加 budget failure class（当前只认 compile/runtime）；
- 提额路径：blocked(budget_exhausted) 的 run 允许以**重新授权**恢复（新 receipt 绑新预算，brief hash 不变；这是既有授权语义的最小扩展，不发明新状态机）；
- evaluation_only run 同享此恢复路径（避免"释放并发占位后只能双倍烧钱重跑"）。

### 3.6 usage_complete=false 的诚实语义

- candidate 含 CLI 节点导致 usage 不完整时：报告显著标记（M3 已有），**publish 默认拒绝**，除非 brief 显式声明接受不可测用量（waiver 记入授权 receipt）；
- Phase 2 落地后按来源/维度收窄 waiver：有完整 CLI 收据的 token/cost
  维度不再豁免；终结收据缺失、CLI 只报部分维度、CLI 内部 tool calls
  等仍不可测部分继续要求显式、带理由的 waiver。未知用量永不按零处理。

### 3.7 evaluation_only 预算面扩展

评测请求 Budget 从仅 MaxCostUSD 扩展为完整 Budget（MaxToolCalls/token 上限可选），与 G4 对齐。

## 4. 与部分物化恢复的关系

互审裁定：预算阻断恢复与 blocked run 部分物化恢复**是同一个问题的两面**（G1 时 agent/team/workflow operation 可能已成功）。本设计的恢复协议（§3.5）只覆盖 budget 类 blocked；通用部分物化恢复（operation ledger 幂等重放）仍属独立债项，但 RetryOperationStep 的 failure class 扩展为其铺路。

## 5. 工作票

- BG-1：统一原语（ExceededDims 等号规则 + reason 收敛）+ G1+G2；
- BG-2：G3 + G4（ABI 扩展 + 真实计数 + 历史不补正声明）；
- BG-3：G5 终结协议（锁序 + publishing→blocked 原子路径 + 迟到 charge 拒绝）；
- BG-4：恢复协议（budget failure class + 重新授权恢复 + evaluation_only 共享）+ 全链验收；
- BG-5：usage_complete=false publish 政策 + evaluation_only 预算面扩展。

## 6. 另立债项（不在本设计）

- **CLI/engine 用量收据**（Phase 2）：engine.RunResult 增 usage 字段、CLI adapter 如实上报、loom 侧契约——这是 loom 层工作，需独立设计与 loom 版本发布。

## 7. 互审记录（codex 审计 + 主审裁决，2026-08-27）

| codex 论断 | 处置 |
|---|---|
| CLI 用量不可测，ledger 只是下界，fail-closed 对 CLI 是空谈 | 采纳，分 Phase 1/2 + §3.6 诚实语义 + §6 另立债项 |
| 提额恢复不存在（blocked 无出边/预算 planning 锁定/receipt 绑定/RetryOperationStep 不认 budget class） | 采纳，§3.5 恢复协议入设计 |
| G5 裸检查会被包装成 retryable infra error 形成重试循环；迟到 charge 无防护 | 采纳，§3.4 终结协议 |
| `Allowed` 等号语义会误杀正好用满预算的 passing run | 采纳，统一 ExceededDims（§3.1） |
| 防第三套语义：统一 gate primitive + reason code | 采纳（§3.1） |
| G1 时物化可能已成功，预算阻断恢复与部分物化恢复同根 | 采纳，§4 划清边界 |
| evaluation_only 只有 MaxCostUSD、blocked 后无法恢复只能双倍烧钱 | 采纳，§3.5/§3.7 |
