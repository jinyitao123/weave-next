## 1. 目标

元团队从"平台建造的唯一大门"降级为"可选的对话向导"；建造机制不再依赖任何 `__` 资产存在。

**互审后的关键认知：这不是一个里程碑，是三个。** 原 v1 把三件事混为一谈，互审证明它们各有独立的前置和阻断，强行同批必烂：

| 子程 | 内容 | 阻断 |
|---|---|---|
| **M2a 向导降级 + 真开关** | architect 的 create 分支产出模板草稿；metateam.enabled 完整 off 语义 | 无（可立即开工） |
| **M2b 后置评测入口** | template 团队的一键评测触发机制 | M1 遗留：candidate API 拒绝 passed run、占位合同无替换入口 |
| **M2c 裁判归建** | SemanticJudge/BlueprintPatchPlanner 从 agent 资产迁为 build 内部执行体 | internal_graph 不可用（硬失败）；质量语义/预算/恢复协议必须完整保留 |

## 2. M2a：向导降级 + 真开关

### 2.1 向导收窄（create 分支）

- architect 的 **create 分支**终点改为产出 team.yaml 草稿（M1 schema），工具面新增 `tf_render_template_draft`（校验+渲染草稿）；用户 Console 审阅后一键提交走 `/v1/teams:from-template`。
- **optimize 分支保留 legacy tf_* 不动**（互审裁定：模板 schema 是 create-only，独立 optimize 入口存在之前删协议 = 删能力）。prompt 重写只删 create 分支的建造协议教学，optimize 相关段落原样保留。

### 2.2 metateam.enabled 完整 off 语义

off ≠ 只跳过 seed（互审证明那会造成"界面看似关闭、资产仍可直呼"的半关闭态）。完整语义：

- **数据保留**：不删 Agent/Team/Roster/Conversation/历史 Run（审计与外键完整）；
- **执行冻结**：拒绝新的 create/optimize intent；拒绝对六个 metateam 名字的直接新运行（chat API gate）；worker dispatch gate；
- **入口隐藏**：Console 隐藏对话式"新团队"入口（feature 由 config 下发，前端不猜）；模板入口（M1）成为唯一创建路径；
- **在途 BuildRun**：off 时在途 run 由归建前继续 drain 或明确阻断报错，不允许"偷偷继续依赖旧 agent"；
- **开关作用域**：只匹配 metateam 六人名单，**不一刀切所有 `__` 前缀**——仓内存在独立的 `__graph_designer`（designprompt）；
- **visibility 修复**：`ensureMetaAgent` 新建记录显式设置 platform visibility（修复"迁移只回填存量、新建落 public"的不一致）。

### 2.3 M2a 验收

- enabled=false 全量测试绿 + 模板路径全功能 + 对话入口隐藏 + 直呼六个名字被拒；
- enabled=true 对话向导 create 分支产出草稿 → 一键提交 → unevaluated 团队；optimize 分支走 legacy 不变。

## 3. M2b：后置评测入口（M1 的未完成承诺）

M1 交付了"团队落 unevaluated"，但互审证明**评测触发入口当前不存在**：template BuildRun 物化后终为 passed，candidate API 只接受活 run；物化时冻结的是占位合同且 hash 已锁、无替换入口。

设计要点（M2b 开工前细化）：

- 新增 **evaluation run** 概念（或 optimize-evaluate 模式的 BuildRun）：以 unevaluated 团队为对象，允许在评测前用真实合同**替换占位合同**（新 contract revision，不是改原 BuildRun）；
- 通过 = 既有 candidate+publish 链；团队转 evaluated + 获得 published workflow；
- Console 在 unevaluated 团队卡片提供"开始评测"入口。

## 4. M2c：裁判归建（重手术）

### 4.1 互审纠正的认知

- `internal_graph` **不可用**：ChangeSet 执行固定失败 `agent_graph_compiler_not_connected`。不作为载体。
- 裁判的真实执行形态：registry 里的 AgentRecord 只是壳，**真正生效的是 GraphDefinition 内的详细 prompt**；执行走 declarative factory 的 llm_call（单条 user message、默认 deepseek-v4-flash、优先 Codex runtime）；attempt 预留、usage ledger、runtime run ID、崩溃恢复协议全在 teamorch 侧。
- 原调试裁判输出类型实为 SemanticJudge 输出（命名误导），**先重命名为 `SemanticJudgeOutputV1` 再拆迁移**。

### 4.2 归建形态

不是"直接调 LLM"（那会破坏预算/幂等/恢复），而是：**GraphDefinition + 执行协议从 agent 资产迁移为 build 带受控资源**（代码内 declarative graph 定义或受控资源文件），执行仍走既有 graph 执行器与 attempt/ledger 协议，只是不再注册为 workspace 可见 agent、不再按名字查 registry。

### 4.3 质量语义钉住

- 迁移前后对同一 frozen 评测输入，judge 输出结构与判据一致性测试；
- transport/model/重试/JSON 约束逐项对齐现状（含 Codex runtime 优先选择逻辑）；
- 预算：M2c 开工前显式预算复审——build 必然增长（prompt/graph/executor 迁入），抵消项是 metateam.go 中裁判 GraphDefinition 删除（app 减少）；预算调整与设计同 commit。

### 4.4 完成标志

- teamforge/teamorch 对 metateam 的 import 全部移除，**depguard baseline 2 归零**；
- api 侧（chat.go/agents.go/team_blueprint_planning.go/teamforge_wiring.go）与前端（identity/WorkspaceContext/AppShell）的 metateam 引用全部收口到"向导存在性"单一判断；
- `metateam.enabled=false` 时评测路径全功能（归建裁判不依赖 __ 资产）。

## 5. depguard baseline 的处置节奏

M2a 不动 baseline（引用仍在）；M2c 完成时归零并删除配置条目。期间任何新增引用 CI 红（ratchet 继续有效）。

## 6. 工作票

- M2a-1：tf_render_template_draft 工具 + architect create 分支 prompt 重写 + Console 草稿审阅提交；
- M2a-2：metateam.enabled 全链（config/seed/API gate/dispatch gate/前端 feature/visibility 修复）+ off 全量回归；
- M2b-1：evaluation run 设计细化（小型互审）；
- M2b-2：evaluation run 实施 + 合同替换入口 + Console 入口；
- M2c-1：调试裁判输出类型重命名为 `SemanticJudgeOutputV1`；
- M2c-2：SemanticJudge 归建（含质量一致性测试）；
- M2c-3：BlueprintPatchPlanner 归建；
- M2c-4：baseline 2 归零 + api/前端引用收口 + off 状态评测全功能回归。

## 7. 总验收

```bash
go build ./... && go vet ./... && go test ./internal/... ./cmd/...
./scripts/depguard.sh && ./scripts/base-depguard.sh && ./scripts/budgetguard.sh
cd weave-app && npm run typecheck && npm run lint && npm run check:tokens
```

真实场景：(a) M2a 两开关态各跑通；(b) M2b unevaluated 团队一键评测 → evaluated + published workflow；(c) M2c 后 enabled=false 下评测路径全功能。

## 8. 风险

1. **M2a prompt 重写伤及 optimize 分支**：只删 create 教学段落，optimize 段原样；用 optimize 回归守住。
2. **M2b 的 evaluation run 与既有 BuildRun 状态机语义冲突**：设计细化时单独互审，不与 M2a 混票。
3. **M2c 质量漂移**：一致性测试钉住；Codex runtime 优先逻辑逐项对齐。
4. **build 预算**：M2c 前显式复审，不接受验收时被动上调。
