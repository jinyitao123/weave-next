## 1. 目标

建造机制不再依赖旧元团队的 `__` 资产；裁判与修订机制归入 build 层，保留预算和恢复协议。

## 2. 旧元团队关闭边界

### 2.1 metateam.enabled 完整 off 语义

off ≠ 只跳过 seed（互审证明那会造成"界面看似关闭、资产仍可直呼"的半关闭态）。完整语义：

- **数据保留**：不删 Agent/Team/Roster/Conversation/历史 Run（审计与外键完整）；
- **执行冻结**：拒绝新的 create/optimize intent；拒绝对六个 metateam 名字的直接新运行（chat API gate）；worker dispatch gate；
- **在途 BuildRun**：off 时在途 run 由归建前继续 drain 或明确阻断报错，不允许"偷偷继续依赖旧 agent"；
- **开关作用域**：只匹配 metateam 六人名单，**不一刀切所有 `__` 前缀**——仓内存在独立的 `__graph_designer`（designprompt）；
- **visibility 修复**：`ensureMetaAgent` 新建记录显式设置 platform visibility（修复"迁移只回填存量、新建落 public"的不一致）。

## 3. M2b：后置评测入口（M1 的未完成承诺）

M1 交付了"团队落 unevaluated"，但互审证明**评测触发入口当前不存在**：template BuildRun 物化后终为 passed，candidate API 只接受活 run；物化时冻结的是占位合同且 hash 已锁、无替换入口。

设计要点（M2b 开工前细化）：

- 新增 **evaluation run** 概念（或 optimize-evaluate 模式的 BuildRun）：以 unevaluated 团队为对象，允许在评测前用真实合同**替换占位合同**（新 contract revision，不是改原 BuildRun）；
- 通过 = 既有 candidate+publish 链；团队转 evaluated + 获得 published workflow；

## 4. M2c：裁判归建（重手术）

### 4.1 互审纠正的认知

- `internal_graph` **不可用**：ChangeSet 执行固定失败 `agent_graph_compiler_not_connected`。不作为载体。
- 裁判的真实执行形态：registry 里的 AgentRecord 只是壳，**真正生效的是 GraphDefinition 内的详细 prompt**；执行走 declarative factory 的 llm_call（单条 user message、默认 deepseek-v4-flash、优先 Codex runtime）；attempt 预留、usage ledger、runtime run ID、崩溃恢复协议全在 teamorch 侧。
- 原调试裁判输出类型实为 SemanticJudge 输出（命名误导），**先重命名为 `SemanticJudgeOutputV1` 再拆迁移**。

### 4.2 归建形态

不是"直接调 LLM"（那会破坏预算/幂等/恢复），而是：**GraphDefinition + 执行协议从 agent 资产迁移为 build 带受控资源**（代码内 declarative graph 定义或受控资源文件），执行仍走既有 graph 执行器与 attempt/ledger 协议，只是不再注册为 workspace 可见 agent、不再按名字查 registry。

### 4.3 质量语义钉住

- 迁移前后对同一 frozen 评测输入，judge 输出结构与判据一致性测试；
- transport/model/重试/JSON 约束逐项对齐现状（含 Codex runtime 优先选择逻辑）；
- 预算：M2c 开工前显式预算复审——build 必然增长（prompt/graph/executor 迁入），抵消项是 metateam.go 中裁判 GraphDefinition 删除（app 减少）；预算调整与设计同 commit。

### 4.4 完成标志

- teamforge/teamorch 对 metateam 的 import 全部移除，**depguard baseline 2 归零**；
- `metateam.enabled=false` 时评测路径全功能（归建裁判不依赖 __ 资产）。
