# 交付可计算核验契约

本契约落实[分层收敛与 Loom 职责基线](2026-09-13-分层收敛与Loom职责基线.md)的交付核验边界。它让平台发现已约定的金额、字段、数量和集合错误，不能证明没有写入契约的业务要求，也不能代替使用者对成果的评价。

## 职责和冻结边界

- 团队构建层把用户目标中可计算的要求写入 `DeliveryContract.RequiredChecks`。内置建队工具提供结构化 `delivery_contract`，用户无需手写 JSON。标题使用业务语言；无法客观计算的要求放入 `limitations`。
- 发布校验拒绝无效的已知核验规则。工作流图、核验器版本、参数、标题随发布版本冻结，运行派发继续使用现有交付合同冻结和摘要机制。
- `internal/kernel/deliverycheck` 只实现有界数据读取、计算和比较。它不调用模型、工具、代码、网络或文件系统，不拥有领取、重试、取消和执行终态。
- `internal/app/deliveryverify` 装配可信核验器，按 workspace、TeamRun 和 snapshot 读取该执行的原始 source task payload。来源与工作流运行器读取 run input 的规则相同；恢复消息不会替换原始输入。
- `internal/base/deliverable` 继续拥有候选产物及来源摘要、版本化核验报告、事务保存和复查。失败的业务检查不会覆盖执行状态；成果更新产生新版本，旧报告保留。
- Workbench 复核区域显示已发布的业务标题、失败原因、实际值和要求值。用户采纳成果和系统核验是独立事实。

## `weave.deterministic/v1`

每个检查表达一个断言。`actual` 必须来自最终输出或最终 JSON 产物，`expected` 可以来自原始运行输入、最终数据或冻结常量。JSON pointer 只选择明确位置，没有表达式执行和动态字段查找。

| 运算 | 语义 |
|---|---|
| `equals` | JSON 值相等；数值按精确十进制意义比较，避免浮点舍入 |
| `less_than` / `at_most` / `greater_than` / `at_least` | 数值边界比较 |
| `set_equals` | 成员集合相同，忽略顺序和重复次数；需要同时检查重复时另加 `unique` |
| `unique` | 数组成员不得重复，可先选择每项业务标识 |
| `schema` | 按冻结的 JSON Schema 核对字段、类型、枚举、边界等；禁止外部引用 |

选择器支持 `count`、`sum` 和 `values`。`sum` 与 `values` 可通过 `field` 指向每项的字段；金额不进行隐式舍入。预期常量在发布时必须可以求值，版本不支持、参数未知或混用不成立时拒绝发布。

例子是一个可供 AI 建队工具生成和存储的内部契约片段，不作为用户配置页面：

```json
{
  "id": "total-matches-rows",
  "title": "总额应等于原始明细合计",
  "verifier_id": "weave.deterministic",
  "verifier_version": "v1",
  "parameters": {
    "actual": {"source": "output", "path": "/total"},
    "operator": "equals",
    "expected": {"source": "input", "path": "/rows", "reduce": "sum", "field": "/amount"}
  }
}
```

内置团队蓝图的最终输出为文本。需要逐字段核对时，团队应同时提交最终 JSON 数据文件，检查通过 `artifact` 指定该文件。产物路径与现有成果列表一致，支持 `outputs/` 展示前缀。

## 结论如何产生

输出中缺少指定字段、数值不一致、集合不一致、重复项或 Schema 不符合，记录为失败。原始比较数据缺失、输入结构无法读取、已知收集限制或核验资源上限使证据不足，记录为尚无法确认。所有声明满足时只证明这些已发布断言成立。

核验不读取模型的自评、置信度或审批声明。结果正文写着 PASS，不能替代数值或集合比较。AI 生成的契约本身仍可能遗漏要求或选错口径；本实现不会据此宣称业务要求已完整覆盖。未结构化的自然语言输入不由核验器再次交给模型解析。

每次核验记录最终内容摘要，使用原始输入时记录输入摘要，并保存实际值和预期值的有界预览。单份 JSON 限制为 1 MiB、嵌套深度 64、值数量 20,000；拒绝重复字段和极端数值指数。超出处理边界时不能获得通过结论。

## 验证范围

测试覆盖错误总额与自述 PASS 并存、精确小数、大整数、缺项、集合替换、重复项、字段和数值 Schema、冻结规则版本、错误来源身份以及外部 Schema 引用。真实隔离 PostgreSQL 测试覆盖失败报告保存、相同成果复查、修正成果的新版本、历史保留和 workspace/snapshot 隔离。

以上是确定性核验机制和产品投影的工程验证。真实浏览器建队、AI 是否正确生成目标要求以及最终业务材料的使用者验收仍应单独记录。
