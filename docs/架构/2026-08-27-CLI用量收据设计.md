## 1. 问题与边界（互审校正版）

CLI engine 用量当前不可测，预算闸对 CLI 消耗是哑的。互审确立的边界：

1. **CLI 自报用量是 best-effort，不是 billing-grade，不是安全控制**。恶意 runtime 可低报绕过、可高报 DoS。平台义务：字段合法性校验（非负/有限/不溢出）、收据绑定 task/run/attempt/runtime/engine/binary version、保留原始事件摘要、来源永标 `cli-reported`；有 provider 侧计量时以服务端为权威交叉核对。订阅/OAuth 通道无法独立核验，预算闸在此类通道仅为尽力而为。
2. **loom contract.Usage 值类型无法区分"未上报"与"真实零"**，且无来源/完整性字段——weave 侧需要自己的收据类型贯穿，映射到 contract.Usage 时保留语义。
3. **通路被截断四处**（本地执行器、远端接口、daemon completion、server executor 只传 output）——本设计的工程量主体在穿线，不在解析。

## 2. UsageReceipt（kernel/engine）

```go
type UsageReceipt struct {
    InputTokens   int    // 规范化后（§3.2）
    OutputTokens  int
    CostUSD       float64
    HasTokens     bool   // 维度级完整性（Codex 可能只报 token 不报成本）
    HasCost       bool
    Source        string // 恒为 "cli-reported"
    Scope         string // "invocation" | "session_cumulative"
    EngineVersion string // CLI binary version（仓内 runtimes 已有观测元数据）
    RawSummary    string // 原始事件摘要（审计用，截断）
}
```

**Usage=nil ≠ 零**：解析失败/事件缺失 → nil + 诊断通道（见 §3.4），绝不把"没解析到"当"零消耗"。CLI 明确报告全零仍是完整收据（HasTokens/HasCost=true）。

## 3. 关键语义

### 3.1 解析（三 CLI，样本钉测试）

- **claude**：result 事件的 `total_cost_usd` + `usage`（字段互斥性用真实 fixture 证明）；
- **codex**：按当前版本真实格式（实现时核实 + 样本钉住）；其 `input_tokens` 可能已含 cached 子集，**禁止盲加**；
- **opencode**：可能有多个 `step_finish` 或漏发终结事件——**只有拿到唯一终结收据才算完整**，否则 Usage=nil，不用部分总数冒充。

### 3.2 规范化（非价格估算）

- `InputTokens` = provider-inclusive 输入总量（cache_read + cache_creation 计入，否则 token 预算系统性低估）；Codex 的 inclusive 语义必须先由真实样本确认；
- `OutputTokens` 含计费 reasoning token，已 inclusive 则不重复加；
- 原始分项保留在 RawSummary 供审计。

### 3.3 计数语义

- **多物理 attempt 真实花费累加，同一 attempt 重放去重**——usage_accumulator 当前"一个逻辑 call 只存一份 Usage"的结构需要扩展（失败 attempt 的已发生花费也要计）；
- **session resume 不计量**（v1）：Codex 有 session 累计用量的历史行为，resume 场景禁用计量避免重复计数；Scope 字段为此预留；
- **失败/超时/取消的已发生用量保留**——三个适配器的 timeout 分支当前重造空 RunResult，必须携带已解析收据；
- **daemon lease lost 的首笔花费**：v1 如实记录局限（无法补回），文档声明。

### 3.4 诊断与下游承载

- terminal schema 增加 usage source/completeness 字段（omitempty，旧 JSON 兼容）——否则"来源标注"无处落地；
- RunResult/EngineExecResult 增加 diagnostics 通道（解析告警不再静默）；
- CLI 内部 tool calls 仍不可测（MaxToolCalls 维度对 CLI 继续盲）——如实写进文档，不宣称"预算闸对 CLI 完整生效"。

### 3.5 usage_complete 语义升级

- 判定从单布尔升级为维度级（HasTokens/HasCost）；
- **incomplete 粘滞**：run 中任一节点 incomplete 后，后续节点有收据也不翻回（与既有恢复逻辑一致）；
- waiver 按"未覆盖来源/维度"继续存在（修正 Phase 1 文档"Phase 2 后取消 waiver"的说法为"按来源收窄"）。

## 4. 工作票

- P2-1：UsageReceipt + 三 CLI 解析（真实样本 fixture）+ 失败分支保留收据 + RunResult/diagnostics 字段；
- P2-2：四处截断点穿线（本地执行器/远端接口/daemon completion/server executor）+ runtimellm adapter 映射（含 judge/planner 通道兼容验证）；
- P2-3：accumulator 计数语义（attempt 累加/重放去重/失败计入）+ terminal source/completeness 字段 + 维度级 usage_complete；
- P2-4：端到端验收（CLI 节点真实收据入账、超支被闸、无收据 waiver 不回归）+ 信任边界文档。

## 5. 验收

- 三 CLI 真实样本解析测试（含 opencode 漏发终结事件 → nil）；
- 失败/超时 run 的已发生用量入账；
- 同 attempt 重放不重复计数、多 attempt 累加；
- CLI 节点 candidate 超支 blocked；
- 真库全量零豁免 + 全部门禁。
