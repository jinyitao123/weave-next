# Workbench 工作对话方案

2026-09-05 · 三批开发已归拢；按 Workbench 唯一业务入口清理后重新验收

Workbench 是唯一页面入口。Weave 提供后台执行与保存；运行节点接入和业务可见状态进入 Workbench 设置，服务诊断与宿主进程操作留在 CLI、系统服务或 Compose。

一项工作保留一个持续的主对话。执行事实固定在顶部，重要事件与决策留在对话，成员过程与成果按需打开。已有团队、运行记录、纠偏、恢复和交付接口继续作为事实来源。

## 四个区域

| 区域 | 职责 |
|---|---|
| 左侧工作导航 | 按工作区的明确会话关联找到工作，以标题、团队、状态呈现已派发任务 |
| 顶部任务栏 | 持续说明当前任务、执行团队、状态和待办 |
| 主对话 | 讨论、接单、回答问题、恢复、明确对象的调整与确认、领取通知 |
| 工作现场 | 在进展与成果间切换，查看成员输入输出、运行位置和可读文件 |

一段工作对话对应一项团队任务，重试和修订保留原工作关系与执行历史。普通提问不等同于修改执行；调整必须带对象与要求，并区分请求提交、受理、等待确认、确认接受与真正生效。

## 分三批实现

| 批次 | 范围 | 统一验收时须证明 |
|---|---|---|
| 交互闭环 | 主对话问题与恢复卡、真实操作回执、成员与成果互跳、桌面默认 40/60 分栏和主动全幅 | 不打开现场也能处理任务；后台更新不抢焦点、丢草稿或重复插卡 |
| 成员过程 | 先接一个 Codex 外部运行时的公开增量事件；少量关注成员；历史阅读与跟看分离 | 阶段尚未结束就有真实输出；重连不丢、不重、不串成员；未支持的运行时标明阶段完成后更新 |
| 项目只读汇总 | 基于工作区明确关联的任务汇总团队、成员状态、活动、运行位置、待办与材料 | 能回答谁在做、哪里需要处理、有哪些成果，并能回到原任务与材料 |

桌面空间不足先收导航，小屏通过明确视图切换。拖动保留宽度偏好，返回保留现有内容树与草稿。现场仅保留进展、成果两类主内容，减少重复统计。执行结束但无最终成果时标为交付待处理，不显示完整交付成功或成果采用评价。

增量事件只展示运行时公开提供的说明、工具操作、允许展示的输入输出与生成内容。未提供的思考不补写，没有新输出也不直接判为卡死。最终与阶段成果按运行归属区分，草稿不能冒充最终交付；完整文件获取须来自真实已保存内容。

本轮成果阅读覆盖已保存的 Markdown、CSV/TSV、SVG 与静态 HTML：表格保留原始单元格文本，图纸在现场缩放，超过预览范围时提供已保存文件的完整下载。现有运行时文件传输仍受单文件 256 KiB、合计 512 KiB 等边界限制；明确承诺但未采集成功的文件必须报告交付缺口。不会把普通网页预览当成应用已启动，也不会从正文猜测可用的应用地址。

本轮不引入团队市场、新调度智能体、复杂组织、全员独立持久聊天或额外审批层。复杂应用、工程计算和公开部署安全仍需要各自业务证据，不能由界面和文件可打开推导通过。

## 开发与验收顺序

按用户最新要求，先完成三批代码并统一归拢，再集中执行工程门禁、真实浏览器任务、断线恢复与跨进程验证。智能体分别负责运行机制、工作对话、项目汇总；主代理负责壳布局、交叉审查、集成与最终验收。共享文件只保留一个编辑者，其他成员通过协议与明确片段协作。

统一验收逐项记录在[验收清单](../验收/2026-09-05-Workbench统一验收清单.md)，不能用某个智能体的局部通过代替整体闭环。
