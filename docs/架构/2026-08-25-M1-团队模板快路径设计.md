## 1. 目标与验收

**一份团队模板 YAML 提交后，团队直接可运行，构建全程零 LLM 调用。**

验收（对应产品方案故事 1）：

- 从样例库复制 `research_synthesis`、改两处、提交，到团队就绪可派活，端到端 < 10 分钟（机制部分目标 < 60 秒）；
- 模板非法时返回字段级错误清单（422 + problems），不是 500；
- 构建全程不触发 LLM 调用（provider 调用日志为证）；
- 既有元团队路径全部回归不变；
- `__` 前缀写门禁端到端回归：模板路径无法创建/修改 `__` 资产。

## 2. 核心设计修正（互审后的诚实版本）

v1 假设"原管线直接复用"，互审证明不成立：**teamforge compiler 强制每个 ChangeSet 恰好包含一个 candidate_run + 一个 publish（publish 依赖 candidate），而 candidate 会真实执行评测合同场景、需要 LLM。** 因此"零 LLM + 评测后置"必须有一个新的执行策略，这是本设计唯一的机制新增：

**`template_instantiate` 执行策略**：ChangeSet 只含资产物化操作（创建 Agent/Team/Workflow），不含 candidate_run、不含 publish。teamorch 按策略分发。团队落库后标记 `unevaluated`（新增持久化字段），以 **free-collab 路径**接活；评测通过后（一键后置，走既有 candidate+publish 链）才拥有 published workflow。

这正好把产品语义说圆了：**未评测的团队自由协作，评测过的团队有固化工作流。**

## 3. 模板 Schema（产品面）

```yaml
# team.yaml
schema: team-template/v1
name: market-research-trio        # URL 安全 ^[a-z0-9][a-z0-9_-]*$，派生 name_prefix
display_name: 市场调研三人组       # 中文展示名
purpose: 持续产出竞品监控报告
template: research_synthesis      # 4 内置拓扑之一；declarative_v1 见 §8
template_parameters:              # 必填项按内置模板要求（lead_instruction、result_requirements）
  lead_instruction: 组织协调调研与成稿
  result_requirements: { report: 不超过 3000 字、含数据来源标注 }
members:
  - name: researcher              # stable_ref = name（确定性派生）
    display_name: 调研员
    role: worker                  # avatar | worker；lead 必须指向 avatar
    responsibilities: [检索与事实收集]
    capabilities: [web_search]
    model_ref: ""                 # 可省略 → 服务端补全
    execution_policy:             # 可省略 → 服务端默认 standard+toolloop
      engine_class: standard
      execution_mode: toolloop
lead: coordinator                 # 按成员 name 引用；该成员 role 必须是 avatar
delivery:
  success_criteria: [数据可溯源, 覆盖全部指定竞品]   # → 合成合同的 rubric 种子
budget:
  max_cost_usd: 2.0               # 必填；> workspace 阈值则转人工授权
```

字段规则：**业务字段必填、技术字段可省略**。`management_mode` 恒为 `managed`（create 模式），模板不暴露。成员 name 唯一、URL 安全，且全部落在团队 name 派生的 name_prefix 下（schema 级校验）。内置工作流的 `primary_ref`、`reviewer_ref`、`parallel_worker_refs` 与 `finalizer_ref` 都会编译成 machine worker 节点，必须引用互不重复的 `role: worker` 成员；lead/avatar 只负责 lead 节点，不能兼任这些执行节点。

映射钉死原则：模板字段与 compact_blueprint 字段 1:1 映射并有测试钉住，**模板层禁止发明 compact_blueprint 没有的语义**。

## 4. 端点与管线

```
POST /v1/teams:from-template     （由 Workbench 宿主调用的后台接口）

请求：{ yaml: <模板文本>, idempotency_key: <uuid> } 或 { sample: <样例名>, overrides: {...}, idempotency_key }
响应：201 { team_id, build_run_id, status: "ready", evaluation: "unevaluated" }
      202 { build_run_id, progress_url }        —— 构建超时兜底 / 需人工授权（authorization_required）
      422 { problems: [字段级错误清单] }
      409 同 idempotency_key 且内容指纹不同
```

幂等：`idempotency_key` 必填；同 key 同指纹重放返回原结果，不同指纹 409。YAML 限制：请求 ≤ 64KB、禁 alias、深度 ≤ 10、未知字段报错、parse error 映射为字段级 problems。

服务端管线：

```
解析+校验模板（422 快速失败）
  → 机器合成 BuildBrief + EvaluationContract（ValidateBuildRunDrafts 同标准，见 §5）
  → CreateBuildRun（planning；created_by = 真实提交用户）
  → expandCompactTeamBlueprint（原样复用）
  → 提交 blueprint revision
  → 授权（§6）
  → SubmitBuildRun → teamorch 按 template_instantiate 策略执行 → ChangeSet 落库
  → 轮询 BuildRun 终态（独立 timeout context）：passed + final_ref.team_id → 201；
    blocked/cancelled → 失败详情；超时 → 202 + progress_url（复用现有 progress API）
```

**写路径铁律**：模板 service 只产出 BuildBrief/Blueprint，一切写入经 teamforge compiler applier（writegate、`__` 保护、receipt 校验全在其内），禁止直接调 org/registry/workflow Store。

## 5. 机器合成 EvaluationContract 的完整规则

互审更正：GateEvaluator 固定执行 14 个内置 gate，**不遍历 contract.HardGates**——把自然语言塞进 hard_gates 不会有任何机器检查。合成规则因此为：

- hard_gates = `DefaultFloorHardGates()`（仅 floor，不添加业务门禁）；
- delivery.success_criteria → **rubric 维度种子**（供后置评测的语义裁判用），不进 hard_gates；
- rubric/public_scenarios/run_count/max_iterations/perturbation_scenarios 按 contract v2 合法性的最低要求生成（空业务场景集 + 明示占位，评测后置时由用户或元团队补全真实场景）；
- 合成器为纯函数 + 表驱动测试钉住输出。

## 6. 授权：分级 + 新 authority 语义

- 新增 authority `template_auto`：**绑定已冻结 blueprint revision token**（不复用 auto_build——它强制 nil token，与设计承诺的"receipt 照常绑定 revision"冲突）；confirmed_by = 真实提交用户，另记决策主体 `platform-template-authorizer` 与阈值判定理由。
- 路由权限：**保持 admin**（或新增显式 scope），不以金额阈值替代权限门槛——模板端点若放开给普通成员等于完整建造权限升级。
- 额度防线（防拆单）：budget ledger 只按 build_run 聚合，挡不住 N×$5。新增 workspace 级**日/月聚合额度** + 单 workspace 并发模板构建上限；模板 budget 仍走既有 ledger 记账。

## 7. unevaluated 状态

- `org.Team` 新增持久化字段（迁移 SQL）：evaluation 状态（`unevaluated`/`evaluated`），模板路径落 `unevaluated`；
- 一键后置评测走既有 candidate+publish 链，通过后转 `evaluated` 并 publish workflow。

## 8. declarative_v1 快路径（M1 收尾票）

模板路径内部串联即可满足现有前置（CreateBuildRun → blueprint revision → declarative plan 冻结 spec hash），不放宽冻结条件。先交付 4 内置模板支持，declarative_v1 紧随其后。

## 9. 样例库

- `templates/` 入库 3 个行业样例（市场调研 research_synthesis / 内容生产 delivery_rework_loop / 代码评审 parallel_review），名称全部 URL 安全；
- `GET /v1/team-templates/samples` 列出样例；

## 10. 验收

```bash
go build ./... && go vet ./... && go test ./internal/... ./cmd/...
./scripts/depguard.sh && ./scripts/base-depguard.sh && ./scripts/budgetguard.sh
```

真实场景：调研样例 → from-template → 团队就绪（unevaluated）→ free-collab 派活 → 交付物（LLM 部分可用 stub provider，协议路径必须真实）。回归：元团队 create_team 路径不变；`__` 前缀拒绝测试。

## 11. 互审记录（codex 审计 + 独立反查，2026-08-25）

### 关键裁决

| codex 论断 | 反查 | 处置 |
|---|---|---|
| ChangeSet 强制 candidate_run+publish，candidate 真实执行评测合同，"零 LLM 复用原管线"不成立 | **属实**（change_set.go:689 无条件追加 candidate→publish；主审亲见） | 采纳，新增 template_instantiate 执行策略（§2） |
| §2 示例按命名规则必然校验失败（中文名、name_prefix） | **属实**（`^[a-z0-9][a-z0-9_-]*$` 亲见） | 采纳，name/display_name 拆分（§3） |
| unevaluated 状态不存在 | **属实**（org.Team 无此字段） | 采纳，§7 新增持久化字段 |
| 四带预算恰好顶格，M1 首提交必红 | **属实**（budgets.json actual==limit） | 采纳，见下方预算裁决 |
| auto_build authority 强制 nil revision token | 属实（authorization.go:221） | 采纳，新增 template_auto（§6） |
| 拆单放大（ledger 按 build_run 聚合） | 属实 | 采纳，workspace 聚合额度（§6） |
| 模板端点非 admin = 权限升级 | 属实（现有创建/授权/submit 均 admin） | 采纳，保持 admin |
| success_criteria 进 hard_gates 无执行效果 | 属实（GateEvaluator 固定 14 内置 gate） | 采纳，改进 rubric 种子（§5） |
| lead_ref 指向 stable_ref 且须 avatar | 属实 | 采纳，stable_ref=name + lead 指向 avatar（§3） |
| 端点命名与产品方案不一致 | 属实 | 采纳，统一为 `/v1/teams:from-template` |
| 完成信号 = BuildRun 终态轮询（非 taskqueue；外层构建走专用 execution_jobs） | 属实 | 采纳，§4 管线按此写 |

### 预算裁决（搬迁方案 ratchet 的补充规则）

ratchet"只减不增"防的是无意膨胀，不挡计划内功能。**计划内功能票允许显式调增预算，条件：在 PR 中写明理由并更新 budgets.json 同 commit 完成。** M1 预计增量：app（模板端点+service）、build（template_instantiate 策略）、kernel（org.Team 字段）各数百行级。

### 遗留

- 元团队路径本身在 M2 才会改户籍；M1 不动它。
- `handleSubmitBuildRun` 响应可能带旧 run_status（授权前读的对象）——模板路径不复刻此行为；既有端点的修复列入"想改但没改"。
