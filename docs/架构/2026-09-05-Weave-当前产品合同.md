# Weave 当前产品合同

2026-09-05 · 2026-09-29 修订：GooeyPi 桌面加 Forge 为唯一客户端，网页 Workbench 下线

**Weave 是智能体团队平台：让员工把多阶段工作交给已发布的团队，并拿回属于这项工作的真实结果。** 依据为 `weave-workbench` 仓决策记录 001（Weave 平台范围收窄与唯一客户端）。

## 客户端与入口

| 入口 | 谁在这里做什么 |
|---|---|
| GooeyPi 桌面加 Forge（`weave-workbench` 产品） | 员工用 Forge 账号交接工作、收到团队结果并续办；开发者配置、试跑和发布团队 |
| 运维 CLI、系统服务、Compose | 维护者做诊断、升级、备份、运行节点接入与管理员 API Key 签发 |

GooeyPi 桌面加 Forge 是当前唯一业务客户端。新入口按客户端契约接入，不为某个入口在 Weave 中另建业务流程。客户端契约维护在 `weave-workbench/contracts/v1`，Weave 对其中由自己实现的部分承担兼容与回归责任。员工与开发者只通过 Forge 身份交换登录；Weave 本地密码登录与首用户注册关闭。

## 保留与下线

- **保留：** 团队与成员定义、流程编排（顺序、并行、条件、循环、汇合、等待）、发布冻结、执行调度、租约、额度、取消与恢复、用量；多运行时成员（Loom、Codex、Claude、OpenCode 等），各执行器分别声明恢复能力。
- **下线：** 团队模板、建队运行与评测（含裁判）、元团队、网页 Workbench。先在部署中关闭（`WEAVE_METATEAM_ENABLED=false`、不部署网页 Workbench 及网关、不注册相应接口），确认无调用后删除代码。删除前先把流程发布使用的产品发布代码移出 `teamconstruction`，并去掉智能体接口对元团队成员名的引用。
- **另行确认：** 对外投递目标、人工等待节点在该客户端中的定位。服务端受限选择决策作为范围例外单独约束，见[受限选择决策接口](2026-10-02-受限选择决策接口.md)。

## 权威边界

团队运行状态以 Weave 为准。业务记录、审批、处理人与最终业务状态以 Forge 为准。Weave 交付物只是团队交付，不能表示业务已完成。客户端读取平台保存的执行事实，不把聊天摘要当成任务状态。

## 卡住后怎么办

| 情况 | 应向员工说明 | 支持的处理方式 |
|---|---|---|
| 需要员工补充或确认 | 缺什么、为什么需要 | 从原工作补充后发起关联的新一轮 |
| 等待执行机器或外部服务 | 等待原因、已完成到哪里 | 等待恢复，或停止任务 |
| 某个阶段失败 | 哪一步失败、是否可以重试 | 支持时重试该阶段；否则说明需要维护者处理 |
| 员工希望结束 | 正在停止还是已经停止 | 停止后仍可查看已保存的工作 |

重试前应说明从哪里重做、哪些成果会保留；需要从头开始时也要明说。停止请求不能提前显示为已经停止，已经完成的外部动作不会因此自动撤回。关闭客户端再回来，应找到同一项工作。

## 验收

产品验收按 `weave-workbench` 仓的验收规则，从 GooeyPi 桌面正常路径发起，并在 Forge 页面独立读回业务结果。Weave 单元测试、健康检查或运行完成状态不能替代这项验收。
