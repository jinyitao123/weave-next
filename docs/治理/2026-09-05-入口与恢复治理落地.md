本轮把已有任务入口和恢复能力接齐、收紧，范围包含 Weave 与相邻的 `weave-workbench` 工作区。保留两仓进入本轮前的未提交工作。

## 用户能感知的变化

| 场景 | 本轮处理 |
|---|---|
| 交出任务 | Workbench 的指引要求确认团队、工作范围与交付要求；用户已经明确确认就直接执行 |
| 任务停住 | Workbench 沿用现有任务卡，区分人工确认、纠偏、定时等待、团队阶段等待与执行环境中断 |
| 重试某一阶段 | 只有当前等待、当前阶段和可恢复的环境故障能显示重试；历史失败不再留下可点的旧按钮 |
| 连点重试 | 同一恢复请求复用已排队的工作，保留检查点中的已完成成果 |
| 重试时同时停止 | 两个操作按同一运行记录排序，停止不会被旧重试复活；重排失败整体回滚 |
| 恢复中遇到崩溃 | 旧任务再次被领取时不能抢走新恢复任务；终态已提交但队列尚未确认时，不重复执行 |
| 长任务看进度 | 有限活动窗口保留最近事件，明确标注记录不完整；有历史成果的阶段再次执行时，不误计为完成 |
| 等待与领取 | 查询只认本次任务；暂停及时返回等待状态；只有阶段产物时，Workbench 提示最终成果待核实 |

没有扩展工具数量或业务功能范围。纠偏、重试与停止继续使用既有接口；后端新增的 `wait_node_id` 只提供当前等待节点，不公开恢复令牌。

## 验证边界

验证使用隔离 PostgreSQL、自动化故障注入及 Workbench 固定输入。它们用于判断状态、并发和展示是否正确，不证明真实模型产出质量、用户采用或线上稳定性。

完成本文所记修复时，尚未发布、提交或部署该版本。真实浏览器连接实际 Weave 的跨仓旅程，以及真实模型执行后的成果领取仍需试点验收。

[20 项真实任务台账](../验收/2026-09-05-20项真实任务试点台账.md)维持已执行 0 / 20；待绑定业务材料、任务提出者与成果采用判断，不能把自动化测试计入。
