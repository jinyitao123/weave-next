# Loom 既有路径补齐与验收顺序

2026-09-07。建议方案；本次仅核对代码并落档，尚未启动以下实现。

## 决策与目标

系统已有 Loom 对话图与成员图执行路径。本次讨论的是补齐工作流内 Loom 成员的工具与恢复链路，并非首次引入 Loom，也不是全量替换 CLI 成员。

建议下一项先修复已经证明的发布工具依赖缺口。之后以一个团队副本、固定串行流程、一个 Loom 成员、同一可用执行环境验证持久化恢复。目标体验是成员中断后，Workbench 显示可恢复位置，用户点击继续，新进程沿同一成员逻辑执行继续，并完成可独立检查的交付。

CLI 失败产物交接仍是可选路线；本轮暂不与 Loom 路线并行开发第二套内部恢复机制。工具链修通只证明 Loom 成员可用，不足以决定业务迁移。必须经过完整任务与故障验收，才能扩大使用范围。

此前的 [成员执行补齐方案](2026-09-07-Loom成员执行补齐方案.md) 保留完整目标架构；本文收窄实施顺序。此前 [采用价值验证记录](../验收/2026-09-07-Loom采用价值验证/README.md) 的对照无效结论保留，不用本方案将其改写为 Loom 胜出。

## 四个连续交付

### 1. 发布后的工具真正可用

打通 `成员配置 → 依赖冻结 → 模型工具定义 → 实际派发`。缺少必需工具、工具重名或定义不兼容时给出具体错误。运行和恢复读取冻结依赖，不临时借用当前注册表中的另一份配置；凭据只保存引用。

先审查完整工厂键、输入版本和旧发布物兼容方式，再修改标准工厂、冻结结构和运行装配。已有发布物的哈希与解释规则保持可加载，新能力通过新发布版本启用。

功能样本使用真实基线与真实工具，让模型自行编写计算文件、执行测试并交付结果。保存冻结包、模型工具定义、调用回执与输出文件，证明工具没有丢在发布链路中。该样本仅验收工具接线，不声称完整成员验收或性能收益。

**出口 A**：正向链路实际执行通过；必需工具缺失被定位；旧发布物兼容检查通过。第一项未通过，不扩大到恢复或 UI 实现。

### 2. 同一成员身份与进度持久保存

将冻结成员图接入受控的持久化入口，复用现有 PostgreSQL、执行租约和终态机制。接口由装配层注入，保持仓库分层约束。恢复保留成员逻辑身份，新的执行进程领取新 attempt；循环进入、并行身份及团队恢复代数的关系须在契约中明示，不能只用节点名作唯一键。

先做不调用模型的双进程契约验证，确认重复接回只产生一个有效执行者，旧进程迟到不能覆盖新状态，成员完成但团队尚未接收时可补齐接收。第一阶段产品覆盖仍限定串行成员。

**出口 B**：服务重启后可找回同一成员及已保存图状态，归属和终态不重复。此时还不能宣称任意工具中断可续作。

### 3. 工具完成后形成可靠恢复点

为新版本标准成员实现通用的持久化工具循环，明确模型响应、待调用请求、工具回执和继续位置。工具回执及恢复点保存成功后才推进下一步；已确认回执与调用身份、工具名、参数摘要和输入版本绑定。

对于“工具已产生效果但回执尚未保存”的窗口，通过工具幂等键或结果查询确认；无法确认时进入待核对，不自动重放。第一版只承诺对纳入验证的工具生效。累计预算跨恢复保持连续。

**出口 C**：真实新进程恢复后，已确认工具效果没有重复产生；保存失败阻止继续；结果不明时明确停住。通用工具循环不能用预写的四步业务图代替。

### 4. 从 Workbench 完成实际恢复与交付

复用现有任务对话和工作现场，增加准确的成员恢复状态与操作。第一版由用户点击继续，不先做无人值守恢复。服务端验证旧执行已停止或失去有效执行权；重复点击幂等。界面只显示实际存在的恢复点，不能把等待停止提前显示为已暂停。

最终样本使用真实工程成员的完整工作要求，让其从真实输入生成模型、图纸、离线应用和验证材料。在已确认计算工具完成、全交付尚未完成时终止承载 Loom 的执行进程，再从 Workbench 继续。模型推理可由 Runtime 承接，但必须证明工具调度由 Loom 控制，未绕到原生 CLI 自行执行工具。

**出口 D**：真实浏览器完成恢复操作；同一成员逻辑身份由新进程继续；调用回执证明复用范围；最终文件可访问，计算、单位、图纸和应用行为独立验收通过。模型自行声称完成不算通过。

## 第一阶段完成条件与后续决策

A 至 D 全部通过，才可称为“一个 Loom 工作流成员具备可用的恢复闭环”。工具接线、数据库检查点或内核脚本单独通过均不算产品完成。

若工具链和恢复闭环可用，再依据完整任务的交付质量、重复工作、恢复成本和新增维护量，决定是否把特定业务成员迁至 Loom。若主要困难是工具能力不足，或收益仍依赖同一套文件/回执交接，则收窄结论并重新比较 CLI 成果接续，不能把公共基础设施的收益归给 Loom。

任意历史分支、跨主机迁移、并行成员恢复、全队切换、长时间休眠后回收本地过期回执属于后续范围。首阶段只承诺有明确恢复点的中断继续。

实现按影响运行定向测试、实际 PostgreSQL 故障验证及仓库要求的分层、产品和全量测试；涉及 Workbench 时完成其规定检查和浏览器验收。迁移与平台装配变化按 `docker-compose.platform.yml` 验证。本文是实施前的可审查方案，不将以上检查记为已完成。
