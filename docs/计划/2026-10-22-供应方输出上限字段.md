# 供应方输出上限字段

本批接续 #83 的地址与管理页面，以及 #82 中未完成的输出上限字段映射。

- 责任层：Loom 的 provider 叶子适配器选择实际 JSON 字段；Weave base 保存契约，kernel 凭据修订及冻结运行时传递配置，app/API 与管理页面负责编辑。
- 事实所有者：沿用 ProviderRevision、FrozenModelBinding 和现有发布哈希；不增加队列、执行器或运行终态。
- 复用入口：组织供应方 PUT/GET、系统供应方镜像、标准发布编译、现有 Chat/Stream。成员的 max_output_tokens 仍是单次回复上限，max_tokens 仍是累计预算。
- 契约：供应方可选 output_limit_field（空值沿用 max_tokens，或显式 max_tokens / max_completion_tokens）。仅 Chat Completions 可声明该字段；其他协议和未知值在调用前拒绝。不根据模型名猜测。不配置单次上限时两个字段均省略。
- 冻结：非空声明进入供应方修订与模型绑定哈希；空值保持既有规范化输入。修改供应方 head 不改变旧发布及备用模型的冻结绑定。
- 验证：实际 HTTP 请求捕获覆盖 Chat、Stream、未设置上限、显式字段和安全观测；PostgreSQL 回归验证修订、哈希及镜像；页面正常保存/重开后独立读取数据库。执行整仓测试、构建、vet、前端检查及分层/产品/预算门禁。

#82 中成员级 thinking、temperature 和供应方能力矩阵不以本批输出字段映射宣称完成。
