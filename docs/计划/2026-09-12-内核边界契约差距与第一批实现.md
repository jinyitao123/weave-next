# 内核边界契约差距与实现顺序

更新：2026-09-13

目标依据：[Weave 内核边界与开发者契约](../架构/2026-09-12-Weave内核边界与开发者契约.md)。

状态：本机 Loom 与 Workbench 已接通，完整开发者契约仍在实施。验证范围见[运行时接入记录](../验收/2026-09-13-能力服务Loom运行时接入.md)。

## 当前实现与差距

| 契约部分 | 当前实现 | 剩余差距 |
|---|---|---|
| 定义 | internal/base/capability 保存开发者角色、步骤、输入输出、依赖及运行要求 | 条件、循环、人工等待及工具资源执行尚未连接，发布时拒绝 |
| 发布冻结 | 定义深复制、严格 JSON 摘要、数据库禁止修订更新/删除、调用绑定版本 | 发布者审计、资源版本依赖和默认别名策略需补齐 |
| 调用 | PostgreSQL 持久记录、原子入队、稳定应用 ID、轮换后身份连续性及 request_id 幂等 | 应用调用历史与配额管理 |
| 执行 | 现有 Loom compiler/ToolLoop、角色指令、JSON Schema 校验、并行依赖调度、结果汇合 | CLI 引擎及远程运行时池接入 |
| 运行事实 | 推理前绑定 Loom run ID、领取令牌、执行期限、终态回写 | 步骤 checkpoint 的自动恢复与更完整的用量产品视图 |
| 取消 | 排队直接取消；运行中先 cancel_requested；迟到结果不可覆盖；取消幂等 | 外部工具副作用及跨运行时停止确认 |
| 权限 | 人员管理权限、独立应用凭据 invoke/read/cancel 范围、发布版本 grant；受理和执行检查撤销 | 自动凭据过期、商业授权和配额 |
| Workbench | 主对话复用已有能力或由 AI 生成草稿，经用户确认后发布；设置页只管理应用、密钥和版本授权 | 对话式真实模型验收、历史调用列表 |
| 验收 | 实际 PostgreSQL 及 race 测试、真实 Workbench Host 和 Chromium 操作、Loom runner 与终态记录 | 真实模型/业务材料验收；当前模型端仍是受控 HTTP 服务 |

现有 workflow、teamrun 和 Runtime 链路继续服务原 Workbench 场景。能力服务的队列表是独立新增表，尚不能把它描述为已经复用了既有 taskqueue 状态机。后续接入需检查并收敛重复机制。

## 已建立的可检查链路

Workbench 主对话先列出已有能力。没有合适能力时，AI 将业务诉求交给 Weave 生成并保存草稿；用户确认业务方案后才发布固定修订。应用调用产生稳定 invocation，worker 领取后校验修订与输入，按依赖执行现有 Loom 步骤，保存 run 关联和结果。查询与取消只针对调用主体有权访问的记录。

测试分别证明数据库持久事实、Loom 运行事实和浏览器操作。受控模型返回的结果不构成真实模型效果或业务验收。

## 后续实施顺序

1. 独立应用、凭据轮换和版本 grant 已接入，继续增加历史记录、自动过期和配额；证据见[应用身份与授权验收](../验收/2026-09-13-能力服务应用身份与授权.md)。
2. 草稿调试快照与 debug 运行类型已接入，继续增加步骤观察与调试历史。
3. 对照现有 workflow machine 补齐条件、循环、人工等待语义，保留完整输入绑定和终止条件。
4. 接入现有 CLI Runtime 与资源授权，每种适配证明工具范围和停止确认，不通过提示词代替约束。
5. 增加 checkpoint 恢复、历史观察、用量与商业授权外围。
6. 用真实模型和真实材料完成开发者创建、调试、发布、修改、再发布、调用、干预和领取结果的验收。

每一步使用可审查提交、相关工程检查、明确的支持范围和真实证据。不能用健康检查、HTTP 202、fixture executor 或测试数量替代最终目标。
