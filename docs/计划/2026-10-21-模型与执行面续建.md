# 模型、部署管理与执行面续建

2026-10-21，接续中断的 provider、部署页、P1、P2 与代码仓库功能清理。依据为[分层基线](../架构/2026-09-13-分层收敛与Loom职责基线.md)和[高并发设计](../架构/2026-10-21-执行面高并发与模型网关设计.md)。决策模型是普通 Loom 成员；不增加成员引擎、直调路径或终态表。

| 部分 | 责任层与复用入口 | 事实所有者 | 契约与验证 |
|---|---|---|---|
| provider / 部署页 | app 组织模型 API、credentials、llmrouter、web/admin | credentials 的头记录与不可变修订 | protocol、可选密钥；真实 PG 隔离/修订/删除回归，管理页正常操作，真实 nimble 调用 |
| P1 | kernel taskqueue / teamrun / fanout / loomruntime；app 只装配 | 现有任务、认领 epoch、租约、TeamRun 与停止回执 | 批量方法不改变状态机；取消、过期、迟到完成、重启与通知丢失回归；受控模型压测 |
| P2 | kernel llmrouter；app 注入部署配置 | 原成员执行与 V3 用量账本 | 部署限流不改冻结修订；并发、RPM/TPM、公平、排队取消、429 期限回归 |
| 代码仓库清理 | app 与管理端，保留执行器使用的共用环境合同 | 历史环境、运行与审计记录不删除 | 先确认调用方，移除专属入口与代码；productguard、依赖检查和完整构建 |

每部分记录实际检查结果；工程测试、受控压测与真实产品验收分别报告。不得将文件存在或模型自述视为完成。
