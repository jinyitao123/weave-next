## 5. 汇合时唯一维护的合同

| 合同 | 当前权威及接收方式 | 桌面后续只补什么 |
|---|---|---|
| 用户原输入、修订归属、派发指纹 | 执行修复维护；T01 记录修复提交的实际字段与反例 | 输入展示、身份来源和材料引用按真实入口接线，不重写用户正文 |
| input 接收与业务接受 | Session 维护持久输入事实，Weave 维护业务接受事实 | 查询与展示两种回执；重试保留原身份，提交未知先向原服务对账 |
| 运行身份与幂等 | Weave 业务入口及既有回执 | 连接切换不能把旧操作提交到新实例，不换新键自动重派发 |
| 执行、交付核验、用户接受 | 执行修复后的产品领域记录 | 忠实显示各维度，不把引擎正常结束映射为交付通过 |
| 取消、预算、恢复与副作用 | 引擎/Weave 执行机制及具体命令回执 | 精确定位 run；保留请求与结果；关窗或停前台不冒充停止业务 |
| 账号政策、设备会话和材料权限 | 后续应用层接入任务，在已稳定执行入口之上交付 | 当前权限检查贯穿入口；不把 cookie、桌面配置写入通用执行内核 |

若缺少必需字段，提交“具体用户动作、现有响应、缺少事实、最小增量、回归样例”后在集成阶段同仓修改生产者与消费者。双方不各自新增一套回执或状态定义。

## 6. 分支与运行隔离

- 当前主工作区保持原分支，本任务所有后续写入、安装和命令显式使用上方独立工作目录；不在主工作区 checkout、stash、reset、clean 或批量暂存。
- 当前计划分支承载上述工作，按 T01、T02 等提交；只有确有独立实现工作才再创建子分支。避免预建大量空分支并维护多份变化基线。
- 并行期提交遵守第 2 节范围。每次提交检查 `git diff --name-only` 和暂存差异；共享接缝即使容易改，也转入 T05 之后的顺序集成。
- 修复产生稳定提交后，先核对本地变更清单与合同差异，在本 worktree 合入该确切提交；不切换或修改修复所在工作区。新依赖锁基于合入结果由固定 pnpm 重算，不手工选一边覆盖。合并不能自动解决语义不一致。
- 不重启、升级或停止现有 Weave、Workbench、Runtime、数据库及验收进程；不复用原测试账号、Session、run、浏览器会话或材料目录。
- 小样使用系统分配空闲端口、专属临时数据目录和日志；后续集成用独立 TEST_DATABASE_URL、专属容器项目与卷。清理只删本任务登记且已无需保留的临时资源，证据与其他任务资源保留。
- 本计划不推送、合并 main 或部署。达到相应任务出口后，再按实际交付范围推进；不得将安装小样报告为多人产品可用。
