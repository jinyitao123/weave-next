# Workbench 桌面接入与账号体系实施验收计划

日期：2026-09-08  
版本：v0.1  
状态：计划与设计核对；所有实现工作包及运行验收尚未执行。

本计划配套[产品技术方案](../架构/2026-09-08-Workbench桌面接入与账号体系产品技术方案.md)，只覆盖本次桌面接入、账号和必要的工作台调整，不重写团队构建、Loom、工作流或业务恢复机制。

## 1. 分两层推进

完整首期目标是一个受控组织内的具名用户，可以安装桌面应用、默认连接服务、登录、提交材料并完成一次真实任务；换设备继续访问同一份已持久工作，切换服务保持身份和数据隔离。

最先实施的窄范围是 M0 的两账号 Host 隔离验证与接口冻结。它的意义是排除最贵的错误路径，不能用静态设计评审替代。M0 后进入 M1 账号型 Web，再进入 M2 桌面首发。M2 所有出口通过才算完成首期。

| 阶段 | 可检查结果 | 完成出口 | 失败后的动作 |
|---|---|---|---|
| M0. 接缝与风险验证 | 两用户隔离 Host 小样、动态身份调用桥小样、桌面框架同页对照、接口与授权清单 | 能证明用户 A/B 的 HTTP、MCP、文件和配置不共用权限；选定一种桌面框架 | 任一跨账号访问成立，停止多用户切入并修正隔离边界；不能缩成“先加登录页”发布 |
| M1. 账号型 Web | 默认 HTTPS 入口、真实账号登录、设备会话、两个用户 Host、材料与成果路径、管理员必要设置 | 两账号分别完成 Web 业务闭环；撤销与异常用例通过 | 保持旧部署可恢复，新入口不切为正式；根据失败层修复 |
| M2. 桌面首发 | 一个指定平台可安装、可更新的应用；默认连接、自建切换、登录、材料上传、成果下载 | 在干净设备完成安装到交付；升级保留连接；双设备/双服务用例通过 | 桌面不标记可交付；Web 中间结果可单独记录 |
| M3. 后续扩展 | 其他平台、受管连接、更多组织、邀请/SSO、按需 Host、本机 Runtime | 每个增量有独立业务出口 | 不影响 M1/M2 的清晰边界 |

## 2. 工作包与依赖

### P0. 冻结事实与接口

输入为当前 checkout、部署记录、现有用户/组织模型、Session 与 MCP 接口。输出：

- 对公开、内部和 Host 所有路由分类，列出首页、RPC、WebSocket、事件结果回传、上传、下载、导出、设置和目录入口。
- 区分 tenant 工作区与目录型 workspace，冻结映射对象及其服务端所有者。
- 列出已有角色/成员控制和空缺，逐项映射产品权限矩阵。
- 冻结服务描述、设备会话、HostDirectory、WeaveConnection 契约、错误码及迁移策略。
- 对照服务端部署 worktree 和当前 main，明确实施基线及合入关系；不在脏工作树中混入其他任务变更。

完成判据：每个用户可达入口都有身份来源、授权位置、数据归属和失败响应；新旧认证模式的适用路径明确。只画架构图不算完成。

### P1. 两账号隔离与身份桥小样

启动 A/B 两个隔离容器与独立数据卷，复用当前 Workbench profile。通过受控代理让两者各自以目标用户访问同一测试 Weave，不在容器中注入共用管理员 key。

至少验证：对话读取、目录选择、附件读取、模型配置、一次只读 MCP、一次可撤销的业务写操作。A 的凭据失效时，A 的 HTTP/MCP 都失败，B 保持正常；不得重新落到全局 API key。

测量 Host 冷启动、空闲内存、活跃内存和双设备同时登录的单 Host 写者归属。验证后台任务投影所需的只读授权与前台动作授权不同。

停止规则：若只能通过共享管理员 key、共享数据卷或模型提示词来维持可用，小样失败。若隔离 Host 的资源开销超过目标服务器预算，先调整常驻用户上限或基础设施，不先引入复杂多进程共享状态优化。

### P2. 账号与设备会话

依赖 P0。复用现有用户表，增加 opaque cookie 会话、登录/退出/续期/设备撤销接口及账号管理的必要 UI。

必须包含：登录错误的统一响应、账号与来源维度的失败节流、首管理员的原子引导、管理员重置密码、角色变更即时判定、密码修改与会话撤销、CSRF、可信代理和长连接撤销。

已有 JWT/API key 中间件继续用于对应旧路由。新账号入口不得接受 API key 操作“我的设备”或修改个人密码。会话 store 不可用时受保护操作失败关闭，不跳过认证。

完成判据：A01–A07 通过，并且错误码能映射到具体用户动作。

### P3. Host 接入层与数据归属

依赖 P1/P2。实现 HostDirectory、服务端主体路由、唯一租约、独立卷、启动故障和可观测性。Host 创建幂等；并发登录不启动两个写者。

对话继续复用当前存储 provider，在应用层建立 ownership 和项目映射。保护冷读、日志导出、搜索、下载、所有 RPC 和流订阅，修正“本地目录”展示为真实所在位置。

试点先常驻，不立刻实现空闲自动休眠。升级、故障重启与历史恢复要验证同一逻辑 Host 的运行身份和目录保持稳定。

完成判据：I01–I06 通过；重启不串用户、不重复写入、不重复派发。

### P4. WeaveConnection、MCP 与模型接线

依赖 P1/P3。给现有 workbench-app、weaveclient 和 MCP 提供统一的主体、实例与凭据获取方式。明确用户请求、已接受的 turn、后台只读观察三种授权的期限与用途。

保留已有业务命令的目标确认和幂等字段。每个敏感写操作重新读取权限，不用模型输出或前端按钮状态做授权。

组织监督模型由管理员配置，用户 Host 获得受控模型能力；个人显示偏好保持私有。通用 settings 不能成为修改其他账号或组织凭据的旁路。

完成判据：A04/A06、I03、B01/B03 通过；操作审计中的实际 actor 与当前用户一致。

### P5. 材料与成果

依赖 P3/P4。先盘点已存在的附件、项目资源和成果 endpoint，复用能满足归属和持久性的部分，再补上传状态、权限、摘要与任务引用。

首期规定文件大小和数量上限，超限可见且可恢复。重试保持原上传操作身份；未完成上传不能进入派发输入。成果打开与下载必须校验目标 run 和文件归属。

完成判据：B01/B02/B05 通过，包括下载后真实文件打开。不同操作系统的本地路径不能被当成远端路径使用。

### P6. 桌面小样与正式包装

小样可与 P2 的独立工作并行，但依赖 P0 的连接契约。对 Electron/Tauri 各加载同一页面，比较冷启动、输入法、长对话流式显示、文件上传、下载、重连和安装。记录包体、内存和版本；不以“理论更轻”决定选型。

正式实现只选一种框架。包含打包默认服务、连接偏好、独立持久会话分区、无凭据服务识别、窗口与外链控制、下载、错误页、版本兼容和签名更新。远程页面不获得 shell 或任意文件 API。

完成判据：C01–C08、D01–D05 通过。没有对应平台真机结果时，仅报告该平台未验收，不能从 macOS 推定 Windows 成功。

### P7. 发布与迁移

依赖 M1 完整通过和 P6 正式包装。取得实际可用的域名/HTTPS、桌面签名与发行配置，准备旧数据归属清单、备份、恢复演练和回退窗口。

部署健康检查升级为能发现“登录成功但 Host 无法启动”“Host 启动但模型不可用”“API 可用但 MCP 主体错误”的探针。将兼容矩阵加入服务器发布流程；桌面稳定版不跟随每次 main 提交自动强制更新。

完成判据：R01–R04 与全部首期必测通过，并保存精确的安装包、服务端、Host 和 Runtime 版本。

## 3. 详细验收用例

以下全部是计划用例，初始状态为未执行。执行时填入证据路径、版本、时间、操作者与实际结果，不能只填写 PASS。

| ID | 场景与操作 | 预期结果 |
|---|---|---|
| A01 | 使用现有账号首次登录，重启客户端 | 账号与组织准确；有效期内恢复登录，无手工 key 输入 |
| A02 | 密码错误、不存在账号、连续失败、账号禁用 | 有限且一致的错误提示；节流有效；不创建 Host 或泄露账号细节 |
| A03 | 续期与并发多标签续期，模拟响应丢失 | 不产生跨账号会话、不无限续期；能够按设计恢复或明确重新登录 |
| A04 | A 的设备 1 退出，设备 2 保持登录 | 设备 1 请求及流在承诺时间内失效；设备 2 正常；旧 cookie 重放无效 |
| A05 | 修改密码、管理员重置、删除/禁用账号 | 撤销范围符合明确规则；旧登录与旧长期连接不能继续操作 |
| A06 | 移除成员或降权，随后从 UI/MCP/直接 API 操作 | 三条路径使用最新权限，拒绝相同的未授权行为 |
| A07 | 伪造内部身份头、跨站写请求、无 cookie 调 RPC/WS/下载 | 不能绕过登录/归属检查；日志无原始凭据 |
| I01 | A/B 同一服务登录，各建对话并重启 Host | 历史只在正确账号可见，B 不能猜 session_id 读取 A |
| I02 | A/B 为不同 tenant，使用同名项目/对话 | 数据、模型设置、节点和任务不按名称混合 |
| I03 | A/B 修改个人偏好、尝试组织配置和凭据读取 | 个人偏好私有；组织管理权限真实执行；错误提示不泄露密钥 |
| I04 | 猜附件、导出、搜索、流订阅、冷历史和目录路径 | 所有访问遵循主体和资源归属；服务器任意目录不可见 |
| I05 | 同账号两设备并发进入、并发发送同一操作 | 一个 Host 写者；幂等操作仅一次；冲突不静默丢失 |
| I06 | Host 进程崩溃或升级后恢复 | 已持久对话和任务绑定恢复；不重发已有运行；未确认写操作可对账 |
| C01 | 干净安装且没有连接偏好 | 自动使用发行包默认服务；正常进入登录 |
| C02 | 改用自建服务，重启并安装新版本 | 始终使用用户选择；不恢复成产品默认 |
| C03 | 从 A 服务切到 B，延迟 A 的请求/事件响应 | B 页面不出现 A 数据；A 凭据不发给 B；A 运行仍保留 |
| C04 | B 失败/取消切换、原服务不可用 | 选择提交规则一致；不自动跳转其他服务；可恢复操作 |
| C05 | 同一 origin 的 instance_id 改变或版本不兼容 | 识别部署/契约变化，不混用旧会话；提示重新连接或升级 |
| C06 | 错误地址、非 Weave 服务、跨域重定向、证书错误 | 不发送密码给未确认目标，不忽略证书错误，不打开任意更新包 |
| C07 | 断网后恢复，最后一个派发响应丢失 | 原幂等键对账，仅产生一个运行；页面说明不确定窗口 |
| C08 | 同机退出 A 后登录 B，再打开最近项目或系统通知 | 无 A 的私有内容、草稿和最近文件泄漏；已主动下载文件按明确本机保留规则处理 |
| B01 | 管理员准备监督模型、团队和节点；成员上传真实材料并派发 | 当前成员身份正确；材料摘要一致；Runtime 实际开始执行 |
| B02 | 关闭桌面应用，另一设备登录并打开同一任务 | 已接受运行继续；持久对话可见；不创建副本运行 |
| B03 | 人工等待，用户在工作对话答复；再测试有权限的停止或恢复 | 命令目标、权限和回执正确；请求状态与生效状态分别呈现 |
| B04 | 无模型、无节点、节点满载、能力不匹配 | 登录仍可用，依赖动作有准确阻断原因；“在线”不冒充可执行 |
| B05 | 任务终态后查看交付、下载成果并打开 | 确认最终成果属于该 run；文件内容可用；缺成果时不显示完整交付成功 |
| D01 | 在干净试点设备安装，首次启动、中文输入和长对话 | 品牌、窗口、输入与流式显示正常；无开发服务依赖 |
| D02 | 升级已安装版本；升级后保留自建地址和可恢复登录 | 签名正确，数据归属不变，不覆盖用户偏好 |
| D03 | 错误签名/不兼容更新与服务器升级 | 拒绝不可信安装包；保留当前可运行应用；给出可操作提示 |
| D04 | 上传/下载取消、重名文件、目标目录无写权限 | 正确提示，重试可用，不把未保存结果标为成功 |
| D05 | 远程页尝试调用任意 IPC/打开危险协议/访问本机文件 | 桌面能力白名单生效；新窗口和外链按固定规则处理 |
| R01 | 从旧单 Host 数据副本迁移一个具名用户 | 会话数、任务引用、材料和成果关系可核对；其他账号看不到旧私有数据 |
| R02 | 迁移后故障与回退演练 | 无双写；备份可恢复；明确回退数据时间边界及未迁移增量 |
| R03 | 5 个试点账号冷/热启动并发测试 | 记录资源与时延；未超过预先设定的容量；无串用户 |
| R04 | 在受支持的旧桌面版本下升级中心服务/Host | 登录、会话、派发、事件与下载兼容；不支持时明确阻断 |

真实业务材料优先使用独立、可核对输入和成果的限定样本。可从已有日冕材料选取一个有限子任务，但不自动沿用历史运行或把历史整个场景的未完成验收带入本次完成结论。

## 4. 工程检查与证据

代码实现时执行仓库指定检查：Go 改动使用 make test；数据库集成明确设置 TEST_DATABASE_URL；分层使用 make depguard；产品边界使用 make productguard；Workbench 使用根目录 make workbench-install workbench-check。Compose 改动使用 make compose-check，并补真实部署验证。

涉及登录页面、Connection/Gateway、事件流和组装 UI 的变化，按 Workbench AGENTS 执行对应 GUI 与真实组装浏览器检查。仅修改文档的本次工作只检查文档结构、引用与仓库边界，不运行整个业务测试套件，也不据此宣称运行链路通过。

每次真实验收保存：

- 软件身份：代码 SHA、镜像 digest、桌面版本及安装包摘要、Runtime 版本。
- 场景身份：服务 instance、账号代号、组织、对话、run 和操作幂等键；凭据以脱敏占位符处理。
- 用户证据：真实页面状态、关键操作录屏或截图、下载后可打开的成果。
- 系统证据：相同动作的请求/事件/审计关联和最终资源状态，不靠页面提示自证。
- 用例回执：预期、实际、是否通过、残余问题及影响范围。

## 5. 暂定性能与容量目标

这些是试点目标，尚未实测；M0 记录设备、网络和服务器规格后冻结。超出目标时先定位网络、Host 冷启动或模型依赖，不在 UI 中隐藏等待。

| 项目 | 初始目标 |
|---|---|
| 已登录热启动 | 在正常测试网络下，从客户端窗口出现到可交互历史 p95 ≤ 3 秒，不含一次新的模型生成 |
| 新 Host 冷启动 | p95 ≤ 15 秒；超出时显示真实准备进度与重试出口 |
| 账号权限撤销 | 新命令立即核验；旧事件流 ≤ 10 秒断开 |
| 服务探测失败 | ≤ 10 秒出现明确失败和操作入口，允许用户主动重试 |
| 并发容量 | 首次以 5 个具名账号测量；总常驻开销应保留至少 30% 服务器内存余量，实际上限由数据决定 |
| 业务正确性 | 跨账号/跨服务泄漏为零；不确定请求重试的重复派发为零 |

不预先承诺包体积或每用户运行成本。两种桌面小样与 Host 实测后再记录数字。

## 6. 工作量判断

主要工作量集中在账号 Host 隔离、主体贯穿 MCP/后台路径和数据迁移，桌面外壳通常不占最大部分。

以熟悉仓库的工程师、一个组织、少量具名用户、一个桌面平台、现有用户表和运行机制可复用为假设，初步估算约 35–60 工程人日。它是便于比较范围的规划量级，不是当前证据支持的交付承诺，也不应简单按并行人数相除得到日历工期。

| 工作组 | 粗估人日 |
|---|---|
| 现状清单、接口冻结与 M0 小样 | 4–6 |
| 账号会话、权限与管理入口 | 5–8 |
| Host 隔离、租约、恢复及主体调用桥 | 10–17 |
| 材料、成果、模型默认与就绪体验 | 4–7 |
| 桌面包装、连接设置及更新 | 5–9 |
| 部署迁移、真实验收与修复 | 7–13 |

估算不包括开放注册/邮件系统、SSO、计费、全平台签名、本地 Runtime 自动安装、多组织账号合并或新业务恢复引擎。M0 完成后按实际接缝调整估算，保留原估算与调整原因。

|---|---|---|---|
| D01 | 默认采用远程 Host 的桌面客户端 | 现有部署与跨设备、关窗继续的目标一致 | 若必须直接处理本机项目，重新评估本地 Host |
| D02 | 首期一个组织、管理员创建具名账号 | 现有账号是 tenant 内身份；减少全局身份改造 | 首批用户数量与组织边界 |
| D03 | 一个 user × workspace 对应一个隔离 Host | 现有 Session/配置/工具围绕 Host 组织 | 资源成本、租约恢复和所有旁路隔离 |
| D04 | 第一方 Web cookie 登录，原生 OAuth 留后续 | 薄客户端不需要原生长期 API token | 企业 SSO 若成为首发要求则改变依赖 |
| D05 | Electron 暂作首选，单次同页小样对照后定型 | 当前 TS/UI 复用与交互一致性 | 实测；框架版本在实施时固定 |
| D06 | 暂以 macOS Apple Silicon 作试点 | 当前用户设备背景，仅是计划假设 | 实际首发平台；Windows 优先时直接改矩阵 |
| D07 | 正式版使用稳定 HTTPS 域名 | 默认地址是长期用户契约 | 实际域名、解析、证书与发布签名材料 |
| D08 | 产品默认服务与自建服务均支持，切换不搬数据 | 用户明确提出可显式改连接 | 首期是否需保存多个服务，默认只保留活动选择 |

这些待定项已经给出本版工作假设，可以支持方案评审和 M0 准备；涉及真实域名、发行签名或目标平台的正式交付在相应阶段需要实际输入。无需为了讨论方案先索取秘密或改变生产配置。

## 8. 三个视角的设计自审

本节是本次作者根据源码进行的设计自审，不是独立子 Agent 互审，也不是已执行测试。后续独立评审应保留原意见与逐项采纳记录，修改文档版本。

| 视角 | 发现的问题 | 本版处理 | 仍开放的层 |
|---|---|---|---|
| 产品 | “安装登录即可用”可能只连上后台，前台模型/任务节点尚不可用 | 将监督模型、材料和具体派发可行性纳入首期 | 实际部署配置与任务交付 |
| 产品 | “工作区”同时表示组织和服务器目录 | 明确组织工作区、项目、工作目录三层 | 现有界面文案及所有目录交互待改 |
| 产品 | 关窗、退出账号、停止任务容易混同 | 分别定义客户端会话与业务运行行为 | 未确认写操作和关窗中的 turn 需验证 |
| 工程 | 只在首页加登录仍能通过 RPC/WS/文件入口访问 Host | 统一入口与所有路由清单，Host 固定归属 | 逐入口反例验证 |
| 工程 | 全局 apiKey 闭包与 MCP 环境变量无法支持用户撤销和切换 | 引入主体连接 provider/内部调用桥，三条路径一致 | 动态授权小样与实际 actor 审计 |
| 工程 | 用用户目录前缀当隔离仍共享工具和进程能力 | 首期容器、卷和凭据隔离，禁共享特权资源 | Host 插件能力清单及逃逸旁路审视 |
| 工程 | 为账号化重写所有 Session 存储会扩大范围 | 沿用 provider，增加应用层归属与 Host 唯一写者 | 数据迁移和双设备并发 |
| 质量 | 登录、健康检查或任务 completed 不能证明完整产品 | 命名 A/I/C/B/D/R 用例，要求真实安装、材料与成果证据 | 全部运行验收未执行 |
| 质量 | 自动跟随 main 可能破坏已安装桌面 | 契约版本与稳定发行分离，兼容矩阵纳入部署 | 当前生产部署流程接入与旧客户端测试 |
| 质量 | 单用户试点可能掩盖隔离缺陷 | 首期至少两账号、两服务、两设备，加跨 tenant 反例 | 对应测试环境需准备 |

本版建议进入 M0，首先验证两账号隔离与实际调用主体；这两个接缝通过后，再按 P2–P7 推进。方案文件本身不构成任何实现或上线完成的证据。
