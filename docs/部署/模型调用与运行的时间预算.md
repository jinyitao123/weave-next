# 模型调用与运行的时间预算

本文写给配置成员和部署的开发者、部署管理员：Weave 里有哪几层时间上限，各从什么时候开始计时，谁先到谁生效，以及怎样按任务类型选择。实际生效的部署级数值可以在 `GET /v1/admin/metrics` 的 `timing` 中读回，`weave config-check` 也会在启动前列出。

## 各层上限

| 上限 | 配置 | 计时 | 到期后 | 缺省 |
|---|---|---|---|---|
| 等待首个输出 | 成员 `first_chunk_timeout_ms`（随发布冻结） | 从发起请求到第一个模型输出块；SSE 心跳、响应头不算输出 | 本次调用以 `stage_timeout`、`timeout_stage=first_chunk` 结束 | 0，不单独限制 |
| 输出间隔 | 成员 `idle_timeout_ms`（随发布冻结） | 每收到一个模型输出块后重新计时 | `timeout_stage=stream_idle` | 0 |
| 整次调用 | 成员 `call_timeout_ms`（随发布冻结） | 从发出请求到调用结束，持续输出也不重置 | `timeout_stage=total` | 0 |
| 单次供应方请求 | 供应方 `attempt_timeout_seconds`（现行配置，不随发布冻结） | 一次物理请求 | 请求失败 | 900 秒 |
| 成员单步 | 固定 45 分钟（`member_step_limit`） | 一个成员步骤，内含它的全部模型调用 | 步骤失败 | 固定 |
| 慢运行告警 | `WEAVE_HEALTH_SLOW_RUN_SECONDS` | 一次运行 | 只在健康统计中计为慢，**不会结束运行** | 600 秒 |
| 停机排空 | `WEAVE_TEAMRUN_DRAIN_TIMEOUT`（如 `30s`） | pooled 执行器收到停机信号后 | 不再等待在途工作 | 0，不等待 |

同时生效的上限，**最早到期的那个结束调用**。三项成员预算只作用于流式调用，从适配器开始发起请求（含建立连接）起计时；Weave 模型网关的排队发生在这之前，不计入，单独记录为 `gateway_wait_ms`。

## 保存时就拒绝的组合

这些组合中至少一个上限永远不会先到期，保存成员时直接拒绝：

- 首个输出或输出间隔上限大于等于整次调用上限；
- 任何一项大于等于成员单步上限 45 分钟（2,700,000 毫秒）；
- 命令行引擎成员设置任何一项（它的运行时自己发请求，设置不会生效）。

供应方单次请求超时不随发布冻结，发布后仍可修改，所以成员预算超过它时不在保存时拒绝；此时实际生效的是较短的供应方超时。

## 到期与取消

- 阶段预算到期、调用方取消都会在本地调用真正返回后才记录事件。`model_failed`（阶段到期）和 `model_cancelled` 带 `local_stopped: true` 与 `upstream_cancel: "unknown"`：放弃一个 HTTP 请求得不到供应方回执，上游是否停止生成无法确认。
- 阶段到期不自动重试、不换模型，因为被放弃的请求可能仍在生成；是否重试由调用方决定，重试会再计一次用量。
- 持续收到输出不能越过整次调用上限，也不能越过成员单步上限。

## 选择示例

| 场景 | 首个输出 | 输出间隔 | 整次调用 | 说明 |
|---|---|---|---|---|
| 实时交互（用户等待结果） | 30,000 | 15,000 | 60,000–120,000 | 思考型模型首字节前可能长时间无输出，首个输出上限过短会误杀正常思考 |
| 后台长任务 | 0 | 60,000 | 0 | 只防止流中长时间停顿，其余交给成员单步上限 |
| 不确定 | 0 | 0 | 0 | 保留缺省，先观察 `model_*` 活动中的 `phases_ms` 再设定 |

慢运行告警阈值应与任务目标匹配：交互部署可以调低 `WEAVE_HEALTH_SLOW_RUN_SECONDS` 让健康页尽早提示，它不会改变任何执行截止时间。
