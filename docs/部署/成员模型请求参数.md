# 成员模型请求参数

本文写给配置成员与模型供应方的开发者、部署管理员：成员可以为模型请求设置哪些参数，供应方如何声明每个模型接受哪些取值，什么时候会被拒绝，以及怎样确认参数确实发了出去。

## 成员可设置的参数

| 参数 | 成员配置字段 | 发到请求中的字段 | 未设置时 |
|---|---|---|---|
| 推理档位 | `reasoning_effort`：none/minimal/low/medium/high/xhigh/max | `reasoning_effort` | 不发送，由供应方默认 |
| 思考开关 | `thinking`：enabled/disabled | `thinking: {"type": ...}` | 不发送，由供应方默认 |
| 采样温度 | `temperature`：0–2 | `temperature` | 不发送 |
| 核采样 | `top_p`：0–1 | `top_p` | 不发送 |

- 这些设置随成员版本发布冻结，进入内容哈希；之后修改草稿或供应方不影响已发布版本和进行中的运行。
- 未设置与显式 0 不同：`temperature: 0` 会发送 0，留空则不发送。
- 设置会用于该成员的每一次模型调用：每一轮、工具预算用尽后的收尾调用、开启工具循环轮次的成员，以及配置的备用模型。
- 命令行引擎成员不使用这些设置（其运行时自己发请求），设置任一项都会在保存时拒绝。
- `thinking: disabled` 与非 none 的推理档位互相矛盾，保存时拒绝。

## 供应方按模型声明

供应方在“模型”页的高级选项（或 API 的 `model_parameters`）中按**确切的模型名**声明成员可以请求的取值：

```json
{
  "glm-5.3": {
    "reasoning_efforts": ["low", "high"],
    "thinking": ["enabled", "disabled"],
    "temperature": {"min": 0, "max": 1},
    "top_p": {"min": 0, "max": 1}
  }
}
```

- 列出的字段给出允许的取值或范围（含两端）；没有列出的字段不接受任何显式值。
- 声明随供应方版本冻结，并只进入所声明模型的绑定；没有声明的模型与此前完全一致，哈希不变。
- 只有 OpenAI 兼容协议的供应方可以声明；声明的模型必须在供应方的模型列表中。
- API 中省略 `model_parameters` 保留现有声明，传 `{}` 清除全部声明；从模型列表移除的模型连同声明一起移除。

Weave 不按模型名猜测参数，只按声明校验。

## 校验与拒绝

发布前，成员的设置会对照它会调用的**每个**模型（主模型和全部备用模型）的声明：

| 情况 | 结果 |
|---|---|
| 模型有声明，取值在声明内 | 通过 |
| 模型有声明，取值不在声明内，或该字段未声明 | 拒绝 |
| 模型没有声明，成员只设置了推理档位 | 通过（与声明出现之前一致，原样发送） |
| 模型没有声明，成员设置了思考开关、temperature 或 top_p | 拒绝 |
| 成员未选择模型（使用默认模型），设置了思考开关或采样参数 | 拒绝 |

拒绝在发布候选的校验结果中报告为 `workflow_agent_model_parameter_undeclared`，说明是哪个成员、哪个模型、哪项设置。参数不会被静默丢弃或改写。

## 确认实际发送

每次模型调用的 `model_completed` / `model_failed` / `model_cancelled` 活动带有 `request`，记录实际发出的受控字段：`reasoning_effort`、`thinking`，以及 `temperature`、`top_p` 是否发送（取值见成员冻结的配置）。OpenAI 兼容接口不回报供应方实际采用的档位或采样值，所以“已发送”不等于“已生效”，也不能用响应速度推断。
