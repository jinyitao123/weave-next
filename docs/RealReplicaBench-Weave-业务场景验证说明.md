# RealReplicaBench × Weave 业务场景验证说明

> 状态：当前执行核心的外部验证说明  
> 适用范围：多运行时、元团队升级、业务团队运行闭环

## 1. 定位

RealReplicaBench 在 Weave 中只承担一个职责：判断业务团队是否真的完成了业务任务。

它不是产品规格来源，不驱动新增页面、治理流程或验证基础设施。Weave 当前产品目标由 [Workbench 产品合同](./架构/2026-09-05-Weave-当前产品合同.md) 裁决。验证从 Workbench 的团队任务展开，不恢复独立业务 CLI 或其他客户端入口。

## 2. 验证对象

当前只验证三类事实：

- 已发布业务团队能否直接接收任务并完成工作；
- Runtime 是否真实领取和执行，而不是服务端伪造成功；
- 最终结果是否能被外部 verifier 或等价业务事实确认。

## 3. 最小业务场景

优先保留已经跑通过或接近跑通的 MCP 场景：

| 场景 | 验证重点 |
|---|---|
| `api-gmail-invoice-hold-mcp` | 邮件和日历状态修改 |
| `api-gmail-vendor-brief-mcp` | 多对象读取、筛选、写回 |
| `api-google-docs-price-list-update-mcp` | 文档读取、修改和回读 |
| `api-google-docs-supplier-risk-rollup-mcp` | 多文档证据整理和最终文档产出 |

如果一个场景不能证明业务团队实际产出，就不进入当前阶段。

## 4. 运行原则

- 使用已发布团队版本，不在普通任务中重新调用元团队。
- 使用真实 Runtime 领取任务，并记录 Runtime、engine、TeamRun 和交付物位置。
- 允许团队在静态授权范围内写入 Mock MCP 或产出文件。
- 以 verifier 结果、外部系统状态或可读取交付物作为结论。
- 不把 benchmark 数据、grader、客户业务词或私有 fixture 写入 `internal/`。

## 5. 当前证据边界

以下是既有执行核心证据的适用范围，不代表当前 Workbench 版本已完成业务验收：

- Codex Runtime 能执行长链业务任务；
- 业务团队能产生分工、执行、复核和交付；
- 元团队能创建团队、成员和声明式工作流；
- Gmail、Calendar、Google Docs 类 Mock MCP 出现过真实状态变化；
- 部分运行被原始 verifier 判定通过。

这些证据证明方向可行，但不证明系统稳定。下一阶段只围绕真实业务场景暴露的问题修复，不为假想治理场景扩建能力。

## 6. 结论标准

一次验证只回答四个问题：

1. 任务由哪个已发布团队版本接收？
2. 哪些 Runtime 实际执行了哪些工作？
3. 最终交付物或外部状态在哪里？
4. 外部事实是否判定业务完成？

回答不了这四个问题，就视为产品主链仍未闭合。
