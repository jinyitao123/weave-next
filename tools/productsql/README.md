# 产品表访问边界

`make depguard` 同时检查 Base/Kernel 对产品表的直接引用。组织、用户、项目、对话、可变 Agent 目录、团队构建记录和发布申请由 Server 持有，执行侧通过显式端口或冻结输入取得事实。

扫描使用 Go AST 读取所有生产 `.go` 文件的字符串字面量，包括当前机器不编译的目标平台文件；排除注释和 `_test.go` 验收材料。它是源代码依赖检查，不执行数据库查询，也不代替迁移的表所有权审查。

`baseline.json` 只记录尚未迁走的历史耦合。新文件、新表或引用数量增加都会失败；消除引用后也必须同步降低基线，不保留可重新使用的额度。不可通过扩大基线引入新的业务依赖。产品源码、查询拼接和数据库迁移仍需代码审查。

```sh
go test ./tools/productsql
go run ./tools/productsql -inventory
make depguard
```

完成一个迁移批次后，审查输出并仅删除或降低已解决项。最终物理分仓前，Kernel 的此项清单应为空；当前清单不代表 Kernel 已完成独立存储边界。
