# Agent Note：Weave 商业内测提供就绪状态与结果证据

状态：已实现

[English](2026-09-01-weave-commercial-pilot-readiness.md) | 中文

## 问题

Workbench 能在任务派发后持续托管并纠偏 Weave 任务，但首次用户在派发前没有一个基于真实事实判断宿主凭据、服务、团队和运行时是否就绪的产品界面。完成的工作也缺少轻量用户判断，因此试点只能统计技术成功，无法判断交付物是否真正被采用。

## 决策

Workbench 宿主提供两个经过浏览器会话认证的精确 Fetch 路由。`/api/weave.status` 使用仅宿主可见的 API Key 探测 Weave，并且只返回有界的就绪事实，包括服务版本、授权结果、可派发团队数量、可用运行时数量和每项检查状态。`/api/weave.pilot-report` 从持久 `workTask` 投影生成不含秘密的 JSON 报告，覆盖完成情况、耗时、已记录成本和 token、纠偏次数、重跑次数、最终交付物数量和用户给出的交付判断。

Weave 设置页展示同一组就绪事实和四步首次使用路径。浏览器保存一次性引导确认，但不保存凭据。具有最终交付物的已完成任务接受 `adopted` 或 `needs-revision` 判断和一段有界备注；人类命令追加完整工作任务状态，不调用模型。报告不包含任务原文、运行标识、请求标识、凭据、运行时标识或宿主路径。

Weave 继续拥有执行用量事实。精确运行活动接口投影已有终态用量和开始结束时间，Workbench 把这些字段写入任务，不估算成本。用量缺失或不完整时，活动完整性映射会如实保留这一状态。

所有终态尝试都可以修订后启动新的 run，包括失败和已完成的交付。旧尝试继续保留在历史中，新 run 从空白执行事实开始；终态、成员、交付物、纠偏、时间与用量不会跨 run 串入。外部成员仍在执行的 fanout 等待任务也会显示与直接运行状态相同的纠偏入口。Weave 持久记录该纠偏，并在下一个工作流边界生成影响计划。

## 考虑过的替代方案

**增加独立分析服务。** 未采用，因为设计伙伴试点只需要基于现有持久事实的有界导出，不需要新的采集、仪表盘、身份和保留周期。

**把运行成功视为交付质量。** 未采用，因为成功终态只能证明工作流结束。轻量用户判断可以记录结果是否进入真实工作，同时不会让评测重新成为发布门禁。

**把 Weave API Key 发送给浏览器。** 未采用，因为浏览器需要的是状态而不是凭据。经过认证的 Workbench 宿主完成所有 Weave 探测，只返回不含秘密的投影。

## 后果

首次用户可以在开始工作前识别连接、授权、团队工作流或运行时缺失，并在同一产品下载试点评审报告。报告是运营证据，不是计费级计量或自动质量评分。会话导出、会话删除、交付物下载和单组织部署控制继续构成本版本的数据管理边界；公共多租户保留策略和计费仍不属于 Workbench 试点范围。
