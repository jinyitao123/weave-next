# Agent Note: Weave 工作任务展示可观察运行时、工具事实与文件

Status: implemented

[English](2026-09-01-weave-observed-work-files.md) | 中文

## 问题

Workbench 已经可以托管持久 Weave run，但可见工作现场仍削弱了产品承诺。运行时 UUID 让用户看不出成员在哪里执行，外置 Codex 工作结束后仍显示零次工具调用，最终消息即使列出 CSV 或 JSON 路径，浏览器也无法查看或下载。若浏览器直接解析任意宿主路径，界面看似完整，实际绕开了 Weave 所有权，而且远程运行时下必然失效。

## 决定

Weave 继续拥有执行事实与文件。现有只追加 run 活动账本接收从 Codex JSONL 解析出的受限工具开始与完成事实，其中包含受限输入输出预览。服务端在远端结果解码边界就把每个物理 attempt 的事件经当前执行上下文送入团队运行，避免更高层结果汇总丢失 attempt 明细；受限终态结果仍作为回退。运行活动把冻结的引擎、提供方、模型事实与注册运行时显示名称关联起来。Workbench 只投影这些可观察事实，不从正文推断工具，也不会用猜测填补缺失事实。

CLI 员工通过把受支持的 UTF-8 格式写入保留的 `outputs/` 目录来发布文件。运行时在每次调用前为合格文件建立快照，只返回新建、重写或内容发生变化的文件，边界为最多十二个文件、单文件 256 KiB、合计 512 KiB。符号链接、路径穿越、宿主路径、不支持的二进制格式、未被触碰的陈旧文件与超限文件都会被排除。Weave 把每个返回文件按相对文件名与内容类型保存为绑定精确 run 的不可变交付物。只有完整受限正文存在时，Workbench 才提供预览与浏览器下载。

宿主 `workTask` 投影拥有浏览器端的持久副本。它记录下载所需的受限文件正文、实名运行时与工具输入输出预览。投影模式版本递增，使恢复的 Session 重放权威事件，不保留旧的仅路径形态。`team_create` MCP 模式也让 YAML 在结构上必须同时携带声明式工作流，避免模型反复提交不完整团队定义。

## 考虑过的替代方案

**解析最终答案中打印的路径。** 否决，因为路径可能属于另一台主机或远程运行时，让浏览器访问任意路径也会在 Weave 交付物账本之外创建新的安全边界。

**增加通用文件浏览器或制品服务。** 否决，因为当前产品只需要工作任务明确产出的文件。受限保留目录可以完成这份合同，无需引入存储 API、上传会话或第二套文件生命周期。

**实时流式传送全部 CLI 事件。** 暂缓，因为终态的可观察工具事实已经补上信任缺口，并能复用只追加活动合同。实时流会增加背压、重连、排序与保留语义，而首期产品主链不需要这些复杂度。

## 后果

用户可以识别每个成员的真实运行时与引擎，查看真实 Codex 工具活动，并在完成后预览或下载真实 CSV、JSON、Markdown、YAML、HTML、SVG、TSV 与文本输出。边界让运行时结果负载与 Session 投影保持有限，代价是排除二进制、超限、未被触碰或不在 `outputs/` 下的文件。工具输入输出只是受限观察，可能不完整；界面只陈述 Weave 实际记录的内容。测试固定 Codex 事件归一化、物理 attempt 事件投影、陈旧文件排除、同内容重写、投影兼容与组装后的浏览器流程。
