# Agent Note: 冷任务列表恢复

Status: implemented

[English](2026-09-05-cold-task-list-recovery.md) | 中文

## 问题

投影版本变化会使持久缓存行失效。冷 Session 即使已有有效的非空白元数据，也可能在侧栏一直缺少任务状态和团队，直到有人打开会话。项目汇总也会省略该任务，却没有标明缺少观察结果。

## 决策

领域通过 `wire.list: true` 声明列表所需的值。这样的值不可用时，Session Controller 在配置的字节上限内观察冷日志。Workbench profile 使用 4 MiB 上限。进程本地观察按注册版本和物理源标识复用；无关 wire 键不会触发完整读取。观察不激活 Agent、不调用模型，也不会把潜在的未提交恢复事件写入持久投影缓存。

有界观察无法恢复的键会在列表中明确标为不可用。已计算的 null 仍是正常值。Client 收到更新的投影后移除未知标记，迟到的列表响应不会把它恢复。侧栏提示记录仍待读取，项目活动报告观察不完整。打开会话仍沿用既有完整读取路径。

## 考虑过的替代方案

读取旧状态版本可能误报已经变化的任务语义。无界列表读取可能让一个大日志阻塞导航。把所有缺失 wire 键都当作重新计算的理由，会反复读取无关状态。因此拒绝这些方案。

## 影响

较小的冷任务会自动恢复到列表。大记录或不可读记录仍然可见，并明确标为未知。回归覆盖版本失效、重复列表读取、null 值、超限记录、声明卸载、推送与列表竞态，以及项目的不完整提示。真实 Workbench 刷新仍是已发布 profile 的集成验收。
