# Agent Note：紧凑模型强度滑杆

Status: implemented

[English](2026-09-04-model-effort-slider.md) | 中文

## 问题

composer 通过第二层单选列表提供推理强度。用户要先打开模型控件、选择强度行、理解六个纯文字选项；每次选择成功后弹层还会关闭，继续比较时必须重新打开。交互在技术上可用，却没有把当前等级、相对尺度与快速调整组织成一项连贯的模型设置。

## 决策

composer 模型触发器现在打开一个紧凑概览。摘要行同时显示当前模型和本地化后的标准强度名称，并可进入按提供方分组的模型列表。两个层级保持同一张卡片宽度，模型选择成功后返回概览，不会关闭卡片。当确切模型公布推理元数据时，概览会把这些等级呈现为原生离散 range 输入，底部轨道显示已填充区和与已公布等级逐一对应的刻度。指针移动会立即更新本地草稿值，松开时才通过完整会话选择持久化，过程中不会让弹层变淡或关闭；被拒绝的修改继续使用既有 toast 路径，并恢复已经生效的值。

滑杆的等级与默认值只来自宿主报告的模型元数据。它不会虚构模型不支持的强度，没有推理元数据的模型也不显示滑杆。原生 range 输入负责方向键和辅助技术所需的 slider 语义；外围弹层使用 dialog，只有进入后的模型列表使用 menu 角色。标准强度标识会转换成本地化名称，未知的适配器自有名称保持原样。

## 曾考虑的替代方案

**只美化单选列表。** 不采用，因为改善间距无法减少额外导航，也无法表达强度值是一组有序等级。

**使用连续数值滑杆。** 不采用，因为提供方接受具名离散等级，而非任意数值；插值会向用户展示所选模型无法服务的取值。

**把永久滑杆放进 composer 工具栏。** 不采用，因为不常调整的设置会长期占用主要输入空间，还会让人误以为所有模型都支持推理等级。

**每次移动滑杆后关闭弹层。** 不采用，因为这会提高比较成本，让直接操作重新退化成反复打开菜单。

## 后果

当前模型与强度会一起显示，一次点击即可看到完整尺度，调整始终留在一张稳定卡片里。控件保留键盘可访问性、尊重减少动态效果偏好，并使用明暗主题 token。提供方元数据仍决定完整可选词表与请求值，因此这次视觉精修不会改变模型路由合同。
