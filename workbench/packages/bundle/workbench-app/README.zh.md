# `@deepseek-ai/dsh-workbench-app`

[English](README.md) | 中文

## 概述

本组合包在不修改 agent loop 的前提下，把通用 DSH Web 运行时变成 Weave Workbench。它加入 Workbench 浏览器身份，在业务 API key 存在时连接本地 `weave mcp serve` 进程，并给前台 agent 一条产品规则：派活前先匹配已有团队；如果没有合适团队，就如实说明并协助定义团队。宿主侧 WorkTask 投影会记录派发，并在前台回合结束后继续同步 Weave 状态。同一个已认证宿主会向 Workbench 主界面提供受限的运行节点注册表。派发成功的 Weave 运行就是持久任务；前台 agent 不再创建影子 DSH 目标、轮询到结束或保存重复交付物。

运行尚未创建时，创建调用先保存独立准备记录。明确的模板失败在再次读取目录后仍然保留，网络错误保持结果未确认。构建编号和服务端更新时间隔离晚到进度；已结束运行后的新创建保留旧尝试记录。导航、任务卡和项目进展读取同一展示状态，区分停止请求、并行执行、定时等待、缺少成果与运行中断。选队不代表派发授权；用户明确要求先创建后确认派发时，继续通过既有提问或方案审阅流程处理分别确认。

## 使用本包

运行 `dsh --profile workbench`，或使用仓库快捷命令 `pnpm workbench`。快捷命令优先使用显式 `WEAVE_API_KEY`，随后检查 macOS 钥匙串服务 `weave-workbench-api-key`；其他平台使用显式环境值。随附 profile 依次叠加 `dsh-base`、`dsh-web-app` 和本组合包。存在 key 时，本组合包通过 stdio 启动 `weave mcp serve`，并把工具发布到 `mcp__weave__*` 命名空间。本地 Workbench 默认把 `WEAVE_API_URL` 设为 `http://127.0.0.1:18080`，`WEAVE_COMMAND` 可以选择另一个受信任的本地二进制。Workbench 不创建兜底工作区：首次使用者必须先选择一个明确的项目目录再开始会话，使项目的团队任务与材料产出始终有可见的文件系统边界。Workbench 不继承 DSH 原生 DeepSeek 适配器与官方默认模型；新会话开始运行前，模型页面中必须已经保存一个提供方和模型。

缺少 `WEAVE_API_KEY` 时，MCP 配置项会被禁用，但浏览器仍能启动。这样前台运行时仍可使用，同时连接缺失不会被伪装；agent 会被要求在工具不可用时不得声称已经完成团队工作。

Host 为固定已发布工作流注册 `weave_dispatch`，模型参数仅包含已商定的团队、工作流与可选项目。Host 在 Session 日志中冻结尚未消费的用户原始消息，再向 Weave 注册不可变输入修订。界面生成的提示记为 `plugin/ui-control` 上下文，不计入业务材料。注册时固定已发布工作流，并分配唯一可接受的派发请求身份；派发仅携带该身份与修订，不接收模型改写的任务正文。Workbench MCP 子进程通过 `WEAVE_WORKBENCH_BOUND_DISPATCH=1` 隐藏原始 `team_dispatch`。

每次网络尝试之前都必须成功保存 Session。响应丢失时重试相同注册与请求。包括认证失效在内的 HTTP 错误不会释放结果未知的请求；只有注册前明确的团队或工作流拒绝才允许更换选择。如果未决请求重试前出现新用户输入，Weave 原子地返回已有运行或关闭尚未消费的修订，Host 不能重新把旧请求入队。关闭修订不会丢弃用户原始材料，后续派发会保留这些材料和后来补充的修改。明确重跑使用同一注册路径，用户操作中的完整修改正文逐字节保留。

分叉会话继承已消费输入的历史，但新的派发使用本会话的修订头和请求身份。继承的未决派发和重跑操作不会重新执行。应先在原会话核对结果，再从已核对历史分叉，或在空白会话提交独立任务；分叉不会静默吸收父会话后来追加的事件。

派发成功后，宿主会把 `client_request_id`、run、团队、工作流、进度、成员活动、实名运行时、精确绑定到该 run 的交付物与异常状态写进 Session 日志。受限轮询器以同一业务身份读取精确 run 活动和交付物合同并追加完整快照。因此关闭对话既不会停止 Weave 执行，也不会破坏 Workbench 的状态恢复。Weave 采集当前 CLI 答复明确产出的 UTF-8 文本文件，保存为不可变交付物，面板无需访问任意宿主路径即可预览和下载。已发布工作流的成员文件属于阶段产物，最终交付由交付节点决定。即使文件数量不变，活动观测也会校正缓存中的阶段标签。

Workbench 设置会在每个 Session 中始终提供已注册运行节点能力，同时不再给全局侧边栏增加独立的基础设施快捷入口。“运行节点”页面概括可用情况，并展示容量、引擎身份、认证方式、程序版本、最近连接时间和故障接管组。用户可以在这里添加、改名、分组或移除节点，无需进入独立管理应用。移除节点会立即撤销连接，并可能中断正在执行的工作；已保存的任务事实与交付物仍然保留。新建节点的运行令牌只出现在创建它的浏览器响应中，同时附带可直接复制的完整连接命令。Host 优先使用已配置的 `WEAVE_RUNTIME_SERVER_URL`；未配置时保留已经可路由的 API URL，或将回环地址和仅容器可见的主机名替换成优先内网 IPv4，同时保留 API 端口。整次任务控制使用专用的已认证产品路由，并直接追加 WorkTask 动作，因此纠偏与重新运行不会在对话里显示成内部命令记录。

Host 还为“已发布能力”设置分区注册 `/api/weave.capabilities`。该路由的封闭动作 schema 只允许应用、凭据、不可变版本、授权、启用状态和管理员停止操作。Host 使用 `WEAVE_API_KEY` 认证每个上游请求；浏览器只会接收一次新签发的应用凭据，永远不会收到该 Host key。

每个会话按配置间隔运行至多一个轮询请求；发布快照不会触发立即重读。业务变化立即追加。没有变化的观察最多每 30 秒追加一次，以更新浏览器的新鲜度期限；执行尝试的更新时间只在其保留字段发生变化时更新。对象字段顺序不构成业务变化。组合包将 `weave/work-task` 注册为由投影承载的历史；浏览器接受精确的 `workTask` 基线后，旧快照以连续序号范围传输。对话、工具与任务操作记录仍留在历史窗口，持久化日志保持完整。团队发现和精确团队详情回执提供显示名称。终态活动会保留成员失败原因；团队详情或交付物读取失败时继续重试，成功后才结束观察。较晚返回的读取保留最新待办、本地评价和明确回执；旧运行的响应不能写入新任务。只有对应操作的实际 HTTP 成功或拒绝才产生回执。每次明确重试持久化并重复使用同一个幂等键，即使响应丢失或阶段再次失败也不会自动产生第二次重试。人审答复保留并原样提交服务端 `interaction_id`，避免旧表单回答同一运行中的后续问题。

持久任务记录 Weave 提供的准确等待类型与节点。浏览器操作和命令仅在对应阶段处于可恢复等待时接受阶段重试。宿主优先从当前运行的活动响应读取人工决策，并在运行继续或结束时清空待处理计数。

Host 从 `/v1/human-tasks/:run_id` 读取确切的人审问题、等待身份和答复结构，先持久化用户答复，再使用稳定幂等键提交到现有完成接口；收到权威响应后才清除等待。浏览器操作的实际接收或拒绝结果折入持久化回执，重放时按身份去重。接收请求不表示工作完成。被放弃的执行与确认取消不同，仅在 Weave 根据对应取消状态迁移明确返回 `stop_unconfirmed` 时才说明停止未能确认。

鉴权后的 `/api/weave.deliverable` 会校验当前会话、运行与已知产物，再从 Weave `/v1/deliverables/:id/content` 流式返回完整保留正文。Host 业务密钥始终留在服务端。下载使用附件响应，SVG 图片预览带沙箱 CSP，HTML 在浏览器中仅作静态沙箱文档展示。投影截断不会变成截断的伪完整下载，也不会生成不存在的本地文件入口。

活动投影保留公开运行文字、传输完整度及当前实际执行任务身份。重复的 `(task_id, seq)` 不会产生重复记录。只有实际运行节点能力声明才标记执行中更新，旧节点与其他引擎仍按阶段完成后更新。这些公开消息不构成最终交付证据，也不暴露私有推理。

Weave 在同一事务中保存成员执行配置并重新发布受影响的工作流。草稿冲突或发布失败时，两者均不改变。已有任务保留冻结配置。CLI 原生模型名称通过所选节点执行，Host 仅返回可编辑字段和安全错误码。

执行、交付核验与用户评价分别记录。Host 投影 Weave 为当前不可变交付版本保存的检查摘要。最终文件或总结表示可以打开成果；文件数量和正文中的 `PASS` 都不能证明交付通过核验。未知要求与失败检查保持可见。试点报告分别提供执行完成率和各核验状态的数量。

评价动作携带页面显示的交付版本，保存用户决定前先向 Weave 核对。证据暂时读取失败时，最近的评价回执仍保留在 Session 日志中；只有再次观察到相同运行与版本时才恢复适用。不同版本从未评价开始。同一版本重新核验时保留评价，并通过 Weave 的有界核验接口读取已保存结果，不再派发成员。即使旧终态轮询仍在进行，Host 也会在重查响应后刷新。迟到的评价读取不能替换更新的核验报告。[交付核验决策](../../../.agents/notes/implemented/bug-fix/2026-09-08-workbench-delivery-verification.zh.md)说明这些身份与限制。

<a id="surface-boundary"></a>
## 界面边界

Workbench 客户端保留 DSH 的会话、可选项目工作区、提供方中立的模型设置、权限、人工确认、工具与交付物底座。它把前台 agent 固定为完整能力的标准预设，并隐藏 agent 预设选择器，因为提示词组合模式属于宿主配置，不该成为业务任务选项。它禁用继承而来的原生 DeepSeek 适配器和官方 DeepSeek 默认值，同时不展示 DSH 内测声明、DeepSeek 官方凭据首次引导、预览版标记、官方品牌占位、Subagent 呈现、消息反馈控件与轨迹检查界面。非 Workbench 构建中的 DSH 通用行为保持不变；Workbench 的模型设置页面仍是显式配置提供方的位置，但浏览器不会再用特定厂商的首次启动弹窗阻塞用户。

<a id="credential-boundary"></a>
## 凭据边界

`WEAVE_API_KEY` 只从受信任的宿主进程传给本地 MCP 子进程和已认证的 Weave 请求。它不会写入客户端产物，也不会加入模型上下文。运行节点列表只返回展示、健康、容量与调度事实；变更响应只会在新建节点时返回一次运行令牌。能力管理响应省略已保存的凭据哈希与调用输入；创建凭据时只返回一次新的应用凭据。`WEAVE_RUNTIME_SERVER_URL` 不含凭据，只在该一次性令牌响应中作为连接地址返回。`WEAVE_SECRET_KEY` 与 `WEAVE_SECRET_KEY_FILE` 只属于 Weave 服务端，用于加密存储凭据；本组合包永远不读取或转发这两个值。

<a id="model-experience"></a>
## 模型体验

### Workbench 团队路由 persona

#### 模型看到什么

Profile 把这条规则注册为独立的 Workbench 提示词段，并把前台 agent 固定为完整能力的标准预设，因此会话模式无法覆盖它。前台 agent 面对实质性业务工作时必须先使用 `mcp__weave__team_list` 等工具列出并匹配 Weave 团队，随后确认所选团队、任务范围与预期交付物，再调用 `weave_dispatch` 派发已发布工作流，参数不含任务正文。对话中已有明确确认就直接执行；内部构建与评测不会增加用户确认步骤。派发后最多调用一次状态接口确认交接，随即只返回所选团队与简短的人类可读状态。除非用户明确索要技术详情，否则不得包含内部标识、原始工作流版本、编排阶段或后端枚举。它不得创建 DSH 目标、在前台轮询 Weave 运行，或保存重复交付物。Workbench 负责后台状态投影；运行终态或用户稍后索取时，模型先核实当前运行是否存在最终交付物。只有阶段记录时，它说明最终成果尚待核实。存在最终交付物时，模型读取后给出简短的用户完成摘要：完成了什么、主要发现或决策、用户可打开哪些文件、是否还需要用户动作。内部 run ID、deliverable ID、runtime ID、宿主路径、哈希、校验命令名与引擎细节不进入主回答，除非用户明确索要技术详情。没有匹配团队时，它必须如实说明并协助定义团队。只有用户明确要求时才可使用自由协作；Weave 连接不可用时也必须诚实报告。

#### Token 影响

一段稳定的产品 persona、Host 拥有的派发 schema，以及连接成功后由 Weave MCP 服务发布的工具 schema。

#### KV Cache 影响

Workbench persona 与已连接的 Weave 工具集合不变时保持稳定。MCP 连接、断开或工具集合变化会改变请求前缀。

## 已知限制与待办事项

<a id="known-limitations-and-deferred-work"></a>

- **凭据发现因宿主而异**：仓库启动器支持 macOS 钥匙串；其他打包宿主目前通过进程环境提供 `WEAVE_API_KEY`。
- **暂时没有专用连接卡片**：启动日志会显示 MCP 进程不可用；Workbench 原生连接状态提示仍待补充。
- **输入归属仍使用会话窗口**：上次初次派发被接受以来的用户原始消息保留在一起。该机制防止正文被静默替换，但不能证明后续对话中哪些消息属于独立新任务。明确任务目标的类型化输入仍需另行完成。绑定派发目前只支持固定工作流；旧的原始 HTTP 调用不具备上述输入来源保证。
- **评价归属于当前 Host**：用户决定保存在该 Host 的 Session 日志中，不构成跨 Host 共享的验收记录。没有版本的历史交付仍可阅读，但不能提交绑定版本的评价或重查。核验只能解决已注册可信检查所支持的要求；专业复核与尚未支持的文件格式仍是明确缺口。
