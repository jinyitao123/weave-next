# Agent Note: 不持有传输的桌面服务选择

Status: implemented

[English](2026-09-08-desktop-connection-selection.md) | 中文

## Problem

桌面改址会与服务描述、登录和旧页面响应发生竞态。复用 Host 传输代数会把客户端偏好耦合到执行修复；把登录成功当成业务回执则赋予了客户端并不拥有的权威。

## Decision

[桌面源码库](../../../../apps/desktop/README.zh.md)维护非敏感服务选择、可取消候选和响应范围。可信适配器确认同一实例且独占偏好存储成功后，选择才提交；失败或取消保留原偏好。每次尝试都会使旧响应范围失效，包括返回相同 origin 的情况；响应范围不能跨创建对象使用。

本决策不替代 [Host ConnectionController 的职责](2026-07-19-gui-web-client-architecture.zh.md)。该控制器继续拥有 RPC 和传输重连代数；新增源码模块没有注册到产品 profile，也没有修改该控制器。它不含业务回执库、任务状态投影或服务器取消通路。

## Alternatives considered

修改现有 Connection 包会把桌面选择与当前执行相关修改混在一起；建立第二套完整客户端又会重复重连和 RPC 行为。采用注入适配器的源码库可以独立验证选择规则，无需增加传输层或包依赖。

## Consequences

定向测试覆盖偏好重载、中止与被替换的尝试、磁盘写入失败、实例不匹配、创建对象替换和真实回环连接断线。夹具不证明账号或业务验收通过。原子磁盘持久化、候选会话清理、服务器实例检查与生产接线仍由适配器承担，仅有源码库不能构成可安装桌面应用，[原生预览适配器](2026-09-08-native-workbench-preview.zh.md)负责这个独立边界。
