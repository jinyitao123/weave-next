# Agent Note：Workbench 管理已发布能力的调用权限

状态：已实现

[English](2026-09-12-weave-published-capability-management.md) | 中文

## 问题

Weave 可以把已发布工作流作为带版本的服务能力提供给业务应用，但运维人员需要在同一个业务界面中创建调用应用、轮换应用凭据、发布不可变能力版本、授予调用权限并停止某次调用。如果通过数据库操作或临时 HTTP 请求管理这些记录，就会绕开受支持的 Workbench 界面，凭据处理和运行状态也难以复核。

## 决策

Workbench 设置页提供“已发布能力”分区。管理员可以创建稳定的应用身份与能力，签发或撤销应用凭据，把下一个不可变能力版本绑定到已经通过准入的已发布工作流，启停新调用，并授予或撤销某个应用对确切版本的访问权限。页面列出最近调用，并分别展示执行状态、结果可用性和停止确认状态。

Workbench Host 负责浏览器路由 `/api/weave.capabilities`。该路由只接受封闭的管理动作集合，使用仅 Host 可见的 `WEAVE_API_KEY` 认证上游请求，并把上游失败转换为有界的浏览器错误码。应用凭据只向创建它的浏览器返回一次；已保存的凭据哈希、调用输入和 Host 凭据不会进入浏览器响应。

浏览器只读取管理投影并发送管理员明确触发的动作。它不推导执行事实、不改写已发布版本，也不调用模型。停用应用、能力或版本会拒绝后续提交，但历史调用仍可读取。管理员停止请求复用 Weave 的持久取消与 TeamRun 控制路径，并把该管理员记录为操作人。

## 考虑过的替代方案

**增加另一个管理应用。** 未采用，因为 Workbench 是受支持的业务界面，并且已经提供经过认证的设置界面。第二个控制台会拆散运维路径和凭据边界。

**把 Weave API key 暴露给浏览器。** 未采用，因为浏览器只需要有界的管理结果，不需要不受限的业务凭据。Host 可以授权确切操作，无需传出自身凭据。

**编辑已发布能力版本。** 未采用，因为服务调用方需要稳定的版本身份。合同、工作流、执行限制或结果策略发生变化时发布下一个版本，启用状态继续作为独立且可逆的控制项。

## 后果

运维人员可以在 Workbench 中完成能力调用权限的完整生命周期，也能在不改变应用身份的前提下轮换应用凭据。该页面是 Weave 持久记录的管理视图，不能证明某项业务能力会产出可接受结果。业务验收仍需要真实输入、一次服务调用、返回结果和独立复核。
