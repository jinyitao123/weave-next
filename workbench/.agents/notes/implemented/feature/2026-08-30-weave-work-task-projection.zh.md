# Agent Note: Weave 对话壳中的工作任务投影

Status: implemented

[English](2026-08-30-weave-work-task-projection.md) | 中文

## Problem

Workbench 把团队发现、派发、状态、人工任务、运行时和交付物调用记录为分散的对话行。用户必须检查工具名与不透明编号，才能判断哪个团队正在工作、工作流是否启动、在哪里受阻，以及可见交付物是否属于当前运行。只有用户选中某个工具调用后，详情列才有内容，因此页面隐藏了长时间 FDE 任务所需的运行状态。

## Decision

`ui-chat` 声明 `conversation.details.summary`，并在没有选中单个工具调用时渲染它。`ui-weave` 用工作任务投影占用该 slot，并在 Session 标题旁提供紧凑状态控件。检测到任务不会自行打开界面。用户点击状态控件后，布局执行显式的专注详情动作：全局侧栏保留，会话让出轨道，工作现场成为主内容区。选择普通工具调用时仍可使用常规详情几何，并由现有输入／输出检查器取代摘要。

团队总览用紧凑导航行呈现成员，不再把完整轨迹展开在列表内部。选择成员后，会进入该成员的独立工作视图，展示所分配的运行位置、工作流阶段、有界工具输入输出、观测到的输入和产物引用。该视图仍来自同一份 WorkTask 投影，不会创建第二个 Session，也不会虚构私有思维过程。Weave 报告当前运行可以接收纠偏时，成员视图会把已有纠偏请求定向到该成员；否则会明确说明当前阶段不可干预。

浏览器投影先折叠已加载的 Chat 节点。Workbench Host 再按精确 `run_id` 读取 Weave 活动快照，把权威状态、冻结成员和运行时、HumanTask、交付物引用、数据新鲜度与各部分完整度写回 Session。派发状态负责工作流生命周期和进度，终端运行状态只提供次级的运行时健康信号，因此 `terminal_missing` 不会覆盖权威的 `queued 0/9` 派发状态。只有交付物的 `run_id` 与活动运行一致时，它才计入当前任务。不透明编号保留在折叠诊断区。

一个 Session 保留按顺序排列的 run attempts 和至多一个 `pendingAction`。团队卡允许用户选择团队，但只会请求生成完整派发简报，不会直接产生远程副作用。Host 会在调用 Weave 前持久化整次运行的停止命令。Weave 将并行阶段判断为基础设施故障时，父任务继续保持托管等待。团队总览会把恢复入口放在整队重跑之前，标明受影响的成员和阶段，并明确说明其他成功阶段和产物继续保留；成员工作视图内也保留同一个操作。浏览器路由和免模型命令只有在阶段同时满足失败、基础设施故障和服务端明确可重试时才会登记恢复。专业工作失败和验收失败不会出现该重试操作。运行进入终态后，用户可以编辑完整简报并确认创建新 request 和新 run，旧 run 与交付物保持可见。Workbench 不提供成员级暂停。

DSH 全局侧边栏会在每个 Session 中提供 Weave 运行节点注册表入口，活动中的 WorkTask 仍然只显示本次实际使用的节点。入口用可用节点数、已注册节点数和健康提示概括状态。已认证的宿主路由只返回节点展示、健康、容量、引擎身份、认证方式、程序版本与调度事实，并接受受限的创建、配置与删除请求。业务 API key 留在宿主内，只有新建运行令牌会向发起创建的浏览器返回一次。任务控制使用专用宿主路由直接追加 WorkTask 动作，不会在对话里创建命令记录。较早的命令型操作记录会获得业务事件呈现，完整任务简报则保持折叠，直到用户主动查看。这个界面负责运行节点注册和调度，不负责启停机器上的本地执行进程。

共享布局对普通详情保留中央列最小宽度让步规则。如果该规则把用户明确打开的普通详情列压缩到零，详情面会改为右侧抽屉，不再直接消失。专注详情会有意绕过抽屉：把侧栏之后的空间分配给详情、隐藏中央轨道，并在恢复普通详情前移除详情缩放手柄。

Session 日志仍然是 Workbench 的本地事实源，Weave 是唯一执行权威。Host 在前台模型轮次结束后继续轮询，重启时会重放未解决的停止 key，或用相同 `client_request_id` 对账派发，因此关闭对话不会停止 Weave 运行。

初次派发正文来自 Host 冻结的用户原始消息。模型重抄的正文不能证明它包含当前发票、附件或约束，即使它与任务面板显示的内容一致。Host 拥有输入修订与派发请求身份，Weave 固定已发布工作流，并在入队事务内消费修订；面板读取由此产生的 Host 事件。明确重跑共用这条路径，从用户操作中保留完整修改正文。界面生成的指令使用现有 plugin 来源中的 `ui-control`，子会话转发也保留此来源，因为可参与对话不代表它是用户手写的业务材料。

每次请求或回放已接受结果之前，Host 都保存 Session，包括此前保存失败后的重试。未知结果使用相同注册与请求身份，包括认证或传输拒绝后的重试。只有明确的注册前选择错误才会释放未注册请求。出现新用户输入时，重试转为原子核对，Weave 在与入队相同的锁下返回已接收运行或关闭未消费修订；迟到派发不能重新打开已关闭修订。该操作不会取消已接收运行，也不能证明旧用户材料可以丢弃。

Host 按派发团队 ID 关联 `team_status` 中嵌套的 `team` 记录，也适用于从 YAML 创建的团队。即使较早持久化的任务快照漏掉名称，重放也会恢复已观测名称；缺失名称还可以通过已认证的精确团队读取补齐。轮询会独立发布当前成员失败原因，不受补充读取是否成功影响，并在读到成员活动和交付物后才结束终态观察。轮询自身的快照事件不能立即发起下一次轮询，当前操作仍负责配置间隔。这能防止持续变化的耗时字段把持久化发布变成无界请求循环。已记录事件的投影快照与 Host 测试覆盖团队名称恢复、失败保留、重试收口和轮询节奏。

## Alternatives considered

**用独立任务应用取代对话。** 否决，因为现有三列壳已提供导航、对话和可调整宽度的详情列；在宿主存在任务生命周期之前替换它，会丢掉已经可用的输入、历史、工具检查和交付物呈现。

**让模型在助手消息中总结任务状态。** 否决，因为模型文字可能遗漏、混淆或停留在过时的运行标识上。浏览器从已记录的工具事实提取任务状态，助手文字只负责解释。

**让模型同时提交任务正文与摘要。** 否决，因为两个相互匹配的模型控制值不能证明是哪条用户消息授权了工作。Host 拥有的来源引用和原始字节仍然必要。

**把状态查询未找到视为从未派发。** 否决，因为并发请求可能在读取后入队。核对操作在入队事务边界内原子关闭未消费修订，同时保留已接收运行。

**统计所有可见交付物。** 否决，因为 `deliverable_list` 可能返回其他运行的文件。面板宁可显示当前任务无交付物，也不展示未验证文件。

**在团队列表中展开完整成员轨迹。** 否决，因为长工具活动会把总览变成狭窄的调试折叠栏，让相邻成员难以比较，还会让右侧界面遮挡会话。紧凑导航保住总览，独立成员视图则给详细活动足够空间。

## Consequences

输入身份独立于所选 CLI 或 Loom 执行器。当前实现保留未消费用户消息的窗口，不推断后续消息是在创建独立任务还是补充旧工作，因此关闭未消费修订后仍保留其原始材料。明确任务目标、独立交付核验和自由协作输入绑定仍是单独的工作。旧的原始 HTTP 派发不属于这项输入来源保证。

Weave Session 可以展示团队、进度、运行时、异常类别、人工决策、数据完整度、运行历史和严格归属当前运行的交付物。打开工作现场成为用户主动的导航动作，不会再打断正在进行的对话；成员活动仍可查看和定向调整，也不会迫使整个总览挤在狭窄栏中。同一个界面可以管理已注册运行节点，同时不暴露 Weave 业务凭据，也不伪装能够控制本地进程。用户能在不调用模型的情况下停止整次 run、发起允许的成员纠偏、直接从团队总览恢复外部运行时断开的阶段，并从完整修订简报创建新 run；丢失的网络响应由持久动作恢复。精确阶段重试沿用原有冻结输入，保留已完成的同级阶段和已有产物，且不会用于专业工作失败或验收失败。成员工作视图是投影范围内的交互，不是独立持久的智能体对话。第一期仍以单团队、无不可逆外部写入的工作流为边界。
