# Agent Note：Workbench 任务优先入口

Status: implemented

[English](2026-09-04-workbench-task-first-entry.md) | 中文

## 问题

空白 Workbench 要求用户先选择文件系统工作区，才能发出第一条请求，即使这项请求只需要调用已有 Weave 团队。同一个输入区还把 DSH agent 预设展示成业务执行模式。这让两个宿主配置问题进入了首要任务路径，也带来正确性风险：完整型 minimal 预设会替换已组装的系统提示词，从而压掉 Workbench 强制执行的团队路由规则。

## 决策

Workbench 不再生成私有默认工作区。尚未选择项目时，输入区保持不可用，并明确提供项目选择器。被选中的目录是该项目团队任务和材料产出的可见边界；已注册的真实项目继续可用。

Workbench profile 禁用 agent 预设选择器，并把完整能力的标准预设保留为宿主负责的选择。它还禁用继承而来的原生 DeepSeek 适配器，并用一个不生效、提供方中立的回退值替换官方 DeepSeek 默认选择。模型页面中保存的选择拥有最终权威；全新部署必须主动配置一个模型。通用 DSH profile 的工作区、预设和原生提供方行为保持不变。真实 CLI profile 组合测试负责约束这些 Workbench 配置，客户端测试负责约束 Workbench 专属的项目选择与输入文案。

## 曾考虑的替代方案

**创建隐形的兜底工作区。** 不采用，因为它会隐藏团队产出应归属何处，还会让产品自建的临时目录意外变成正式项目。

**从 Workbench 移除工作区。** 不采用，因为项目文件、源资料、命令执行与会话归组仍需要明确的文件系统边界。工作区只是可选上下文，并非无用基础设施。

**保留预设选择器，只把标准模式设为默认。** 不采用，因为它仍把提示词组合方式表现成业务选择，而且选择完整型预设仍可能破坏 Workbench 路由契约。

**分叉或删除 DSH 预设系统。** 不采用，因为其他 DSH 产品确实需要它。由 profile 决定界面更小，也能保留上游行为。

**用另一个硬编码厂商替换 DeepSeek 默认值。** 不采用，因为这只会换个名字重复同一种厂商耦合，还会让私有部署路由进入产品合同。

## 后果

首次使用 Workbench 的用户需要先选择项目，再开始会话。宿主不创建隐藏目录，也不保留环境级兜底路径。Workbench 获得唯一且可预测的前台 agent 契约，也不再带有厂商默认模型；DSH 在其他场景下仍保持可配置。
