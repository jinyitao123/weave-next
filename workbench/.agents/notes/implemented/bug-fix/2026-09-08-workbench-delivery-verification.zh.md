# Agent Note: Workbench 交付核验与绑定版本的评价

Status: implemented

English | [中文](2026-09-08-workbench-delivery-verification.md)

## 问题

工作流结束时仍可能缺少文件、尚未完成复核，或产生非预期的外部变更。最终总结与复核员的 `PASS` 文字不能证明交付质量。只绑定运行的用户评价，也可能被展示为对替换后成果的认可。

## 决策

[Workbench Host](../../../../packages/bundle/workbench-app/README.zh.md)分别投影执行状态、Weave 已保存的交付检查，以及用户对具体交付版本的评价。Weave 拥有冻结要求、产物清单与不可变报告。Workbench 通过既有任务面板和命令呈现这些事实，agent loop（智能体循环）与执行预设保持不变。

评价请求携带页面显示的运行与版本。Host 在追加用户回执前，向 Weave 与本地最新任务核对两者。迟到的身份读取不能替换当前核验报告。回执将运行、版本、决定、说明和时间保留在既有 Session 日志中。证据暂时不可读时，只隐藏其对当前成果的适用状态，不删除回执。相同版本恢复原评价，不同版本从未评价开始。没有版本的历史记录仍可阅读，但不能提交绑定版本的评价。

重新核验调用 Weave 对已保存结果的有界观察，不派发成员或替换产物。只有 Weave 的当前选择校验成功时才更新当前报告，冲突观察保留为历史。Host 在重新核验后刷新，即使旧终态轮询仍在进行。交付读取不可用时继续允许重试。明确的未知报告或服务端不支持该能力的响应，可以结束观察，同时不声称存在正在运行的核验任务。

试点导出分别报告执行完成率、核验数量和用户评价，不将执行成功标为业务成功。

## 考虑过的替代方案

**根据结束状态、文件数量或复核文字推断质量。** 这些事实不能证明冻结要求已经检查，也不能证明不存在额外外部效果。

**只把用户评价绑定到运行。** 替换后的产物可能继承针对不同内容作出的决定。绑定 Weave 的产物版本，才能保留决定的实际对象。

**在前台 agent 中执行核验。** 这会重复团队执行，并允许模型断言替代已保存证据。Host 读取 Weave 报告并调用其既有观察接口。

**在本次改动中增加共享验收服务。** 当前使用方已有持久化 Session 日志。跨 Host 权威验收需要独立确定所有权和同步方式，本地回执不声称具备该能力。

## 影响

用户可以打开可用成果，同时看到失败或未知的检查。用户评价与这些检查保持独立。重新核验不能让尚未支持的专业复核或文件格式变为支持。Weave 注册的 verifier 属于受信应用代码，Host 不为其实现提供权限沙箱。

[Host 操作回归](../../../../packages/bundle/workbench-app/tests/human-task-action.spec.ts)覆盖迟到读取、暂时失败、版本替换与刷新竞争。[Loader 与 JSONL 回归](../../../../packages/bundle/workbench-app/tests/dispatch-input-loader.spec.ts)覆盖实际 Host 组合与持久化重放。[客户端检查](../../../../packages/client/ui-weave/tests/work-task-recovery.client.spec.tsx)保证三项状态及页面显示版本的参数可见。
