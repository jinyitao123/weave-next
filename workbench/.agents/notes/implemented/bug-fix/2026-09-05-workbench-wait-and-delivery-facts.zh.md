# Agent Note: Workbench 等待与交付事实

Status: implemented

[English](2026-09-05-workbench-wait-and-delivery-facts.md) | 中文

## 问题

Workbench 把所有暂停运行合并为一个等待标签，并在运行继续或停止后保留旧失败事件产生的重试按钮。执行完成可能与阶段文件并列显示，却没有明确说明最终交付缺失。团队路由提示词还会跳过选队界面要求的任务确认。

## 决策

现有 WorkTask 投影携带 Weave 的等待类型与准确等待节点。当前基础设施中断若带有 Weave 明确的恢复连接并等待停止确认原因，即使 retryable 为 false，仍显示具体等待说明。主对话、工作现场和成员记录指出受影响阶段，说明恢复运行节点连接并等待确认。只有现有投影随后返回重试资格时才显示入口，不从无关或历史失败文字推导当前等待。浏览器沿用现有任务状态，分别说明定时暂停、团队阶段、人工回答、纠偏确认与运行时中断。宿主与浏览器把阶段重试限制在当前可恢复等待，且要求命中对应运行时节点或并行分支。人工决策计数使用当前运行的响应，并在执行继续或结束后清空。被放弃的运行不等于确认停止；仅在 Weave 根据对应取消状态迁移明确返回 `stop_unconfirmed` 时才说明停止未能确认。

执行状态保持权威。运行已完成但没有最终交付物时，任务面板与标头明确说明交付尚待核实；阶段文件仍可阅读。最终交付以 Weave 的 `artifact_kind=final` 为准，包括被分组为交付结论的无文件名 deliver 节点产物。状态标签与完整性提示共用此定义；交付结论不表示缺少文件包。类型未知或标记为阶段的产物不会因标题、节点类型或缺少文件名而取得最终交付资格。前台提示词分别核实最终交付与执行完成。

已发布 profile 的 persona 与宿主路由段均要求用户在派发前确认所选团队、任务范围与预期交付物。对话中已有明确确认就足够。内部构建与评测不会增加用户确认步骤。

工作现场保留为一个现有页面，分为“进展”和“成果”页签。执行中优先展示成员与当前可操作项。失败任务默认进入成员进展，在现场和主对话回执中说明失败阶段，并提供可展开的原始原因。完成任务默认打开交付，已停止任务仅在有保留产物时默认打开交付。已派发任务缺少团队名称时，不表示仍在匹配团队。分隔线的像素值配有对应像素范围，避免辅助技术将较宽的分栏统一截成 100。文档原位阅读，Markdown 正常排版，SVG 以受限图片展示，HTML 仅作沙箱静态预览。鉴权下载路由流式返回后端保留的完整产物，不把截断预览冒充完整文件，也不从生成文字中建立应用访问地址。缺少最终成果时采用中性展示，优先核对已有工作，将重新运行保留为另一个明确操作。

主对话通过现有输入框附属插槽保留一张紧凑的当前运行回执、可用操作和成果直达入口，不挂载完整现场、成果列表、成员记录或重新运行面板。人审、纠偏表单与持久化操作历史由用户主动展开，结束任务保持紧凑，主对话仍可直接处理恢复。全幅、并排和返回对话入口依据真实布局焦点与窄列状态互斥展示。任务状态条保留可见团队与状态，阶段计数收进悬停提示。人审使用真实问题结构和确切完成接口，复杂答复结构留在讨论中处理，不猜测答复字段。纠偏展示请求、受影响和保留的阶段、确认，以及实际生效或放弃的结果。成员调整复用现有引用片段插入机制，保留原草稿及已有引用；用户发送时才序列化确切运行、成员、阶段和产物身份。普通问题不自动提交调整。跨会话项目导航在目标任务视图实际就位后才打开现场。

最多三名关注成员属于浏览器阅读偏好，不产生独立对话或执行控制。状态点仅在新近执行事实下轻微闪动，也包括已观测到成员运行的分工等待；正在执行的成员名称与最新公开记录的短暂高亮让实际工作更可见。停止确认等待、过期事实、停止中与终态不呈现这种运行反馈。减少动态效果偏好禁用两种动画，不通过定时器编造进度或占位文字，也不移动焦点或阅读位置。公开更新只包含真实公开文字和工具事件，运行节点实际能力决定执行中更新或阶段结束后更新。新记录到达不会打断历史阅读的滚动位置。传输完整度和截断状态明确展示，与最终成果无关。项目动态只读聚合工作区明确关联的会话，相同运行按观测时间去重，排除归档和未关联会话，并链接回原任务与成果。

外层界面默认采用记住宽度的并排布局，提供主动全幅和小屏视图切换，保留输入草稿与已挂载现场。键盘调整宽度和浏览器存储不可用时仍可操作。侧栏区分当前任务状态与历史对话，识别停止中和已停止，历史折叠时仍保留活动任务，只有具备最终产物才标记交付。Workbench 将技术用量折叠为按需明细，并用业务语言展示权限标签，权限执行机制保持不变。

每个会话串行执行后台轮询，并根据当前运行和待办身份约束写入。迟到的读取保留新增用户操作与本地评价，只有真实操作响应才产生接收或拒绝回执。重试在响应丢失后保留同一个持久幂等键；人审答复保留服务端稳定问题身份，后续问题替换旧表单时也不会答错对象。卸载会取消在途读取并停止调度。

CSV/TSV 使用现有解析器，明确限制预览 200 行、40 列并提供真实完整下载；SVG 图片提供受限缩放。成员与页签往返保留选择和最多 100 个阅读位置，翻阅历史时仍保留新内容的未读状态。项目链接选中确切产物。

## 考虑过的替代方案

**引入独立的恢复生命周期。** 未采用，因为 Weave 已经拥有运行状态、等待身份与阶段重试资格。第二套生命周期会让浏览器再协调一种状态。

**把所有保留的基础设施失败视为可重试。** 未采用，因为历史失败不能授权重试正在运行、正在停止或已经结束的任务。

## 影响

用户可以区分工作停下的原因与可执行的操作。服务端响应未标明可恢复等待时，界面不提供重试按钮。最终交付物缺失保持为明确的交付缺口，不会改变已记录的执行结果。已补充局部投影、组件和已发布 CLI 组合回归用例；这些用例不调用真实模型，也不能替代真实界面验收。

本轮回归覆盖确切运行投影、答复结构与回执、重复更新、键盘导航、引用插入、跨会话导航、受限正文展示和已发布 CLI 配置。此前三个实现批次经首次运行与定向复跑，闭合了 482 项不同的聚焦用例，另有已发布 profile 检查；离线锁定安装、类型检查、局部 lint 与 Workbench 构建均通过。后续真实界面反馈暴露输入框附属区过大，因此重新开放该处整改。最终视觉整合通过了 109 项界面与投影检查、32 项布局和 24 项对话外壳检查、已发布 profile 检查、类型检查、局部 lint，以及新的 Workbench 构建。其中恢复和组件检查共 31 项，包含新增的 8 项紧凑回执与原位操作回归。这些检查没有调用模型，不能代替重建版本的真实浏览器验收，后者仍由协调代理完成。
