# Agent Note: Workbench 任务状态与阅读连续性

Status: implemented

[English](2026-09-05-workbench-task-state-and-reading-continuity.md) | 中文

## Problem

团队创建失败时，对话可能仍在展示团队选择，而实际尚未发生派发。各处独立组织的状态文案模糊了等待用户、等待执行停止和团队正在工作的区别。成员长记录、变化的列表前缀以及重复状态动画会干扰用户当前的阅读。只给对话保留 360px 的布局也会挤压任务回执与操作入口。

## Decision

[Workbench Host](../../../../packages/bundle/workbench-app/src/index.ts) 负责持久化准备记录，并为任务消费方推导 `displayState`。准备记录保留创建调用、返回的构建标识、实际步骤与尝试次数，以及已知或未知的结果，直到派发替换该记录。后台刷新通过现有构建进度路由查询已记录的构建，传输错误不构成创建失败的证据。任务更新拒绝其他运行和较早的观测，不以无关或过期事实替换当前任务。

团队卡选择通过现有对话请求查看方案。路由指令区分包含派发的确认，以及用户明确要求先创建、再单独决定派发的情况。已展示的方案和答复保留在现有结构化提问或计划审阅记录中。本次改动不添加带版本的方案授权模型，也不在执行 API 上施加新权限检查。

[任务界面](../../../../packages/client/ui-weave/README.zh.md) 在对话回执中保留准备状态与当前操作，工作现场负责完整成员记录和交付物预览。长公开记录展示原文片段，并提供明确的展开入口。阅读偏好保留记录展开状态、跟看状态、未读状态，以及仍保留的记录身份与视口偏移。列表前部条目被移除时，仍保留的当前正文因此保持原阅读位置。任务完成会保留已选中的进展页，回到最新记录仍由用户主动操作。

任务面板在呈现列表、详情、关注入口、恢复责任人、纠偏对象和调整引用之前，统一计算成员展示名。已记录的可读名称照常显示；空名称、UUID 和内部标识使用本地化的角色或名册位置名称，重复名称追加位置序号。这样可以辨认尚无可读姓名的成员，同时不编造身份。动作引用与折叠识别信息继续保留精确的成员标识。

[布局拥有者](../../../../packages/client/ui-layout/README.zh.md) 要求内容区域至少有 900px 才分栏，对话至少保留 420px、现场至少保留 480px，均未扣除留白。窄布局只显示一个主视图。每个任务区域只让主要执行状态轻微闪动，成员状态点与团队候选卡保持静止。新鲜度到期时无需等待下一次投影更新即可停止执行动效，减少动态效果偏好会移除动画和过渡效果。

成员身份与操作通过紧凑页头和次级控件呈现，长职责按需展开，记录内标题低于成员标题。中断对话回执保留下一步恢复说明，不重复整列成员名称。仅作用于 Workbench 的外壳样式对齐现场留白，并让导航选中状态区别于悬停。

现场以固定的总览、进展和成果页签组织内容。已完成且有最终交付的任务首次打开总览，集中列出最多三项最终输出、团队与已记录的输入引用；缺少最终交付时打开成果页。全部输出包含阶段文件并支持文件名查找，精确成果链接会清空搜索条件。总览中的成员入口明确返回成员列表起点。已处理的调整记录保留在默认折叠的入口中。成员记录使用现场主滚动区；现场按运行、页签和成员分别保留位置，也覆盖来自对话回执的导航。隐藏的阅读区不跟随新记录，也不恢复旧锚点。成果直达按运行、文件和请求编号只消费一次，返回页签不会重复抢焦点。文件预览首次展开后持续挂载，收起和切换页签保留原状态。只有一个阶段文件时直接展开文件。已知的两字段人审结论优先显示决定和批注，并提供原始 JSON 查看入口。

Workbench 将任务回执放在固定输入框上方的文档流中，展开回执只增加自身占位，不再扩大覆盖旧消息的浮层。操作历史在工作现场查看，历史人工输入标为“此前提交的回答”。紧凑顶部入口组合工作现场名称、当前状态与进入箭头，团队明细保留在悬停提示中。Workbench 移除会话记录下载按钮，保留底层导出服务和命令反馈。

## Alternatives considered

**根据没有派发推断创建结果。** 创建仍在提交或核验时，本来就不存在运行。保留实际创建记录，可以在不虚构派发的前提下区分失败和传输结果未知。

**把团队卡选择视为派发确认。** 选择团队不能确定任务范围，也不能确定用户是否授权立即执行。现有对话审阅可以保留这一区别，无需引入另一套产品流程。

**保留固定滚动偏移，并让每个执行中成员都显示动画。** 删除列表前缀会改变固定偏移处的正文，多处循环也会干扰主要状态。保留记录锚点和单一主要信号可以维持阅读连续性与清晰的状态层级。

模型选择器使用友好的不可用说明，保留可操作的选单，并复用目录刷新在配置变化后重新核验。空选单给出既有“设置 → 模型”路径，本次不新增设置导航服务。等待用户决定时隐藏对话运行提示，收起的思考行不预览过程正文。

## Consequences

这些改动改善既有创建、执行和阅读事实的呈现，不增加产品功能或业务权限，也不修复团队构建失败或运行中断的后端根因。方案修订与持久授权执行约束仍不在本次实现范围。浏览器锚点无法恢复服务端已经移除的记录，截断提示继续保留。最小宽度保护分栏几何关系，但不能证明扣除留白后所有译文和文档都能正确排版。

## Verification

针对性的组件与投影测试覆盖创建失败和结果未知、共用展示状态、过期观测、方案选择文案、完成时不强制切页、长记录展开、列表截断后的保留记录锚点，以及可读成员名与不变的动作对象。分栏测试覆盖切换阈值与最小宽度。追加的任务现场回归覆盖稳定页签焦点、成果直达只消费一次、预览按需首次挂载并保留缩放，以及内容延后载入时不持久化被浏览器截短的位置。Workbench 构建可编译修订后的 CSS。

本地 Workbench 截图核验历史失败、中断、成果入口、长记录展开与返回，以及部分响应式尺寸。独立浏览器将刷新失败定位为现场列展开时的浏览器自动滚动锚定；任务现场正文区关闭该行为，由现场负责恢复位置。生产预览组件的隔离样本覆盖 CSV、TSV、SVG 在 1440 和 390 宽下的横向滚动与缩放保留；这些样本不验证鉴权下载。上述证据不能证明新运行成功、真实故障恢复或完整视觉品质验收。浏览器辅助函数现按实际载入的界面配置选择准确的项目入口和文案。Workbench 回放通过持久会话主路径与完整取消路径，包括排队草稿删除和停止后恢复。专用 Workbench 黄金文件保留了通用配置的原有预期。1440 和 390 宽的独立真实页面检查确认任务回执能滚出视口，输入框保持固定，操作历史仍可在现场查看。其余回放场景和通用配置未重新验收。
