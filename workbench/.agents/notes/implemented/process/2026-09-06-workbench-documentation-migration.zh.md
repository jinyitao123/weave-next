# Agent Note: Workbench 文档检查以保留的工作区为准

Status: implemented

[English](2026-09-06-workbench-documentation-migration.md) | 中文

## 问题

文档检查依赖包归属、可执行的构建目标，以及工作区在 Git 中的位置。指向已删除归属方的引用，以及工作区就是 Git 根目录的假设，使保留的文档无法完成验证。

## 决策

[检查注册表](../../../../scripts/run-gates.ts) 验证保留的 Workbench 工程文档。已退役的公共网站不再对应构建或投影测试项。服务映射、类型等价注册、库分类和 README 例外均指向现存归属方，各自的完整性与新鲜度检查继续生效。生成目录使用保留的源码声明，经评审的中文对应文档遵循同一份包清单。

[归档检查器](../../../../scripts/verify-archived-agent-notes.ts) 通过 Git 的 `ref:./path` 语法，相对工作区定位已提交的清单。基线比较继续拒绝删除或替换封存哈希，不依赖当前归档文件的哈希是否一致。归档内容保持冻结。

## 考虑过的替代方案

**恢复公共网站或已移除包**会仅为满足过期注册项，重新引入 Workbench 产品范围外的入口。检查项应随保留的归属方更新。

**忽略缺失文件或禁用文档检查**会掩盖后续失效链接、缺少文档的服务和被更改的归档封存记录。本次仅删除过期注册项，其余检查保留原有失败条件。

## 影响

文档流水线无需依赖已退役的产品资产，即可验证当前工作区。包归属变化仍需显式更新注册表和双语文档。归档回归测试在嵌套的 Git 工作区执行真实检查器，接受已封存基线，并拒绝移除其中已提交的封存记录。
