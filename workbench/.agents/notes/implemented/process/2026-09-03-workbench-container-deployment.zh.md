# Agent Note: Workbench 容器部署

Status: implemented

[English](2026-09-03-workbench-container-deployment.md) | 中文

迁移说明：本文保留原运行底座的决策依据；标注为历史路径的组件未包含在当前 Weave Workbench 工作区中。

## Problem

Workbench profile 可以从开发仓库运行，但远程安装缺少可重复构建的镜像、持久化 Harness 主目录、私有 Weave 连接和明确的公网 authority 配置。直接把本地进程复制到服务器，既可能遗漏 Weave 可执行文件，也可能让凭据落入临时 shell 状态。

## Decision

`Dockerfile.workbench` 使用仓库固定的 Node 与 pnpm 版本构建 Workbench 客户端 profile 及原生 Landlock 启动器，从指定 Weave 镜像复制受信任的 Weave 可执行文件，并启动受支持的 `dsh --profile workbench` 入口。原生启动器在镜像构建阶段生成，让 Linux 容器无需特权能力也能执行“工作区可写”策略。`deploy/workbench.compose.yml` 持久化 Harness 主目录和工作区，加入现有 Weave Docker 网络，只把业务 API Key 交给 Workbench Host，并要求部署者声明 DSH 身份验证接受的浏览器 authority。DSH 继续只监听容器内部的回环地址。一个共享网络命名空间的 Nginx 网关发布独立内部端口，同时保留 DSH 的启动 token 身份验证、WebSocket 连接、流式响应和公网 Host 请求头。除非运维人员主动选择其他地址，对外端口只绑定宿主机回环地址。

DSH 启动 token 交换仍是浏览器身份验证机制。带身份验证的地址由运维人员保管，未通过身份验证的请求无法取得应用内容。Weave 服务端加密密钥不会进入 Workbench 容器。

[Docker 构建上下文排除规则](../../../../.dockerignore) 排除所有目录层级的 `.env*` 文件。镜像会将构建工作区复制到运行阶段，因此本地环境文件必须在 Docker 接收上下文前排除；部署凭据仅通过运行时配置传入。

[镜像构建](../../../../../Dockerfile.workbench) 将 APT 下载包与索引、npm 工具下载和 pnpm 存储保留在 BuildKit 缓存中。中断后的下载可以续用缓存，软件包缓存不会进入运行镜像；构建仍要求锁定依赖和编译源码。

## Alternatives considered

**直接用 systemd 运行仓库。** 这种方式会让部署依赖服务器上的 Node 版本、包管理器安装、原生依赖工具链和可变仓库。

**不使用 DSH 身份验证直接暴露 Workbench 端口。** 网络可达不代表用户已获授权，而 Workbench Host 能启动模型和工具执行，所以不能接受公开的免登录监听端口。

**让 DSH 自身监听所有网络接口。** DSH 因 Host 可以执行代码而主动拒绝这种配置。让 Host 留在容器回环地址上可以保留该安全不变量，再由网关提供明确的部署边界。

**把完整 Weave 环境文件传入 Workbench。** 这种方式会把服务端专用的加密与管理密钥泄漏给一个只需要业务 API Key 和模型提供方凭据的进程。

## Consequences

该镜像比静态前端更大，因为它包含 DSH Host 运行时、构建后的包依赖图、工作区沙箱和 Weave MCP 可执行文件。低内存服务器应当在别处构建镜像，或在构建期间临时扩充交换空间；运行中的 Workbench 不需要构建工具链的峰值内存。网关会增加一个很小的容器，但不会引入第二套身份系统。构建 Landlock 启动器会增加一个仅适用于 Linux 的原生构建步骤，并要求内核真正支持 Landlock；否则启动器探测会安全失败。相应地，部署后的浏览器与本地开发使用同一个 Workbench profile，挂载状态能跨容器替换保留，默认的“工作区可写”策略无需特权容器能力，也无需退化为无约束执行，Weave 凭据始终停留在 Host 侧。运维人员必须保管生成的身份验证地址或已有的浏览器签名 Cookie，并在启动前设置精确的公网 authority。

## 云端业务闭环验证

部署后的 Workbench 通过浏览器发起了一次供应商风险复盘，由四人团队 `Rrb L3 Supplier Risk Team 001` 执行。Workbench 容器替换期间，Weave 运行仍持续推进；重新选择 `workspace` 工作区后，持久化 DSH 会话可恢复，任务最终完成全部四个阶段，并呈现九份已绑定产物。独立评审员核对十条来源记录、八个有效 finding 与两组重评链后，给出通过结论。

本轮验证暴露并处理了四类部署与产品问题。首个镜像没有可执行的工作区沙箱，现改为在镜像内构建并探测 Landlock，不再请求特权容器能力。DSH 的回环监听安全规则阻止直接发布，现由共享网络命名空间的网关在保留该规则与启动 token 交换的前提下提供访问。就绪信息与原始路由提示可能泄漏后端英文、标识符和原始生命周期枚举，现已将就绪事实本地化，并要求 Workbench 只使用面向用户的状态。最后，工作流终局的交付说明原先被归入普通阶段产物，导致已完成任务仍显示没有最终结果。Workbench 现明确区分最终文件、交付说明和过程产物；交付说明可作为完成结果查看，同时诚实提示运行时本地文件包尚未同步到云端。

大体量历史会话的恢复渲染仍可能明显慢于新会话，远端运行时生成的本地文件路径也还不是浏览器可移植下载。这两项作为明确的后续边界记录，不以削弱沙箱或把交付说明冒充已同步文件的方式掩盖。
